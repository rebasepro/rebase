# Rebase — Full Audit (OSS core + Cloud)

**Date:** 2026-07-23 · **Method:** 7 parallel deep-dives reading real source (not docs/marketing), every headline finding re-verified against code with file:line. Confirmed = traced in source; Suspected = strong inference needing a live check.

Detailed per-dimension reports live alongside this file in the session scratchpad (`audit/01…07-*.md`). This is the consolidated, prioritized synthesis.

---

## 1. The one-paragraph verdict

Rebase is a **genuinely strong, well-engineered Supabase-class Postgres BaaS** — the things that are hard to fake are real and good: RLS-as-authorization with a fail-closed reader-role model, a real WebSocket + CDC realtime engine with a genuine cross-instance pub/sub, pgvector, TUS resumable uploads, Barman PITR, a full Studio, first-party offline sync, and an MCP/agent story that beats every competitor here. The code is disciplined for its size (217k LOC, typecheck green, ~127 TODOs total, no committed dist, lockstep versions). **The gap between "impressive demo" and "credible Firebase/Supabase/Strapi/Payload alternative" is not code quality — it is three specific things:** (1) it does not yet **scale** (two structural CRITICALs — unbounded list reads and an O(subscribers) realtime refetch storm — bite at low-hundreds of users / ~10 tenants per instance); (2) the **CMS positioning is oversold** — it's missing the three features that *define* that category (drafts/versioning, localization, block rich-text) plus "full-text search" is actually `ILIKE`; and (3) the **safety nets don't run** — the excellent RLS/tenant-isolation tests are wired into no CI pipeline, and the documented first-run doesn't produce a working app. Layered on top are a handful of sharp, concrete bugs that deserve immediate attention regardless of strategy: **`rebase db push` silently drops columns** (and can drop *all* tables on a transient introspection error), **backups omit roles so RLS is silently lost on restore**, the **MCP server runs every tool as unconditional admin while the README says to point it at production**, and the **offline sync loses/duplicates writes**. None of this is a rewrite — the foundations are sound and every item here is closeable.

## 3. Priority queue — what to fix, in order

### 🔴 P0 — Do these first (correctness / scale / safety-net)

1. **Cap list reads.** `query-parser.ts:43` sets no default page size and there is **no max cap** anywhere on the data path — a plain `GET /posts` returns the entire table buffered into memory + JSON (and `?page=2` defaults the limit only for the offset math, never the returned rows). Inject a default (e.g. 50) and clamp to a hard max (e.g. 1000). *One-file fix, prevents a trivial OOM/DoS.* → perf #2
2. **Wire the RLS/security e2e suite into CI.** `test:e2e` (the `rls-enforcement.test.ts` that proves tenant isolation end-to-end against a real Postgres) runs in **no** workflow. CI's `e2e` job already stands up Postgres — add `pnpm --filter @rebasepro/server-postgres --filter @rebasepro/cli test:e2e`. *Literally one line; today a change that breaks RLS ships green.* → testing #1
3. **Fix the realtime refetch storm.** `realtimeService.ts:551` matches subscriptions by path only, so every write triggers a full-collection refetch **per subscriber**, each its own RLS transaction (`min(writes/s,3.3) × subscribers` queries/s per instance). Add server-side filter matching (skip refetch when the changed row can't affect a subscription) and/or diff-based patches. *This is the ceiling on the "realtime" selling point — bites at low-hundreds of concurrent subscribers.* → perf #1
4. **Ship a safe storage default — this is the one thing exploitable in default config.** Storage authorization is a single opt-in hook (`if (!authorize) return`, `storage/routes.ts:189`); with no hook, the posture is "any authenticated user, any operation, whole bucket." The red-team pass confirmed the concrete attack: `GET /storage/list?prefix=` enumerates every key → read/delete/overwrite any other user's files → mint anonymous 5-minute download URLs for arbitrary keys. Storage is not under RLS and keys share one flat namespace. Fix: refuse to boot storage in prod without an `authorize` hook or an explicit `publicRead` opt-out; consider default per-user key namespacing. **Also verify (NEEDS-LIVE-TEST):** the read/delete handlers may not re-run `sanitizeStorageKey`, so `..%2f` local-disk traversal is worth a live check. → security-core #2, adversarial FACT 3
5. **Reserve the cloud ingress IP.** `34.62.144.171` on the ingress-nginx Service is **ephemeral**; one Service recreation dark-outs every tenant subdomain and every custom domain irreversibly. The `gcloud compute addresses create …` fix is already written in `DISASTER-RECOVERY.md` but apparently not run. *Minutes of work; removes an irreversible outage.* → cloud #H1
6. **Fix the documented first-run.** The template README's Docker path tells users to `cp .env.example .env` (clobbering the generated secrets/port) and never runs `db push`, so the default CMS scaffold opens an admin panel where every example collection 500s ("SCHEMA DRIFT" is only logged, `PostgresBootstrapper.ts:485`). The Quickstart doc omits `db push` and starting a DB entirely. *The first thing every new user reads does not work.* → dx C1/C2
7. **Make `db push` fail-closed and non-destructive-by-default.** `atlas schema apply --auto-approve` (`cli.ts:174`) silently drops columns on a field rename/removal with no diff or confirmation, and the `--exclude` safety-list that protects non-collection tables **fails open** on any introspection error (`cli-helpers.ts:146-177`) → a transient DB hiccup drops *every* table not in `schema.sql`. Fix: fail *closed* on introspection error, gate destructive DDL behind a shown diff + `--allow-destructive`, and make backups role-complete (`pg_dumpall --globals-only`) with `--exit-on-error` restore so RLS survives a restore. *This is the highest silent-data-loss risk in the product.* → migration #1/#2/#3

### 🟠 P1 — Credibility & scale (weeks)

8. **Verify tenant isolation is actually applied in prod (not just in the repo manifest).** `control-plane-rbac.yaml` grants the `networkpolicies` verb whose earlier absence made `provisionNetworkPolicy` **fail open with a log line** (`orchestrator.ts:2278`). Run `kubectl get netpol -A` + confirm the ClusterRole binding; add a boot/CI assertion that every tenant namespace has its isolation NetworkPolicy. Also add a default-deny ingress NetworkPolicy on the `rebase-saas` control-plane namespace (tenant pods can currently reach the control-plane API directly). → cloud #H4/#M1
9. **Harden the MCP / AI surface.** Every MCP tool runs as unconditional admin with no confirmation gating, and the README markets pointing it at production — a prompt-injected agent can `db_push` (drop tables), `create_user roles:["admin"]`, or `reset_password`. Add a per-tool allowlist + confirmation for destructive tools (or a read-only default), fix the dev-host **shell-injection RCE** in `runRebaseCmd` (unquoted agent-supplied branch args, `mcp/index.ts:844`), and **rotate + relocate the hardcoded shared LLM key** shipped in the browser bundle (`plugin-ai/.../useDataEnhancementPlugin.tsx:7`, quick win). → mcp-ai #1/#3/#4
10. **Per-tenant pool exhaustion.** `DatabasePoolManager` creates one never-evicted `max:10` pool per tenant DB; against stock Postgres (`max_connections=100`) a single instance dies at **~10 active tenants**. Needs PgBouncer/Supavisor-style pooling or a global connection budget before the cloud scales past a handful of live tenants. → perf #3
11. **Real full-text search.** "Full-text search" in the docs is `ILIKE '%term%'` (`drizzle-conditions.ts:761`) — no tsvector/ranking/language. Cheapest high-value win (it's your own Postgres) and it closes the biggest Supabase parity gap *and* a docs-vs-reality credibility issue. → competitive #3
12. **Drop the CMS overclaim until the CMS features exist** — or build them. Right now the site sells Strapi/Payload parity but there are **no drafts/versioning/publish workflow, no content localization, and no block rich-text** (only markdown + read-only audit history). Either build the top one (drafts+versioning is table stakes for *any* CMS claim) or soften the positioning to "developer BaaS with an admin panel." → competitive #1/#2/#4
13. **Fix the offline-sync data-loss bugs before headlining "local-first"** — add a client-generated idempotency key per mutation (server dedups), record a base version for conflict detection, and fix the coalesce-then-drop lost-write (`client/src/offline.ts`). → offline #F1/#F2/#F4
14. **De-risk the single-secret and single-laptop failure modes.** `JWT_SECRET` signs sessions *and* derives every tenant DB password *and* domain-verification tokens with no rotation tooling (split off `DOMAIN_VERIFICATION_SECRET` now; stop deriving tenant DB passwords from it long-term). Move Terraform state to a GCS backend and bring the orphaned prod TLS cert under IaC. → cloud #M2/#H2/#H3
15. **Add a data/HTTP caching relief valve** (ETag/Cache-Control on reads, or request coalescing) and fold the mandatory `COUNT(*)` into the fetch transaction / make it opt-out — every list is currently ~10 sequential round-trips with no cache. → perf #4/#5/#6

### 🟡 P2 — Hardening & polish

- **Deny-all RLS on the internal auth/rebase tables (defense-in-depth).** `ensureAppRole` (`PostgresBootstrapper.ts:286`) grants `rebase_user` full DML on `auth.refresh_tokens`/`mfa_factors`/`recovery_codes`/`rebase.api_keys`, which have no RLS. The red-team pass confirmed **no shipped client path reaches these today** (baas introspects `public` only and excludes non-RLS/`rebase_*` tables; filters resolve against drizzle objects, never interpolated) — so this is *latent*, not live. But it's the one place the "no RLS ⇒ not reachable by the user role" invariant is false. Fix: `ENABLE ROW LEVEL SECURITY` with no policy (owner still bypasses) or `REVOKE ALL … FROM rebase_user` on those schemas — so a future feature that names them can't turn it into session-forgery/MFA-tamper. → security-core #1, adversarial FACT 1
- Reject/normalize commas in role identifiers at the `set_config` chokepoint — `app.user_roles` is a comma-joined string split on `,`; roles come from the DB today (blocked), but it's a latent escalation footgun for custom auth adapters. → security-core #5, adversarial FACT 2
- Ship CORS from the framework and enable CSRF by default under cookie-auth (currently warn-only). → security-core #3
- Equalize login timing (dummy scrypt on missing user) + stop logging the submitted email on failed login. → security-core #4
- Finish the half-migrated backend data layer (canonical-rows `DataDriver` vs legacy Entity `DataRepository`) and either wire DataSource routing on the backend or mark it clearly unfinished — today it reads as done but `server-postgres/src` has zero usages. → arch #1/#2
- Convert the 10 value `import React` in `packages/types` to `import type` + lint-forbid — BaaS stays React-free only by TS elision today. → arch #3
- Add an **AI/Agents docs section** (the strongest differentiator is entirely undocumented), a **Firebase/Supabase migration guide**, and warn on the silent bare-string `where` footgun (docs currently teach the risky format). → dx #H3/#H4/#M2
- Enforce lint in CI, make `release.sh` fail on red tests (or delete it for `publish.yml`), flip `verify:docs` to `--strict`, and stand up private CI for the gitignored `saas/` suite. → testing #5/#6/#7
- Cloud DR: drill the control-plane restore (1-day RPO, never tested) and a real tenant PITR; fix `backupsConfigured` reporting healthy while nothing archives. → cloud #M3/#M4/#M5
- Arm the managed-storage ~100-tenant GCP capacity alert (log line exists; nothing watches it). → cloud #M7

## 4. What is genuinely excellent — do not regress

- **RLS chokepoint & query builder** — fail-closed scoping (raw driver never enters context), filters resolve to Drizzle column objects (no string interpolation, no SQLi found), JWT pins `HS256` (no alg confusion), empty-uid coerced to sentinel at one chokepoint. This is the core thesis and it holds.
- **Realtime foundation** — real cross-instance pub/sub via CDC + pg_notify (multi-instance actually works), 8KB-overflow→identity-only fallback so a wide row can't abort a write, dirty-release pool guard preventing RLS-GUC leaks. The engine is well-built; only the fan-out algorithm needs work.
- **Cloud app-layer security** — no cross-tenant path found, per-tenant DB/storage/pod/network isolation, AES-256-GCM secrets with a mandatory key + correct domain separation from `JWT_SECRET`, Stripe signature-verified + idempotent, the two historically-cosmetic bugs (custom-domain verification, org self-join) are now real fixes.
- **Auth breadth** — 12 OAuth providers, magic link, real RFC-6238 TOTP MFA, account linking, scoped API keys double-gated by permission-list + RLS. The README *undersells* this.
- **Engineering discipline** — headless-guard is a real CI invariant, typecheck green and source-resolved, `rls-enforcement.test.ts` is a model integration test, publish pipeline is production-grade (OIDC trusted publishers, no standing token, workspace-protocol tarball guard, correct canary sort).
- **Offline sync & MCP** — both are first-party and ahead of all four competitors.

## 5. To be a credible alternative to each — the shortlist

- **vs Supabase (closest, ~80%):** real FTS, isolated functions runtime (stop calling in-process Hono "edge"), more SDK languages, connection pooling. Then you're at parity + ahead on admin/MCP/offline.
- **vs Firebase (web-credible, not mobile):** native mobile SDKs (Swift/Kotlin/Dart), push/FCM, phone auth. Until then it competes only for web/Postgres teams.
- **vs Strapi & Payload (the overclaim):** drafts/versioning/publish, content localization, block rich-text, live preview. These three-to-four features are the entire difference between "BaaS with an admin panel" and "CMS." Payload currently beats Rebase on every pure-CMS axis.

**Bottom line:** close the two scale CRITICALs + wire up CI (a week of focused work) and Rebase is a *legitimately shippable* Supabase alternative. Add FTS + drafts/versioning + localization (a quarter) and the "alternative to all four" claim becomes true instead of aspirational.

## 7. Second sweep — offline integrity, accessibility, i18n, red-team

Three additional deep-dives on areas the first pass didn't cover. Full reports: `audit/08–10-*.md`.

### 7a. Offline / local-first sync has data-integrity bugs (2 HIGH, 4 MEDIUM)
Offline sync is a *marketed differentiator* and ahead of all four competitors in scope — but it has real data-loss/duplication bugs, the worst class. All in `packages/client/src/offline.ts` (the replay engine is `OfflineManager`; there is no `offline-sync-engine.ts` despite the README's framing):
- **HIGH — no idempotency key.** A create whose server commit succeeds but whose ACK is lost is re-POSTed on next sync → duplicate row (serial id), or a 409 that `rejectMutation` treats as failure and then **deletes the local row that actually exists on the server** (`offline.ts:1377-1396`).
- **HIGH — lost write during flush.** An update issued while a same-row op is in-flight is coalesced into it (same mutationId), then dropped from memory + IndexedDB after the in-flight op succeeds — the second edit is silently never sent (`offline.ts:1208-1221`, `1519-1525`).
- **MEDIUM ×4:** delete resurrection (ACK-lost delete retried against a 404 → row restored), blind last-write-wins (bare PUT, no version/If-Match → concurrent server edits clobbered with no conflict signal), cross-tab duplicate replay when `navigator.locks` is unavailable (every write sent twice), and realtime subscriptions silently dying after 5 reconnect attempts with no error/re-arm.
- **Good:** reconnect *reconciliation* is correct (full-snapshot `mergeRows`), and local query semantics are otherwise faithful to Postgres (null/coercion/ordering). The gap is write-path integrity, not read semantics.
- **Action:** add a client-generated idempotency key per mutation (server dedups on it), record a base version for conflict detection, fix the coalesce-then-drop lost-write, and fall back to a real cross-tab lock. Don't headline "local-first" until these land — data loss erodes trust faster than a missing feature.

### 7b. "Premium" yes, "accessible" no; admin chrome IS translated
Judged against the "premium UI, fast, accessible" claim:
- **Premium: largely true.** `@rebasepro/ui` is a real standalone design system (peers only react/react-dom, zero admin coupling, 18 Radix primitives + Tailwind v4 tokens, thorough dark mode).
- **i18n — better than expected, and a needed correction to §3:** the admin *content surfaces* ARE internationalized (react-i18next, **7 locales, ~860 typed keys**, override-able) — competitive with Payload/Strapi. This is admin-*chrome* i18n; it is distinct from **content localization** (per-locale field *values*), which is still absent (§3). Both statements are true. Studio, however, is English-only (6/25 files touch i18n) and `packages/ui` itself is 0/93 localized.
- **Accessible: no — contradicts the marketing.** The flagship `VirtualTable` is `div`-soup: one `aria-*` in the whole component, no `role="grid/row/gridcell"`, zero `onKeyDown` (no keyboard nav), rows are clickable divs with no role/tabIndex — keyboard and screen-reader users cannot select or open a row (`ui/.../VirtualTable/VirtualTableRow.tsx:19-38`). **157 of 158 `IconButton` usages have no `aria-label`** (prop is optional, unenforced). **Zero live regions** — toasts and form-validation errors are never announced. And there is **no axe/jest-axe/`jsx-a11y` lint anywhere**, so none of it is guarded against regression. Contrast of white-on-#0070F4 is ~4.5:1 (right at the AA line).
- **Action:** either soften "accessible" or (better) make the VirtualTable a real ARIA grid with keyboard nav, enforce `aria-label` on `IconButton`, add an `aria-live` region for toasts/errors, and add `jsx-a11y` + a jest-axe smoke test. This is a bounded, well-understood body of work.

### 7c. Red-team verdict — core auth is solid; storage is the one live hole
The adversarial pass tried to weaponize every survey finding. **BLOCKED:** the auth-tables DML gap (baas introspects `public` only), roles comma-smuggle (roles from DB, admin-gated writes), anonymous-IS-NOT-NULL (blocked in OSS core + boot linter), JWT alg/purpose/download-token confusion (pinned + claim-checked), first-user-admin race, refresh-token rotation replay. **EXPLOITABLE in default config:** storage (see P0 #4). **NEEDS-LIVE-TEST:** storage `..%2f` local-disk traversal. Net: the security core is genuinely strong; harden storage and the internal-table grant and it's excellent.

## 8. Third sweep — data-loss, email/observability, AI surface

Three more deep-dives on the last uncovered corners. Full reports: `audit/11–13-*.md`. **This sweep produced the most severe findings in the whole audit** (schema-apply data loss and the MCP admin blast radius).

### 8a. `rebase db push` is a silent-data-loss command (2 CRITICAL) — belongs in P0
The restore/retention/doctor/bootstrap paths are mostly well-guarded, but the schema-*apply* path is sharp:
- **CRITICAL — `db push` drops columns silently.** `cli.ts:174` runs `atlas schema apply --auto-approve` with no dry-run/diff/confirmation/migration file. Remove a field → `DROP COLUMN`; rename → drop+add. The templates present `push` as the day-one workflow and nothing gates the target, so pointing it at prod destroys prod columns with no prompt.
- **CRITICAL — a transient introspection failure can drop *every* unmapped table.** `cli-helpers.ts:146-177` builds the `--exclude` list that shields non-collection tables; on any query error it **fails open** (returns a near-empty list) and continues, so the auto-approved declarative apply drops every table not in `schema.sql`. Must fail *closed*.
- **HIGH — backups omit roles/globals.** `pg-tools.ts:178-195` uses single-DB `pg_dump` (no `pg_dumpall --globals-only`), so `rebase_user` is absent from the dump; restore runs `pg_restore` without `--exit-on-error` and **silently skips the role-dependent RLS/GRANT statements**, reporting success → policies un-enforced after a restore. A recovery *and* security hole.
- **MEDIUM — scheduled backups hard-delete old dumps without validating the new one** (`backup-cron.ts:140-173`) — a corrupt-but-exit-0 dump prunes the good backups. And the generate+migrate "safe" path still bakes `DROP COLUMN` into migration SQL with no `atlas migrate lint` destructive gate; push is non-transactional (a mid-push failure leaves committed drops, no rollback).
- **Confirmed-safe:** restore confirmation-gating (non-TTY = no), `--target-db`/`--create-db` won't clobber the live DB, Atlas dev-diff uses a separate `_dev_diff` DB, `doctor` is read-only. (Note: the OSS path uses Atlas with linear-order enforcement, so the saas "high-water-mark skips out-of-order migrations" hazard is lower-risk here.)
- **Action (now P0):** make `db push` fail *closed* on introspection error, gate destructive changes behind a confirmation/`--allow-destructive` + a shown diff, add `pg_dumpall --globals-only` (or document role recreation) to backups and `--exit-on-error` to restore, and validate a dump before pruning.

### 8b. Transactional email is solid; observability has gaps
- **Good:** password-reset and magic-link are genuinely deliverable and safe — real Nodemailer SMTP, 320-bit tokens stored as SHA-256 only, single-use + expiring (1h/15min), reset origin from **trusted config not the Host header** (no host-header takeover), and unconfigured email fails *loudly* with 503 (no silent lockout). Structured JSON logs with request-id correlation + `/health` DB ping.
- **Fix:** default from-address `noreply@rebase.pro` (a domain self-hosters don't own → SPF/DKIM/DMARC fail → mail silently spam-filed; require `SMTP_FROM`); the **email-verification token never expires and isn't cleared after use** (permanent standing credential — add expiry + single-use); no log-redaction layer (login logs the plaintext email; nothing stops a future `{token}` leak); no durable audit log / metrics / error-tracking; email rate-limit is per-IP-per-replica not per-target (mail-bomb a victim). saas `invite-by-email` sends no actual email (only resolves existing users).

### 8c. The MCP / AI surface is the agent-native pitch's biggest risk (2 CRITICAL, 2 HIGH)
The MCP server is stdio-only (not network-exposable), but the trust model is dangerous **and the README markets pointing it at production** (`README.md:23`):
- **CRITICAL — every MCP tool runs as unconditional admin.** The service-key credential reports Rebase admin (`server/src/auth/middleware.ts:315-324`); a compromised/prompt-injected agent gets full read/write of all data + user/role/storage/cron/function control with **zero confirmation gating or allowlist** on any destructive tool. The "lethal trifacta" is present: `list_documents` returns attacker-writable rows to the agent, and the same session can `create_user` with `roles:["admin"]`, `reset_password`, or `db_push` (drop tables) — no prompt (`index.ts:1064,1111,1142,385`).
- **CRITICAL — the admin gate is theater.** `ensureAdmin` (`index.ts:342-353`) checks a role the service-key already reports as admin — it protects nothing, and only the branch tools even call it.
- **HIGH — RCE on the dev host.** `runRebaseCmd` uses `shell:true` and appends the agent-supplied branch `name`/`from` unquoted (`index.ts:844,896`) → shell injection on the developer's machine.
- **HIGH — hardcoded shared LLM/enhancement key in the browser bundle:** `fcms-U9jdDii…` (`plugin-ai/src/useDataEnhancementPlugin.tsx:7`) — extractable by anyone, drains shared quota. **Rotate it and move it server-side (quick win).**
- **MEDIUM — default third-party egress:** plugin-ai posts DB content + the admin's auth token to `api.rebase.pro` on autofill (`plugin-ai/src/api.ts:13,56-66`), and AI suggestions are written to form fields with no output validation. Make this opt-in and self-hostable.
- **Safe:** `packages/inference` does no SQL/DB access (injection-safe); `plugin-insights` callbacks are developer-authored and touch no LLM/secrets. MCP goes through the SDK/HTTP API (no raw-SQL tool), but `db_push`/`db_migrate` run DDL.
- **Action:** add per-tool allowlist + confirmation gating for destructive MCP tools (or a read-only default mode), quote/validate the branch args (fix the RCE), stop marketing "point it at production" without a scoped `rk_` key story instead of the full-admin service key, and rotate+relocate the hardcoded plugin-ai key.
