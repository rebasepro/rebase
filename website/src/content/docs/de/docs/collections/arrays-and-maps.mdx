Eine Array-Spalte ist eine Liste, die das Formular wiederholt. Eine `jsonb`-Spalte ist ein
Dokument: Das CMS erstellt ein Formular dafür, wenn die Spalte ihre Struktur mit
[`json.*`](/docs/schema/json/) beschreibt, und bietet eine freie Schlüssel/Wert-Bearbeitung,
wenn dies nicht der Fall ist.

```ts
// backend/schema/pages.ts
import { defineTable, col, json } from "@rebasepro/server/schema";

export const pages = defineTable("pages", {
    columns: {
        id:       col.uuid().primaryKey().defaultRandom(),
        tags:     col.text().array(),
        settings: col.jsonb().$type<{ theme?: "light" | "dark"; pinned?: boolean }>(),
        address:  col.jsonb(json.object({
            street: json.string().required(),
            city:   json.string(),
            zip:    json.string(),
        })),
        body:     col.jsonb(json.array(json.oneOf({
            paragraph: json.string(),
            image:     json.storage({ path: "pages/images/", accept: ["image/*"] }),
            quote:     json.object({ text: json.string().required(), author: json.string() }),
        }))),
    },
    rls: "admin-only",
});
```

## Arrays

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Eine Array-Spalte (`col.text().array()`) ist eine wiederholbare Liste des Elementfelds: `tags`
oben ist eine Liste von Texteingaben. `.validate({ minItems, maxItems, uniqueItems })` auf dem
Array legt fest, wie viele Elemente das Formular akzeptiert.

<FieldWidgetPreview client:only="react" variant="repeat" />

Ein Array einer geschlossenen Menge, `col.text({ enum: [...] }).array()`, ist stattdessen eine
Mehrfachauswahl; siehe [geschlossene Mengen](/docs/collections/properties/#closed-sets-of-values).
Eine `col.storage().multiple()`-Spalte ist ein Upload für mehrere Dateien; siehe
[Datei-Uploads](/docs/collections/file-uploads/#several-files).

## Dokumente mit einer Struktur

<span class="since-badge" data-since="0.31">Seit 0.31</span>

`col.jsonb(json.object({ … }))` ist eine Gruppe von Feldern, eines pro Schlüssel, jeweils das
Feld, das sein `json.*`-Builder vorsieht: `json.string()` ein Texteingabefeld, `json.number()`
eine Zahl, `json.date()` eine Datumsauswahl, `json.storage()` ein Upload-Feld. Ein
`.required()`-Schlüssel ist im Formular erforderlich, und ein `.default()` befüllt das Formular
eines neuen Datensatzes.

<FieldWidgetPreview client:only="react" variant="group" />

`json.array(of)` wiederholt sein Element. Ein Array aus `json.oneOf({ … })` ist ein
Block-Editor: Jede Variante ist eine Art von Block, den eine Person hinzufügen, neu anordnen
und entfernen kann. `body` oben enthält Absätze, Bilder und Zitate.

<FieldWidgetPreview client:only="react" variant="block" />

Ein eigenständiges `json.oneOf` außerhalb eines Arrays sowie `json.unknown()` besitzen kein
strukturiertes Feld: Sie werden als freies JSON bearbeitet.

## Dokumente ohne Struktur

<span class="since-badge" data-since="0.31">Seit 0.31</span>

`col.jsonb().$type<T>()` typisiert das Dokument für TypeScript, aber `T` wird beim Ausführen
des Codes gelöscht, sodass der Server und das CMS nichts darüber wissen. `settings` oben wird
als freie Schlüssel/Wert-Paare bearbeitet. Geben Sie der Spalte eine `json.*`-Struktur, wenn
das CMS dafür ein Formular darstellen soll.

## Elemente und verschachtelte Schlüssel anpassen

<span class="since-badge" data-since="0.31">Seit 0.31</span>

```tsx
// frontend/src/cms/pages.tsx
import { customizeTable } from "@rebasepro/cms";
import type { pages } from "../../../backend/schema/pages";

export const pagesCms = customizeTable<typeof pages>("pages", {
    fields: {
        tags: { sortable: false, of: { previewAsTag: true } },
        address: {
            spreadChildren: true,
            fieldOrder: ["zip", "city", "street"],
            fields: {
                street: { name: "Street and number" },
                zip:    { name: "Postal code", span: 1 },
            },
        },
        body: {
            expanded: true,
            oneOf: {
                paragraph: { markdown: true },
                quote:     { fields: { author: { name: "Who said it" } } },
            },
        },
    },
});
```

Bei einem Array:

| Option | Wirkung |
|---|---|
| `of` | Die Optionen jedes Elements: jede Feldoption, so tief verschachtelt wie das Element selbst. |
| `sortable` | Elemente können per Drag-and-Drop neu angeordnet werden. |
| `canAddElements` | Elemente können hinzugefügt werden. |
| `expanded` | Jedes Element ist beim Laden geöffnet. |
| `minimalistView` | Elemente ohne ihren Rahmen und Header. |
| `oneOf` | Für eine Liste typisierter Blöcke: die Optionen jeder Variante, nach Variantenname. |
| `enumLabels`, `enumOrder`, `storage` | Werden für das Array definiert und auf jedes Element angewendet. |

Bei einem Dokument:

| Option | Wirkung |
|---|---|
| `fields` | Die Optionen jedes Schlüssels, nach Schlüssel; jede akzeptiert beliebige Feldoptionen, einschließlich eigener `fields`. |
| `fieldOrder` | Die Reihenfolge, in der die Schlüssel angezeigt werden. |
| `previewFields` | Die Schlüssel, die angezeigt werden, wenn das Dokument als Vorschau dargestellt wird. |
| `spreadChildren` | Die Schlüssel werden so angeordnet, als wären sie die eigenen Felder des Datensatzes. |
| `expanded` | Die Schlüssel sind beim Laden geöffnet. |
| `minimalistView` | Die Schlüssel ohne den Rahmen des Dokuments. |
| `keyValue` | Als freie Schlüssel/Wert-Paare bearbeiten, selbst wenn die Spalte eine Struktur hat. |

`fields`, `fieldOrder` und `previewFields` sind anhand der Schlüssel des Dokuments typisiert,
unabhängig davon, ob die Spalte `col.jsonb().$type<T>()` ist oder eine `json.*`-Struktur hat.
Bei einer `col.jsonb().$type<T>()`-Spalte hat das CMS jedoch keine Struktur, auf die sie
angewendet werden könnten: Sie werden übersprungen, begleitet von einer Warnung während der
Entwicklung. Verschachtelte Optionen für einen Schlüssel, eine Variante oder ein Element,
das das Dokument nicht besitzt, werden auf dieselbe Weise übersprungen.
