Jede Spalte einer Tabelle ist ein Feld im CMS. Welche Art von Feld es ist, ergibt sich
aus der Spalte: ihr Typ, ihre Validierung und ihre Speicherregeln, die alle in
[`backend/schema`](/docs/schema/columns/) deklariert werden. Wie das Feld aussieht,
können Sie feldweise in [`customizeTable`](/docs/frontend/customize-table/) anpassen.

Diese Tabelle wird in den folgenden Beispielen verwendet:

```ts
// backend/schema/products.ts
import { defineTable, col } from "@rebasepro/server/schema";

export const products = defineTable("products", {
    columns: {
        id:          col.uuid().primaryKey().defaultRandom(),
        name:        col.text().notNull().validate({ min: 2, max: 200 }),
        description: col.text(),
        body:        col.text(),
        supportEmail: col.text().validate({ email: true }),
        website:     col.text().validate({ url: true }),
        category:    col.enum(["electronics", "clothing", "home"]).notNull(),
        locales:     col.text({ enum: ["es", "en", "fr"] }).array(),
        price:       col.numeric({ precision: 10, scale: 2 }).notNull(),
        stock:       col.integer().default(0),
        onSale:      col.boolean().default(false),
        launchDay:   col.date(),
        availableAt: col.timestamp({ withTimezone: true }),
        ownerId:     col.uuid().userId(),
        createdAt:   col.timestamp({ withTimezone: true }).notNull().onCreateNow(),
        createdBy:   col.uuid().onCreateUser(),
    },
    rls: "admin-only",
});
```

Ohne eine Frontend-Datei besitzt jede Spalte bereits ein Feld. Diese Anpassung
ändert einige davon:

```tsx
// frontend/src/cms/products.tsx
import { customizeTable } from "@rebasepro/cms";
import type { products } from "../../../backend/schema/products";

export const productsCms = customizeTable<typeof products>("products", {
    fields: {
        description: { multiline: true },
        body:        { name: "Product page", markdown: true },
        website:     { urlPreview: true },
        category: {
            enumLabels: {
                electronics: { label: "Electronics", color: "blueDark" },
                clothing:    { label: "Clothing", color: "pink" },
            },
            enumOrder: ["home", "electronics", "clothing"],
        },
        locales: {
            enumLabels: { es: "Spanish", en: "English", fr: "French" },
        },
        price:       { format: { style: "currency", currency: "EUR" } },
        stock:       { format: { notation: "compact" }, columnWidth: 90 },
        availableAt: { timezone: "Europe/Madrid" },
    },
});
```

## Text

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Eine `col.text()`-, `col.varchar({ length })`-, `col.char({ length })`- oder `col.uuid()`-Spalte ist ein
Texteingabefeld. `varchar(n)` und `char(n)` begrenzen die Länge auf `n`, und `.validate({ min,
max, length, matches })` fügt Regeln hinzu, die das Formular vor dem Speichern prüft.

<FieldWidgetPreview client:only="react" variant="text" />

`multiline: true` macht daraus ein mehrzeiliges Textfeld (Textarea), das mit seinem Inhalt wächst.

<FieldWidgetPreview client:only="react" variant="multiline" />

`markdown: true` macht daraus einen Markdown-Editor mit Werkzeugleiste und Vorschau.

<FieldWidgetPreview client:only="react" variant="markdown" />

`.validate({ email: true })` an der Spalte erzeugt ein E-Mail-Eingabefeld, das als
E-Mail validiert wird. Da es sich um eine Eigenschaft der Daten handelt, wird dies an der Spalte
deklariert, wo auch der Server dies prüft.

<FieldWidgetPreview client:only="react" variant="email" />

`.validate({ url: true })` erzeugt ein URL-Eingabefeld, das als URL validiert wird, mit einer
Linkvorschau. `urlPreview` ändert lediglich die Vorschau: `true` für einen Link oder `"image"`,
`"video"`, `"audio"` oder `"file"`, um das Medium direkt inline anzuzeigen.

<FieldWidgetPreview client:only="react" variant="url" />

Eine mit `.userId()` gekennzeichnete Text- oder UUID-Spalte enthält die ID eines Benutzers und dient als
Auswahl für die Benutzer des Projekts: deren Namen, E-Mails und Avatare werden jedem angeboten,
der Schreibrechte auf die Tabelle hat. `ownerId` oben ist ein solches Feld. Ebenso jedes Element eines
`col.text().userId().array()`.

`previewAsTag: true` stellt den Wert außerhalb des Formulars als Chip dar. `clearable:
true` fügt ein Steuerelement hinzu, das ihn auf `null` setzt. `referenceTo: "<slug>"` behandelt den
Wert als Schlüssel eines Datensatzes in einer anderen Collection (auf einer beliebigen Datenquelle) und
stellt eine Referenzauswahl dar; siehe [Firestore](/docs/frontend/firebase/#from-a-table-to-firestore).

## Feste Wertemengen (Enums)

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Ein `col.enum([...])` ist ein Select-Feld, das an anderer Stelle als farbiger Chip dargestellt wird. Dasselbe gilt für eine
Text- oder Zahlenspalte mit `.oneOf([...])`. Jeder Wert erhält eine Beschriftung anhand seines
Bezeichners (`needs_review` wird zu „Needs Review“) und eine vom Wert abgeleitete Farbe,
die bei jedem Laden identisch bleibt.

<FieldWidgetPreview client:only="react" variant="select" />

`enumLabels` definiert Beschriftungen und Farben für ausgewählte Werte; ein nicht aufgeführter Wert
behält seine abgeleitete Beschriftung und Farbe. Jeder Eintrag ist ein String oder
`{ label, color?, disabled? }`: `color` ist ein Schlüssel für eine Chip-Farbe wie `"green"`
oder `"orangeDark"`, und `disabled` lässt den Wert sichtbar, verhindert jedoch dessen
Auswahl. `enumOrder` bestimmt die Reihenfolge, in der Werte angeboten werden, sowie die Reihenfolge von
Kanban-Spalten. Beides wird anhand der Spalte überprüft: Ein Wert, den die Spalte nicht
aufnehmen kann, führt zu einem Typfehler.

Ein Array einer festen Wertemenge, `col.text({ enum: [...] }).array()`, ist ein
Multi-Select über eine einzelne `text[]`-Spalte. Für das Array definierte `enumLabels` gelten
auch für dessen Elemente.

<FieldWidgetPreview client:only="react" variant="multi_select" />

## Zahlen

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Jede Integer-, Serial-, `real`-, `doublePrecision`- und `numeric`-Spalte ist ein
Zahleneingabefeld. Integer- und Serial-Spalten akzeptieren nur ganze Zahlen, und
`.validate({ min, max, moreThan, lessThan, positive, negative })` fügt Begrenzungen hinzu.

<FieldWidgetPreview client:only="react" variant="number" />

`format` formatiert die Zahl für die Anzeige, ohne den gespeicherten Wert zu verändern: `style`
(`"decimal"`, `"currency"`, `"percent"`), `currency` (zusammen mit `"currency"`),
`locale`, `minimumFractionDigits`, `maximumFractionDigits` und `notation:
"compact"`, wodurch `12000` in einer schmalen Spalte als `12K` dargestellt wird. `clearable` fügt ein
Steuerelement hinzu, das den Wert auf `null` setzt.

## Boolscher Wert

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Ein `col.boolean()` ist ein Schalter (Switch).

## Datum und Uhrzeit

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Ein `col.timestamp({ withTimezone: true })` ist eine Datums- und Uhrzeitauswahl, ein `col.date()` eine Datumsauswahl und
ein `col.time()` eine Uhrzeitauswahl. `mode` wechselt zwischen `"date"` und
`"date_time"`, und `timezone` zeigt und wählt den Wert in einer festen IANA-Zeitzone
(`"Europe/Madrid"`) statt in der des Betrachters.

<FieldWidgetPreview client:only="react" variant="date" />

<FieldWidgetPreview client:only="react" variant="date_time" />

Eine vom Server gesetzte Spalte mit `.onCreateNow()` oder `.onUpdateNow()` ist
schreibgeschützt, wird im Metadatenblock des Datensatzes angezeigt und in den Standard-Tabellenspalten
ausgelassen. Spalten mit `.onCreateUser()` und `.onUpdateUser()` sind schreibgeschützt:
Der Server schreibt die ID des ausführenden Benutzers, unabhängig vom Inhalt der Anfrage.

## Dateien

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Eine `col.storage({ … })`-Spalte ist ein Upload-Feld mit Vorschau, und
`.multiple()` macht daraus ein Mehrfachdatei-Feld. Der Bucket, der Pfad, die akzeptierten
Dateitypen und das Größenlimit werden an der Spalte deklariert; die Funktionen, die im
Browser ausgeführt werden, werden mit `storage` in `customizeTable` hinzugefügt. Siehe
[Datei-Uploads](/docs/collections/file-uploads/).

<FieldWidgetPreview client:only="react" variant="file_upload" />

## Arrays und JSON

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Eine Array-Spalte (`<item>.array()`) ist eine wiederholbare Liste des Element-Felds. Eine `jsonb`-Spalte
mit einer [`json.*`-Struktur](/docs/schema/json/) ist eine Gruppe aus typisierten Feldern, Listen und
Blöcken; eine ohne Struktur ist ein Schlüssel-Wert-Editor. Siehe
[Arrays und JSON](/docs/collections/arrays-and-maps/).

## Relationen und Referenzen

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Ein `belongsTo` ist eine Auswahl für die verknüpfte Zeile, die anstelle der Foreign-Key-Spalte
angezeigt wird; eine To-Many-Relation wird als Reiter (Tab) des Datensatzes dargestellt. Eine Textspalte mit
`referenceTo` ist ebenfalls ein Auswahlelement.

<FieldWidgetPreview client:only="react" variant="reference" />

Siehe [Relationen im Panel](/docs/collections/relations-in-the-admin-panel/).

## Geopoints, Vektoren und Binärdaten

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Ein `col.geopoint()` ist ein Feld für Breiten- und Längengrad. Ein `col.vector({ dimensions })` ist eine
Vektoreingabe; `clearable` ist dessen einzige Option. Ein `col.bytea()` ist ein Binärfeld,
das als Base64 gelesen und geschrieben wird. Keines dieser Felder hat typspezifische Optionen über
diejenigen hinaus, die jedes Feld unterstützt.

## Optionen, die jedes Feld unterstützt

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Unabhängig vom Spaltentyp:

- `name` und `description` ersetzen die abgeleitete Beschriftung und ergänzen Hilfetext.
- `hidden` blendet das Feld in Tabellen- und Kartenansichten aus, und `hiddenInForm`
  blendet es im Formular aus. Beides ändert nichts daran, was die API liest oder schreibt; um
  einen Wert vor einem Aufrufer zu verbergen, verwenden Sie [Feldzugriff](/docs/collections/field-access/).
- `readOnly` stellt den Wert als Text dar; `disabled` graut das Steuerelement aus, und als
  `{ disabledMessage, clearOnDisabled }` erklärt es den Grund und leert den Wert.
- `columnWidth` legt die Breite der Tabellenspalte fest; `span` bestimmt, wie viele der
  vier Rasterspalten des Formulars das Feld einnimmt (siehe [Formular-Layout](/docs/frontend/form-layout/)).
- `filterOperators` schränkt die für das Feld angebotenen Filteroperatoren ein, und
  `[]` deaktiviert das Filtern dafür vollständig. Die angebotenen Operatoren ergeben sich aus der
  Schnittmenge der Operatoren, die die Datenquelle ausführen kann, den Standardwerten des Typs und dieser Liste:
  Sie können nur einschränken.
- `filledByServer` erlaubt es, das Feld beim Erstellen leer zu lassen, damit ein Server-Hook
  es befüllen kann.
- `Field`, `Preview` und `Filter` ersetzen das Formular-Steuerelement, die Darstellung außerhalb
  des Formulars und das Filter-Steuerelement durch Ihre eigenen Komponenten; `customProps` wird
  unverändert an sie übergeben. Siehe [Benutzerdefinierte Felder](/docs/frontend/custom-fields/).
- `propertyConfig` gibt einen Feldtyp an, der unter `<Rebase propertyConfigs>` registriert ist.
- `conditions` und `dynamicProps` verändern das Feld basierend auf den Werten des
  Datensatzes selbst; siehe [Bedingte Felder](/docs/collections/validation-and-conditions/#conditional-fields).
- `metadata` steht Ihnen frei zur Verfügung.

Alle Optionen mitsamt Typangaben finden Sie in der
[customizeTable-Referenz](/docs/frontend/customize-table/#field-options).

:::note[Nur Darstellung]
Feldoptionen bestimmen lediglich, was das CMS darstellt. Die API akzeptiert Schreibvorgänge, die
diese ignorieren, und es steht kein Constraint dahinter. Was für jeden Aufrufer gelten
muss, gehört an die Spalte (`.notNull()`, `.validate()`, `.access()`) oder in die
[Row-Level-Security](/docs/collections/security-rules/) der Tabelle.
:::
