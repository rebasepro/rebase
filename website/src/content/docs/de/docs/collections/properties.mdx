## Übersicht

Properties definieren die Spalten in Ihrer Datenbanktabelle und wie sie in der Admin-UI gerendert werden. Jede Property hat einen `type`, der Folgendes bestimmt:

- Den **Datenbankspaltentyp** (über die Drizzle-Schema-Generierung)
- Die **Formularfeld**-Komponente
- Den **Tabellenzellen**-Renderer
- Die **Validierungs**regeln

## Property-Typen

| Typ | Beschreibung | PostgreSQL-Spalte |
|------|-------------|-------------------|
| `string` | Text, Select, Markdown, Datei-Upload, URL, E-Mail | standardmäßig `text`; `varchar`, `char` oder `uuid` mit `columnType`; ein Postgres-Enum-Typ (`<table>_<column>`) mit `enum` |
| `number` | Ganzzahl, Dezimalzahl, Währung | `integer`, `numeric`, `bigint`, `serial` |
| `boolean` | True/False-Umschalter | `boolean` |
| `date` | Datum, Datum/Uhrzeit, Timestamp | standardmäßig `timestamptz`; `date` oder `time` mit `columnType` |
| `array` | Geordnete Liste von Werten | Ein natives Array (`text[]`, `integer[]`, `numeric[]`, `boolean[]`), wenn `of` eine einzelne String-, Number- oder Boolean-Property ist; andernfalls `jsonb` |
| `map` | Schlüssel-Wert-Objekt | `jsonb` |
| `geopoint` | Breitengrad-/Längengrad-Paar | `jsonb` |
| `reference` | Eingebettete Referenz auf eine andere Entität | Der Primärschlüsseltyp des Ziels (speichert dessen ID) |
| `relation` | SQL-Fremdschlüssel-Relation | Verwendet das `relations`-Array |
| `vector` | Embedding, für Nearest-Neighbor-Suche | `VECTOR(n)` (pgvector) |
| `binary` | Rohdatenbytes, gelesen und geschrieben als Base64 | `bytea` |

## Gemeinsame Properties

Alle Property-Typen teilen sich diese Optionen:

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `type` | `string` | **Erforderlich.** Datentyp (siehe oben) |
| `name` | `string` | Anzeigename (Label). Standardmäßig der Property-Schlüssel, formatiert – `publishDate` → "Publish Date". Setzen Sie ihn, wenn diese Ableitung nicht passt: `"URL"` statt "Url". |
| `description` | `string` | Hilfetext, der unter dem Feld angezeigt wird |
| `defaultValue` | `any` | Standardwert für neue Entitäten. Ein literaler Wert – ein String, eine Zahl, ein Boolean, ein Datum, eine Enum-ID oder ein als JSON gespeichertes `map`/`array`-Dokument – wird auch zum `DEFAULT` der Spalte, sodass eine Zeile, die von etwas anderem als dem Admin-Panel eingefügt wird (die REST-API, ein Seed, `psql`), diesen ebenfalls erhält |
| `databaseDefault` | `boolean \| SqlExpression` | Die Datenbank füllt die Spalte, wenn sie bei der Erstellung leer gelassen wird: eine `NOT NULL DEFAULT <Ausdruck>`-Spalte wie `gen_random_uuid()` oder `nextval(…)`. Ein `required`-Feld damit kann bei der Erstellung im Admin-Formular und über die API weggelassen werden, und ein beim Erstellen übergebenes `null` wird der Datenbank überlassen; beim Bearbeiten bleibt es erforderlich, und der generierte `Insert`-Typ macht es optional. Geben Sie den Ausdruck in der Template-Form an, die auch `isId` verwendet: ``databaseDefault: "sql`gen_random_uuid()`"``, und der Schema-Planer schreibt ihn als `DEFAULT` der Spalte, sodass `rebase db push` ihn beibehält. `true` deklariert ein an anderer Stelle geschriebenes `DEFAULT`: Der Planer schreibt keines, und `rebase db push` lässt das, welches die Datenbank hält, unverändert. "Import from table" und `rebase schema introspect` setzen den Ausdruck, den sie auslesen |
| `validation` | `object` | Validierungsregeln |
| `propertyConfig` | `string` | Registrierter Property-Config-Schlüssel |
| `columnName` | `string` | Expliziter Datenbankspaltenname (umgeht die snake_case-Konvertierung) |
| `callbacks` | `PropertyCallbacks` | Hooks für `afterRead`- und `beforeSave`-Transformationen |
| `excludeFromApi` | `boolean` | Diese Spalte niemals auf der API-Oberfläche erwähnen, in keiner Richtung – für einen Passwort-Hash oder ein Verifikationstoken. Der Wert wird serverseitig weiterhin geschrieben und abgefragt; er wird aus jeder Zeile entfernt, die die API ausliefert, für jeden Aufrufer einschließlich Admins und Service-Schlüsseln, und fehlt in den generierten `Row`-, `Insert`- und `Update`-Typen sowie im OpenAPI-Schema. Syntaktischer Zucker für `access: { read: [], write: [] }` – beides ist derselbe Mechanismus, und das Festlegen von beidem für eine Property wird beim Booten abgelehnt |
| `access` | `{ read?: string[]; write?: string[] }` | Wer dieses einzelne Feld lesen und wer es schreiben darf, nach Rolle. Eine weggelassene Liste delegiert an die [Sicherheitsregeln](/docs/collections/security-rules/) der Zeile; `[]` bedeutet niemand über die API; eine Rollenliste umfasst diese Rollen plus `admin`. Ein nicht lesbares Feld ist in Antworten **nicht vorhanden** (statt `null`), und ein Schreibzugriff, der ein nicht schreibbares Feld benennt, ergibt einen 400-Fehler. Siehe [Feldzugriff](/docs/collections/field-access/) |
| `metadata` | `Record<string, unknown>` | Alles, was Ihr eigener Code an eine Property anhängen muss. Rebase liest es nicht; es übersteht die Serialisierung unverändert |
| `dynamicProps` | `function` | Dynamischer Property-Builder (siehe [Bedingte Felder](/docs/collections/validation-and-conditions/#conditional-fields)). **Nur Admin-Formular – wird nicht von der API oder der Datenbank erzwungen.** |
| `conditions` | `PropertyConditions` | Deklarative JSON-Logic-Bedingungen. **Nur Admin-Formular – wird nicht von der API oder der Datenbank erzwungen.** |

:::note[Was "Nur Admin-Formular" bedeutet]
Mehrere Optionen unten tragen diesen Hinweis: Sie bestimmen das Formular, das das Panel darstellt, und sonst nichts – die API akzeptiert Schreibvorgänge, die sie ignorieren, und es steht kein Constraint dahinter. Eine Regel, die für jeden API-Aufrufer gelten muss, ist eine [Validierungsregel](/docs/collections/validation-and-conditions/) – geprüft bei REST-, Socket- und MCP-Schreibvorgängen, [nicht bei In-Process-Vorgängen](/docs/collections/validation-and-conditions/#where-validation-runs) – oder eine [Sicherheitsregel](/docs/collections/security-rules/), die die Datenbank für jeden erzwingt.
:::

### UI-Konfiguration (`admin`)

UI-bezogene Optionen sind unter dem `admin`-Unterobjekt verschachtelt:

```typescript
price: {
    type: "number",
    name: "Price",
    admin: {
        readOnly: true,
        columnWidth: 120,
        hideFromCollection: false
    }
}
```

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `admin.readOnly` | `boolean` | Bearbeitung verhindern |
| `admin.disabled` | `boolean \| PropertyDisabledConfig` | Deaktivieren mit optionalem Tooltip |
| `admin.filledByServer` | `boolean` | Der Server füllt das Feld, wenn ein neuer Datensatz es leer lässt (ein `beforeSave`-Hook). Das Formular lässt das Erstellen ohne das Feld zu; beim Bearbeiten bleibt es erforderlich, und die servereigenen Prüfungen gelten weiterhin |
| `admin.hideFromCollection` | `boolean` | In der Tabellenansicht ausblenden. Reine Anzeige: Die verknüpften Zeilen einer ausgeblendeten Relation-Property sind beim Listenabruf weiterhin eingebettet (siehe [Relations](/docs/collections/relations)) |
| `admin.columnWidth` | `number` | Spaltenbreite in Pixeln (Tabellenansicht) |
| `admin.span` | `1 \| 2 \| 3 \| 4` | Feldbreite über das vierspaltige Formularraster |
| `admin.Field` | `ComponentRef` | Benutzerdefinierte Feldkomponente |
| `admin.Preview` | `ComponentRef` | Benutzerdefinierte Tabellenzellenkomponente |
| `admin.Filter` | `ComponentRef` | Benutzerdefiniertes Filterfeld für diese Property. Überschreibt das Override auf Collection-Ebene `Collection.FilterField` und das integrierte typspezifische Feld |
| `admin.filterOperators` | `WhereFilterOp[]` | Schränkt die Operatoren ein, die beim Filtern nach dieser Property angeboten werden. Die angebotene Menge ist die **Schnittmenge** aus den Fähigkeiten der Engine, den Standardwerten des Typs und dieser Liste – Sie können nur einschränken, niemals einen Operator hinzufügen, den die Engine nicht ausführen kann. `[]` deaktiviert das Filtern nach dieser Property |
| `admin.customProps` | `unknown` | Alles, was Ihr eigenes `Field` oder `Preview` benötigt. Rebase reicht es unverändert durch |

#### `PropertyDisabledConfig`

Die Objektform von `admin.disabled`. Das Steuerelement bleibt sichtbar und ausgegraut, was der Unterschied zu `admin.readOnly` ist – ein Betrachter kann die Struktur dessen sehen, was er nicht ausfüllen darf.

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `disabledMessage` | `string` | Warum diese Property deaktiviert ist, wird dem Benutzer angezeigt. Ohne diese Angabe erklärt ein ausgegrautes Steuerelement nichts |
| `clearOnDisabled` | `boolean` | Setzt den Wert auf `null`, wenn die Property deaktiviert wird, damit keine veraltete Angabe mit der Entität gespeichert wird |
| `hidden` | `boolean` | Blendet das Feld vollständig aus, während es deaktiviert ist, anstatt es auszugrauen |

### Multi-Select

Mehrere Werte aus einer festen Menge sind ein **Array eines Enum-Strings**, kein Flag an einem einzelnen: Die Spalte enthält viele Werte, daher ist die Property, die sie beschreibt, das Array. Es handelt sich um eine einzelne Postgres-Spalte, ein `text[]`, anstelle eines Joins: Ein Array, dessen `of` eine einzelne String-Property ist, erhält standardmäßig ein natives Array, und das untenstehende `columnType` gibt dies lediglich explizit an.

```typescript no-verify
locales: {
    type: "array",
    name: "Available locales",
    columnType: "text[]",
    of: {
        type: "string",
        name: "Locale",
        enum: [
            { id: "es", label: "Spanish", color: "pink" },
            { id: "en", label: "English", color: "blueLight" },
            { id: "fr", label: "French", color: "purpleLight" },
        ]
    }
}
```

| `email` | `boolean` | Validierung des E-Mail-Formats |

| `enum` | `EnumValues` | Als Select-Dropdown rendern |

| `isId` | `boolean \| string` | Markiert die Property als Primärschlüssel und legt fest, wer sie füllt: `"manual"` (Sie selbst), `"uuid"` (`gen_random_uuid()`) oder jeder andere String, der unverändert als SQL-Default-Ausdruck der Spalte verwendet wird – direkt (`nanoid()`) oder in Template-Form (``"sql`nanoid()`"``). Die Funktion muss existieren; nichts hier erstellt sie. `"increment"` ist eine **Number**-Strategie und wird hier, wie `"cuid"`, beim Laden der Konfiguration abgewiesen |
| `autoValue` | `"user_on_create" \| "user_on_update"` | Stempelt die Spalte mit der **UID des agierenden Benutzers** – nur bei der Erstellung oder bei jedem Schreibvorgang. Siehe [Audit-Spalten](#audit-spalten) |
| `userSelect` | `boolean` | Als Benutzerauswahl (User Picker) rendern. Der Wert ist eine einfache String-Spalte, die die Benutzer-ID enthält – nichts löst sie beim Eingang auf oder prüft sie. **Nur Admin-Formular – wird nicht von der API oder der Datenbank erzwungen.** Die Auswahl listet Namen, E-Mails und Avatare von Benutzern für jeden auf, der die Collection schreiben darf, über [`GET /api/admin/users/pick`](/docs/backend/auth-endpoints/), ohne den Scope `users:read`. Eine Collection, deren Schreibregeln aus direktem SQL bestehen, zählt nicht dazu, da diese nicht vorab ausgewertet werden können: Dort können nur Inhaber von `users:read` Benutzer auswählen. |
| `admin.previewAsTag` | `boolean` | Diesen String in der Vorschau als Tag rendern |
| `admin.clearable` | `boolean` | Ein Icon zum Leeren des Werts hinzufügen (auf null setzen) |
| `admin.urlPreview` | `PreviewType \| boolean` | Wie ein String gerendert werden soll, der eine URL enthält: `true` für einen Link oder `"image"`, `"video"`, `"audio"` bzw. `"file"` für eine Inline-Vorschau. Reine Darstellung – ob der Wert eine URL *ist*, entscheidet das Flag `url` an der Property, aus dem der OpenAPI-Vertrag generiert wird |

### Audit-Spalten

`autoValue` bei einem String ist das `created_by` / `updated_by`-Pendant zur selben Option bei einem [Datum](#date-optionen):

```typescript
createdBy: {
    type: "string",
    name: "Created by",
    autoValue: "user_on_create",
    admin: { readOnly: true }
},

updatedBy: {
    type: "string",
    name: "Updated by",
    autoValue: "user_on_update"
}
```

Der Wert stammt aus dem Aufrufkontext, niemals aus dem Request-Body – der Treiber überschreibt alles, was übermittelt wurde, sodass ein Aufrufer sich nicht als jemand anderes ausgeben kann, indem er das Feld mitsendet. Eine Spalte, deren Wert der Aufrufer bereitstellt, ist keine Audit-Spalte.

Ohne agierenden Benutzer – ein anonymer Request, ein Service-Token, ein Seed-Skript – wird die Spalte auf `null` gesetzt. In Kombination mit `validation: { required: true }` wird daraus stattdessen ein 400-Fehler: Eine Collection, die darauf besteht zu wissen, wer eine Zeile geschrieben hat, kann keinen anonymen Schreibvorgang akzeptieren.

Es gibt keinen Fremdschlüssel. Die UID ist ein String, der Benutzerspeicher kann eine völlig andere Datenbank sein, und ein gelöschter Benutzer darf den Audit-Trail nicht mit sich reißen – deklarieren Sie eine [Relation](/docs/collections/relations), wenn Sie den Join wünschen.

:::note[Zusammengesetzte Primärschlüssel]
Markieren Sie mehrere Properties mit `isId`, bilden sie einen zusammengesetzten Schlüssel: Die Tabelle erhält einen einzelnen `PRIMARY KEY (a, b)`-Constraint, und eine Zeile wird über alle ihre Schlüsselwerte in Deklarationsreihenfolge adressiert, getrennt durch `:::` – `company_translation/1:::en_US`. Weisen Sie jeder Schlüsselspalte die passende Strategie zu: `isId: true` für einen vom Aufrufer bereitgestellten Wert, was bei den meisten zusammengesetzten Schlüsseln für jede Spalte gilt, und niemals `"increment"` bei einem Fremdschlüssel oder einer String-Spalte. Ein Fremdschlüssel ist eine einzelne Spalte und kann nicht auf einen zusammengesetzten Schlüssel verweisen; daher wird eine Relation oder Referenz *auf* eine solche Collection bei der Schema-Generierung abgelehnt. Wenn Sie eine Eindeutigkeitsbeschränkung über mehrere Spalten statt der Identität der Zeile wollten, ist dies ein eindeutiger [Index](/docs/backend/indexes). Unter 0.23 wird ein zweites `isId` beim Laden der Konfiguration abgewiesen.

Eine Collection, in der keine Property `isId` beansprucht, erhält eine eigene `id`-Spalte: `TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text`. Die Datenbank füllt sie, sodass eine aus dem Admin-Panel, über die REST-API oder das SDK erstellte Zeile keinen Schlüssel benötigt, und ein übergebener Schlüssel wie angegeben verwendet wird. Eine Tabelle, die erstellt wurde, bevor dieser Standard existierte, erhält ihn beim nächsten Start. Unter 0.23 hat die Spalte keinen Standardwert, und eine Erstellung ohne übergebenen Schlüssel schlägt fehl.

Dasselbe gilt für einen deklarierten `isId: "uuid"`-Schlüssel, dessen Tabelle keinen Default hat – eine Tabelle, die mit `rebase schema introspect` übernommen oder manuell erstellt wurde: Beim nächsten Booten wird `DEFAULT gen_random_uuid()` gesetzt. Beim Booten wird für keinen anderen deklarierten Schlüssel ein Default gesetzt. Die Funktion einer SQL-Strategie existiert möglicherweise noch nicht; fügen Sie diesen Default also selbst hinzu oder lassen Sie ihn von `rebase db push` anwenden.
:::

## Number-Properties

```typescript
price: {
    type: "number",
    name: "Price",
    validation: { required: true, min: 0 }
}

quantity: {
    type: "number",
    name: "Quantity",
    columnType: "integer"  // Store as integer
}
```

<FieldWidgetPreview client:only="react" variant="number" />

Number-Felder werden als Standard-Texteingabe mit numerischer Validierung gerendert.

### Number-Optionen

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `enum` | `EnumValues` | Als Select mit numerischen Werten rendern. Anders als bei einem String-Enum wird hierbei **kein Postgres-Enum-Typ** erstellt – die Spalte bleibt `NUMERIC` oder `INTEGER`, sodass das Panel die Werte anbietet und die Datenbank sie nicht erzwingt |
| `columnType` | `string` | `"integer"`, `"real"`, `"double precision"`, `"numeric"`, `"bigint"`, `"serial"`, `"bigserial"`. Standardmäßig `integer`, wenn `validation.integer` oder `isId` besagt, dass der Wert ganzzahlig ist, andernfalls `numeric` |
| `precision` / `scale` | `number` | Gesamtzahl signifikanter Stellen und Nachkommastellen bei einer `numeric`-Spalte – `NUMERIC(10, 2)`. Geldbeträge ohne diese Angaben sind ein unbegrenztes `NUMERIC`, das beibehält, was der Aufrufer gesendet hat, und später nicht ohne Umschreiben der Spalte eingeschränkt werden kann |
| `isId` | `boolean \| string` | Markiert die Property als Primärschlüssel: `"manual"`, `"increment"` oder jeder andere String, der unverändert als SQL-Default-Ausdruck der Spalte verwendet wird. `"increment"` ist immer `INTEGER GENERATED BY DEFAULT AS IDENTITY` – ein daneben stehendes `columnType` wird mit einer Warnung ignoriert, da jeder Fremdschlüssel, der auf einen numerischen Schlüssel verweist, `INTEGER` ist und ein breiterer Schlüssel von schmaleren Spalten referenziert werden würde. `"uuid"` ist eine **String**-Strategie und wird hier beim Laden der Konfiguration abgewiesen |
| `admin.clearable` | `boolean` | Ein Icon zum Leeren des Werts hinzufügen (auf null setzen) |
| `admin.format` | `NumberFormatOptions` | Schreibt die Zahl als Währung, Prozentsatz oder mit festen Dezimalstellen aus. Fehlt die Option, wird der Rohwert gerendert – eine Zahl in der Datenbank wird als die Zahl in der Datenbank dargestellt |

#### `NumberFormatOptions`

Reine Darstellung. Der gespeicherte Wert ändert sich nie – eine gerundete Anzeige ist in der Spalte und in der API weiterhin die vollständige Zahl.

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `style` | `"decimal" \| "currency" \| "percent"` | Standardmäßig `"decimal"`. `"currency"` erfordert `currency` |
| `currency` | `string` | ISO 4217-Code – `"EUR"`, `"USD"`. Das Setzen impliziert `style: "currency"`, daher genügt im Regelfall ein einzelner Schlüssel |
| `locale` | `string` | BCP 47-Tag. Standardmäßig das Gebietsschema (Locale) des Panels, wodurch derselbe Betrag für einen Betrachter als `1,234.50` und für einen anderen als `1.234,50` dargestellt wird |
| `minimumFractionDigits` | `number` | Auffüllen auf mindestens so viele Dezimalstellen – `2` schreibt `5` als `5.00` |
| `maximumFractionDigits` | `number` | Runden auf höchstens so viele Dezimalstellen. Ändert nicht den gespeicherten Wert |
| `notation` | `"standard" \| "compact"` | `"compact"` rendert `12000` als `12K`. Nützlich in einer schmalen Tabellenspalte |

### Automatische Zeitstempel

Verwenden Sie `autoValue`, um Zeitstempel beim Erstellen oder Aktualisieren automatisch zu setzen.

```typescript
createdAt: {
    type: "date",
    name: "Created At",
    autoValue: "on_create",
    admin: { readOnly: true }
}

updatedAt: {
    type: "date",
    name: "Updated At",
    autoValue: "on_update"
}
```

`on_update` ist ein Datenbank-Trigger, nicht nur ein Stempel auf Anwendungsebene. Rebase schreibt die Spalte bei jedem Speichervorgang, den es durchführt – sodass ein `beforeSave`-Hook den neuen Wert sieht – und richtet einen `BEFORE UPDATE`-Trigger ein, der sie für alle anderen schreibt. Ohne den Trigger hinterließ ein Seed-Skript, ein Migrations-Backfill oder eine in `psql` korrigierte Zeile die Spalte mit der Behauptung, die Zeile habe sich nicht geändert, und alles, was sie las, um über eine Neuindizierung oder ein erneutes Senden zu entscheiden, übersprang diese Zeile.

Der Trigger wird in `.rebase/sql/triggers.sql` generiert, durch `rebase db push` und beim Booten durch die Schema-Sicherstellung angewendet – Atlas kann ihn aus demselben Grund nicht verwalten, aus dem es die Volltextsuche-Helfer nicht verwalten kann.

### Date-Optionen

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `mode` | `"date" \| "date_time"` | Nur Datum oder Datum + Uhrzeit (Standard: `"date_time"`). Bestimmt das Widget; die Spalte ist in beiden Fällen identisch. **Nur Admin-Formular – wird nicht von der API oder der Datenbank erzwungen.** |
| `autoValue` | `"on_create" \| "on_update"` | Zeitstempel automatisch setzen. `on_create` ist ein `DEFAULT now()`; `on_update` ist ein `BEFORE UPDATE`-Trigger **sowie** ein Stempel auf Anwendungsebene, sodass ein direktes `UPDATE` aus einem Seed oder einer Migration die Spalte ebenfalls aktualisiert |
| `columnType` | `"timestamp" \| "date" \| "time"` | Die Datenbankspalte. Standardmäßig `timestamp` **mit Zeitzone**. Eine `date`-Spalte wird unabhängig von `mode` als Tag ausgewählt und angezeigt; eine `time`-Spalte ausschließlich als Tageszeit in UTC ohne Tag (sie wird als diese Uhrzeit am 1970-01-01 übertragen) |
| `timezone` | `string` | In welcher Zeitzone die Auswahl den Wert liest und schreibt. **Nur Admin-Formular – wird nicht von der API oder der Datenbank erzwungen.** |
| `admin.clearable` | `boolean` | Ein Icon zum Leeren des Werts hinzufügen (auf null setzen) |

## Array- und Map-Properties

Die beiden zusammengesetzten Typen – eine wiederholbare Liste und ein strukturiertes Objekt, beide als JSONB gespeichert, es sei denn, ein natives Postgres-Array passt. Wiederholungen, Block-Editoren, Gruppen, Key-Value-Editoren und alle Optionen, die beide annehmen, finden Sie unter **[Arrays und Maps](/docs/collections/arrays-and-maps)**.

## Geopoint-Properties

Ein Breitengrad-/Längengrad-Paar, gespeichert als `jsonb` – `{ latitude, longitude }`, was dem entspricht, was der generierte TypeScript-Typ, das OpenAPI-Schema und das Formularfeld beschreiben.

```typescript
location: {
    type: "geopoint",
    name: "Location"
}
```

Schreibvorgänge haben dieselbe Struktur oder nutzen einen `GeoPoint` aus `@rebasepro/types`:
`new GeoPoint(41.4036, 2.1744)`.

Es gibt keine weiteren Optionen über diejenigen hinaus, die jede Property besitzt. Die Spalte ist nicht räumlich indiziert und es gibt keinen Distanzoperator zum Filtern: Ein Geopoint ist ein Wert, den Sie speichern und anzeigen, nicht einer, nach dem Sie suchen. Modellieren Sie dafür die beiden Zahlen als eigene Spalten.

## Reference-Properties

Referenzen verknüpfen mit Entitäten in einer anderen Collection. Sie werden als Vorschaukarte gerendert, die die Details der referenzierten Entität anzeigt.

```typescript
client: {
    type: "reference",
    name: "Related client",
    path: "clients",
    admin: {
        previewProperties: ["first_name", "last_name", "email"]
    }
}
```

<FieldWidgetPreview client:only="react" variant="reference" />

`reference` ist die Verknüpfung der Dokumentdatenbanken (Firestore, MongoDB). Unter Postgres verknüpfen Sie stattdessen mit einer [`relation`](/docs/collections/relations): Die Property-Typen einer `PostgresCollectionConfig` weisen `reference` ab, so wie die einer Firestore-Collection `relation` abweisen. Eine `reference`, die trotzdem beim Schema-Generator ankommt – eine Konfiguration, die ohne diese Typen geschrieben wurde –, wird zu einem Fremdschlüssel mit den `ON DELETE`-Regeln von `belongsTo`: optional ist `SET NULL`, erforderlich ist `RESTRICT`.


### Reference- & Relation-Optionen

Diese gelten sowohl für `reference`- als auch für `relation`-Properties.

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `admin.fixedFilter` | `FilterValues` | Die im Auswahl-Widget angebotenen Entitäten filtern |
| `admin.widget` | `"select" \| "dialog"` | Welches Widget die verknüpfte Entität auswählt (nur Relations) |
| `admin.includeId` | `boolean` | Die ID der verknüpften Entität in Vorschauen anzeigen (Standard: true) |
| `admin.includeEntityLink` | `boolean` | Einen Link anzeigen, der die verknüpfte Entität öffnet (Standard: true) |
| `admin.previewProperties` | `string[]` | Welche Properties des Ziels in der Vorschau erscheinen (max. 3) |
| `admin.renderInForm` | `boolean` | Eine **Many**-Relation als Picker innerhalb des Formulars sowie in dem Tab rendern, den sie bereits erhält. Standardmäßig `false`: Die Entitätsansicht listet die verknüpften Zeilen bereits als Tab auf, sodass die beiden Oberflächen konstruktionsbedingt redundant sind. Keine Auswirkung auf eine To-One-Relation, die keinen Tab erhält |

## Vector-Properties

Eine Embedding-Spalte für die Nearest-Neighbor-Suche. Nur Postgres.

```typescript
embedding: {
    type: "vector",
    name: "Embedding",
    dimensions: 1536
}
```

| Property | Typ | Beschreibung |
|----------|------|-------------|
| `dimensions` | `number` | **Erforderlich.** Länge des Vektors. Kompiliert zu `VECTOR(n)`. |
| `index` | `VectorIndexConfig \| false` | Wie der ANN-Index aufgebaut wird. Wenn weggelassen, ein HNSW-Index für Kosinus-Distanz. `false` erstellt keinen Index. |

Ein ANN-Index wird zusammen mit der Spalte erstellt, sodass `vectorSearch` approximativ und schnell ist statt eines exakten Scans. Er wird für die **Kosinus**-Distanz (Cosine Distance) erstellt, mit der `vectorSearch` misst, sofern Sie nicht `distance` übergeben – ein Index bedient genau einen Operator, sodass eine `l2`-Abfrage gegen einen Kosinus-Index stillschweigend auf einen Scan zurückfällt. `method` (`hnsw` oder `ivfflat`), `distance` (einzeln oder mehrere), `m`, `efConstruction` und `lists` befinden sich alle auf `index`. Über 2000 Dimensionen kann pgvector keinen der beiden Indextypen erstellen; daher bleibt die Spalte unindiziert und der Boot-Vorgang weist darauf hin.

Fragen Sie sie mit [`.vectorSearch()`](/docs/sdk/aggregates-and-search#vector-search) ab, was auch abdeckt, was pgvector für die Installation benötigt und wie der Index optimiert werden kann. Für reguläre B-Tree-, GIN- und BRIN-Indizes auf beliebigen Collections siehe [Indizes](/docs/backend/indexes).

## Binary-Properties

Rohdatenbytes, gespeichert als `bytea`. Werte passieren die API als **Base64-Strings** – einschließlich `defaultValue`.

```typescript
signature: {
    type: "binary",
    name: "Signature"
}
```

Große Dateien gehören in den [Storage](/docs/backend/storage), nicht in eine Spalte: Ein `bytea` wird im Ganzen mit der Zeile gelesen und geschrieben.

Enum-Werte, Validierungsregeln und bedingte Felder haben eine eigene Seite: [Validierung und Bedingungen](/docs/collections/validation-and-conditions/).
