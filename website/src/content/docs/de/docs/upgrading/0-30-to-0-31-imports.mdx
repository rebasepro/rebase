# In 0.31 verschobene Imports

<span class="since-badge" data-since="0.31">Seit 0.31</span>

Die Kernel-Pakete beschreiben ausschließlich Tabellen. Daher wurde alles, was eine Collection für die Darstellung im Admin-Panel beschreibt, nach `@rebasepro/cms-types` verschoben, und das Migrations-Lifting nach `@rebasepro/common/migrate` ([Abschnitt 135 des Upgrade-Leitfadens](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

`rebase migrate sdk-calls` (Teil von `rebase migrate collections-to-tables`) verschiebt jeden der unten aufgeführten Imports in sein neues Paket – zusammengeführt mit einem bereits in der Datei vorhandenen Import dieses Pakets, wobei `import type`, Inline-`type` und `as`-Aliase beibehalten werden – und fügt das Paket zu den Abhängigkeiten des importierenden Workspace-Pakets hinzu; führen Sie danach `pnpm install` aus. Ein Import eines entfernten Namens, ein Namespace-Import, ein `export *`, ein dynamischer `import()` oder ein `require()`, der einen verschobenen Namen verwendet, ist ein nummerierter manueller Schritt.

Diese Liste basiert auf `tooling/scripts/headless-guard/moved-symbols.json`, der Tabelle, die der Codemod einliest. Siehe [`rebase migrate`](/docs/cli/schema/#rebase-migrate) für den Befehl und [Anpassen einer Tabelle](/docs/frontend/customize-table/) für Informationen darüber, wo die Typen des Panels verwendet werden.
