# Upgrade 0.18 → next

**Nichts davon ist veröffentlicht.** Dies sind die `### Breaking`-Einträge aus dem
Abschnitt [`[Unreleased]`](/de/docs/changelog/) des Changelogs: Sie liegen auf
`main`, und diese Dokumentationsseite wird aus `main` veröffentlicht — also
bevor die Version existiert, die sie enthält. Wenn Sie von npm installiert
haben, sind Sie auf 0.20 und nichts davon hat Sie erreicht. 0.19 und 0.20
deklarieren keine Breaking Changes, dies ist also ein Sprung ab 0.18.

---

## 31. `context.client.data` kompiliert in einem Collection-Callback nicht mehr

`RebaseCallContext["client"]` ist jetzt `RebaseCallbackClient`: `RebaseClient`
ohne `data`. Serverseitig ist dieser Client das `rebase`-Singleton, das seit 0.18
kein `data` mehr hat — `context.client.data.collection(…)` kompilierte also und
warf dann bei jedem Aufruf `Cannot read properties of undefined (reading
'collection')`. Jetzt ist es ein Kompilierfehler.

**Zu ändern:** Abfragen über `context.data` stellen, den Accessor, den die
Abfragen eines Callbacks immer verwenden sollten. Er läuft mit den Rechten
dessen, was den Callback ausgelöst hat, in der Transaktion des Schreibvorgangs.
Was jeder Accessor des Kontexts erreicht, beschreibt der
[Callbacks-Leitfaden](/de/docs/collections/callbacks/).

```diff lang="ts"
 afterSave: async ({ context }) => {
-    await context.client.data.audit_logs.create({ action: "approved" });
+    await context.data.audit_logs.create({ action: "approved" });
 }
```

```bash
grep -rn "client\.data\b" config
```

`context.client.dataAsAdmin` bleibt für einen Callback, der sehen muss, was ein
Admin sehen darf. `admin.browserCallbacks` ist ebenfalls betroffen: Dort lief die
alte Schreibweise, weil der Client des Panels `data` hat, und sie kompiliert
trotzdem nicht mehr. `useRebaseContext().client` in einer React-Komponente behält
sein `data`.
