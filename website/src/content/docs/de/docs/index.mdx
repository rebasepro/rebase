## Was ist Rebase?

Rebase ist das **Open-Source-Backend für PostgreSQL** mit einem **Admin-Panel** für Ihr Team, entwickelt mit React und TypeScript. Es bietet Ihnen alles, was Sie zum Erstellen einer produktionsreifen Anwendung auf Basis von **PostgreSQL** benötigen:

- **Schema as Code** — Deklarieren Sie Ihre Postgres-Tabellen in TypeScript, jeweils mit einer erforderlichen Richtlinie für Row Level Security. Rebase generiert aus dieser einzigen Source of Truth die Tabellen und deren Richtlinien, REST-API-Endpunkte, ein typisiertes SDK und eine vollständige CRUD-Benutzeroberfläche.
- **Sofort einsatzbereites Admin-Panel** — Ein ansprechendes, schnelles React-basiertes Panel mit Tabellenkalkulationsansichten, Listen, Formularen, Kanban-Boards, Inline-Bearbeitung und Echtzeitsynchronisierung.
- **Integriertes Backend** — Authentifizierung (Passwörter, Magic Links, Einmal-Codes, MFA, API-Schlüssel und zwölf OAuth/OIDC-Anbieter), Dateispeicher (lokal, S3 oder GCS), Row Level Security, Entitätshistorie und WebSocket-Echtzeit – alles von Haus aus integriert.
- **Radikal erweiterbar** — Was Sie in React erstellen können, können Sie auch zu Rebase hinzufügen. Eigene Felder, benutzerdefinierte Ansichten, Plugins und vollständiger Zugriff auf interne Hooks.

:::tip
Rebase funktioniert auf beide Arten, und Ihr Code ändert sich dabei nicht. **Self-Hosting** — Sie besitzen die Daten, den Code und die Maschine, auf der es läuft. Oder deployen Sie dasselbe Projekt in der **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), was dasselbe Rebase ist, das für Sie betrieben wird; es ist bereits heute mit echten Mandanten live und wird während der privaten Beta schrittweise geöffnet. Betrachten Sie es als Open-Source-Alternative zu Supabase oder Retool, bei der *Sie* entscheiden, wer es betreibt.
:::

## Wählen Sie Ihren Weg

Rebase ist ein Backend und ein Admin-Panel, die sich einen Server teilen. Beginnen Sie mit dem Teil, den
Sie suchen:

| Ich möchte… | Hier starten | Was Sie erhalten |
|---|---|---|
| **Ein Backend und ein Admin-Panel** | [Schnellstart](/docs/getting-started/quickstart/) | Tabellen in TypeScript, eine generierte CRUD-UI, eine REST-API, Authentifizierung, Speicher und Echtzeit |
| **Nur die API über meiner eigenen Datenbank** | [Nur Backend](/docs/getting-started/headless/) | Eine Headless-REST-API und ein SDK über Ihrem bestehenden PostgreSQL — ohne Admin-Panel, ohne Tabellendateien |

Keine der beiden Optionen ist eine Einbahnstraße: Ein Headless-Projekt kann durch Hinzufügen eines
Frontends um ein Admin-Panel erweitert werden, welches jede vom Backend bereitgestellte Tabelle rendert, und beide Varianten können ihre
Tabellen in `backend/schema/` festhalten, wenn sie als Code definiert werden sollen.

## Schnellstart

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` generiert eine sofort einsatzbereite `.env` für Sie — kein Bearbeiten erforderlich. Danach:

```bash
pnpm install
pnpm run dev
```

Das ist schon der gesamte erste Start. Es muss keine Datenbank installiert und kein Schemaschritt ausgeführt werden:
Wenn keine `DATABASE_URL` gesetzt ist, startet `rebase dev` ein verwaltetes PostgreSQL (PGlite) im
Projektverzeichnis, generiert das Schema aus Ihren Tabellen und erstellt
die Tabellen beim Systemstart.

**Lesen Sie die URLs aus der Ausgabe ab.** `rebase dev` wählt pro Projekt einen freien Port
statt fester Ports, sodass sie sich zwischen Projekten und Maschinen unterscheiden.
Das erste Konto, das Sie registrieren, wird zum Admin — auf Ihrer Maschine. Bei einem
Produktions-Deployment wird der Admin stattdessen über `REBASE_ADMIN_EMAIL` und
`REBASE_ADMIN_PASSWORD` festgelegt (siehe [Konfiguration](/docs/getting-started/configuration/)).

Um stattdessen Ihr eigenes Postgres zu verwenden, heben Sie die Auskommentierung von `DATABASE_URL` in der `.env` auf und führen Sie
`pnpm run dev` erneut aus.

→ Folgen Sie der vollständigen [Schnellstartanleitung](/docs/getting-started/quickstart) für eine komplette Übersicht, einschließlich des Verbindens Ihrer eigenen Datenbank.

## Kernfunktionen

| Funktion | Beschreibung |
|---------|-------------|
| **Tabellenkalkulationsansichten** | Schnelle, virtualisierte Tabelle mit Inline-Bearbeitung, Filterung, Sortierung und Textsuche |
| **Listenansicht** | Übersichtliche, responsive vertikale Listenansicht für jede Tabelle |
| **Kanban-Board** | Drag-and-Drop-Boardansicht, gruppiert nach einer beliebigen Enum-Spalte |
| **Relationen** | Eins-zu-Eins, Eins-zu-Viele, Viele-zu-Viele mit Verknüpfungstabellen und Multi-Hop-Joins |
| **Row Level Security** | Postgres-RLS-Richtlinien, kompiliert aus dem `rls`, das jede Tabelle deklarieren muss |
| **Authentifizierung** | JWT + Refresh-Token, zwölf OAuth/OIDC-Anbieter, Magic Links, Einmal-Codes, TOTP MFA, scoped API-Schlüssel, rollenbasierte Zugriffskontrolle |
| **Dateispeicher** | Lokales Dateisystem, S3-kompatibel oder Google Cloud Storage, mit Upload-Feldern und Dateibrowser |
| **Echtzeitsynchronisierung** | WebSocket-gestützte Live-Updates über alle verbundenen Clients hinweg |
| **Entitätshistorie** | Vollständiges Audit-Protokoll für jede Erstellung, Aktualisierung und Löschung |
| **REST-API** | Automatisch generierte CRUD-Endpunkte für jede Tabelle |
| **Datenimport/-export** | CSV-, JSON- und Excel-Import mit Feld-Mapping; CSV/JSON-Export |
| **Typisiertes SDK** | Typsicheres JavaScript-SDK für Ihre Frontend-Anwendungen |
| **Plugin-System** | Erweitern Sie jeden Teil der Benutzeroberfläche — Toolbar, Formulare, Felder, Startseite |
| **KI-Datenoptimierung** | LLM-gestützte Autovervollständigung für Textfelder |
| **Cron-Jobs** | Geplante Hintergrundaufgaben mit Überwachung, Protokollierung und Studio-Dashboard |
| **Eigene Funktionen** | Dateibasierte Hono-Routen, die automatisch mit Authentifizierungs-Middleware und DB-Zugriff eingebunden werden |
| **E-Mail-Dienst** | Integriertes SMTP für Passwortzurücksetzung, Verifizierung und transaktionale E-Mails |
| **Datenbank-Branching** | Sofortige isolierte Kopien Ihrer Datenbank für Entwicklung, Staging oder Tests |
| **Webhooks** | HMAC-signierte ausgehende Benachrichtigungen bei INSERT, UPDATE, DELETE |
| **Broadcast-Kanäle** | WebSocket-Kanäle für Echtzeitnachrichten zwischen verbundenen Clients |
| **Präsenzerkennung** | Online-Benutzer erfassen und gemeinsamen Status über Teilnehmer hinweg synchronisieren |
