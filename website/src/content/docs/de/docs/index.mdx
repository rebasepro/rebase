## Was ist Rebase?

Rebase ist das **Open-Source-Backend für PostgreSQL** mit einem **Admin-Panel** für dein Team, entwickelt mit React und TypeScript. Es bietet alles, was du benötigst, um eine produktionsreife Anwendung auf Basis von **PostgreSQL** zu erstellen:

- **Schema as Code** — Deklariere deine Postgres-Tabellen in TypeScript, jeweils mit einer erforderlichen Row-Level-Security-Einstellung. Rebase generiert aus dieser zentralen Quelle der Wahrheit (Single Source of Truth) die Tabellen und deren Policies, REST-API-Endpunkte, ein typisiertes SDK und eine vollständige CRUD-UI.
- **Sofortiges Admin-Panel** — Ein elegantes, schnelles React-basiertes Panel mit Tabellenansichten im Tabellenkalkulations-Stil, Listen, Formularen, Kanban-Boards, Inline-Bearbeitung und Echtzeitsynchronisierung.
- **Integriertes Backend** — Authentifizierung (Passwörter, Magic Links, Einmal-Codes, MFA, API-Schlüssel und zwölf OAuth/OIDC-Anbieter), Dateispeicher (lokal, S3 oder GCS), Row-Level-Security, Entitätshistorie und WebSocket-Echtzeit – alles von Haus aus integriert.
- **Radikal erweiterbar** — Wenn du es in React bauen kannst, kannst du es zu Rebase hinzufügen. Benutzerdefinierte Felder, individuelle Ansichten, Plugins und vollständiger Zugriff auf interne Hooks.

:::tip
Rebase funktioniert auf beide Arten, und dein Code ändert sich dabei nicht. **Hoste es selbst** – du behältst die volle Kontrolle über die Daten, den Code und den Server, auf dem es läuft. Oder deploye dasselbe Projekt in der **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), was dasselbe Rebase ist, nur für dich betrieben; es ist bereits heute mit echten Mandanten live und wird während der privaten Beta schrittweise geöffnet. Betrachte es als Open-Source-Alternative zu Supabase oder Retool, bei der *du* entscheidest, wer es betreibt.
:::

## Wähle deinen Weg

Rebase ist ein Backend und ein Admin-Panel, die sich einen Server teilen. Starte mit dem, weswegen du hier bist:

| Ich möchte… | Hier starten | Was du bekommst |
|---|---|---|
| **Ein Backend und ein Admin-Panel** | [Quickstart](/docs/getting-started/quickstart/) | Tabellen in TypeScript, eine generierte CRUD-UI, eine REST-API, Auth, Speicher und Echtzeit |
| **Nur die API über meiner eigenen Datenbank** | [Backend only](/docs/getting-started/headless/) | Eine Headless-REST-API und ein SDK über deine bestehende PostgreSQL-Datenbank – kein Admin-Panel, keine Tabellendateien |

Beides ist keine Einbahnstraße: Ein Headless-Projekt kann durch Hinzufügen eines Frontends um ein Admin-Panel erweitert werden, das jede Tabelle darstellt, die das Backend bereitstellt. Und beide Varianten können ihre Tabellen in `backend/schema/` definieren, sobald sie im Code verwaltet werden sollen.

## Schnellstart

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` generiert eine sofort einsatzbereite `.env` für dich – keine Bearbeitung erforderlich. Danach:

```bash
pnpm install
pnpm run dev
```

Das ist bereits der gesamte erste Durchlauf. Es muss keine Datenbank installiert und kein Schema-Schritt ausgeführt werden: Wenn keine `DATABASE_URL` gesetzt ist, startet `rebase dev` ein verwaltetes PostgreSQL (PGlite) im Projektverzeichnis, generiert das Schema anhand deiner Tabellen und erstellt die Tabellen beim Starten.

**Lies die URLs aus der Konsolenausgabe ab.** `rebase dev` wählt für jedes Projekt einen freien Port anstelle fester Ports, sodass sich diese zwischen Projekten und Maschinen unterscheiden. Der erste Account, den du registrierst, wird zum Administrator – auf deiner Maschine. Ein Produktions-Deployment bestimmt seinen Administrator stattdessen über `REBASE_ADMIN_EMAIL` und `REBASE_ADMIN_PASSWORD` (siehe [Konfiguration](/docs/getting-started/configuration/)).

Um stattdessen dein eigenes Postgres zu verwenden, entferne den Kommentar vor `DATABASE_URL` in der `.env` und führe `pnpm run dev` erneut aus.

→ Folge der vollständigen [Quickstart-Anleitung](/docs/getting-started/quickstart) für eine ausführliche Anleitung, einschließlich der Verbindung mit deiner eigenen Datenbank.

## Hauptfunktionen

<span class="since-badge" data-since="0.31">Seit 0.31</span>

| Feature | Beschreibung |
|---------|-------------|
| **Tabellenkalkulations-Ansichten** | Schnelle, virtualisierte Tabelle mit Inline-Bearbeitung, Filterung, Sortierung und Textsuche |
| **Listenansicht** | Übersichtliche, responsive vertikale Listenansicht für jede Tabelle |
| **Kanban-Board** | Drag-and-Drop-Board-Ansicht, gruppiert nach beliebigen Enum-Spalten |
| **Relationen** | 1:1, 1:n, n:m mit Verknüpfungstabellen (Junction Tables) und Multi-Hop-Joins |
| **Row Level Security** | Postgres-RLS-Policies, kompiliert aus der `rls`-Definition, die jede Tabelle deklarieren muss |
| **Authentifizierung** | JWT + Refresh-Tokens, zwölf OAuth/OIDC-Anbieter, Magic Links, Einmal-Codes, TOTP-MFA, berechtigte API-Schlüssel, rollenbasierte Zugriffskontrolle (RBAC) |
| **Dateispeicher** | Lokales Dateisystem, S3-kompatibel oder Google Cloud Storage, mit Upload-Feldern und Datei-Browser |
| **Echtzeitsynchronisierung** | WebSocket-gestützte Live-Updates über alle verbundenen Clients hinweg |
| **Entitätshistorie** | Vollständiges Audit-Protokoll für jede Erstellung, Aktualisierung und Löschung |
| **REST-API** | Automatisch generierte CRUD-Endpunkte für jede Tabelle |
| **Datenimport/-export** | CSV-, JSON- und Excel-Import mit Feld-Mapping; CSV/JSON-Export |
| **Collection-Editor** | Visueller Schema-Editor, der TypeScript in `backend/schema` mittels AST-Manipulation schreibt |
| **Typisiertes SDK** | Typsicheres JavaScript-SDK für deine Frontend-Anwendungen |
| **Plugin-System** | Erweitere jeden Teil der Benutzeroberfläche – Toolbar, Formulare, Felder, Startseite |
| **KI-Datenoptimierung** | LLM-gestützte Autovervollständigung für Textfelder |
| **Cron-Jobs** | Geplante Hintergrundaufgaben mit Überwachung, Protokollierung und Studio-Dashboard |
| **Eigene Funktionen** | Dateibasierte Hono-Routen, automatisch eingebunden mit Auth-Middleware und Datenbankzugriff |
| **E-Mail-Dienst** | Integriertes SMTP für Passwort-Resets, Verifizierungen und Transaktions-E-Mails |
| **Datenbank-Branching** | Sofortige, isolierte Kopien deiner Datenbank für Entwicklung, Staging oder Tests |
| **Webhooks** | HMAC-signierte ausgehende Benachrichtigungen bei INSERT, UPDATE, DELETE |
| **Broadcast-Kanäle** | WebSocket-Kanäle für Echtzeit-Nachrichten zwischen verbundenen Clients |
| **Präsenz-Tracking** | Verfolge Online-Benutzer und synchronisiere den geteilten Zustand zwischen Teilnehmern |
