# Upgrade einer bestehenden App

Elf Schritte, die neuesten zuerst. Beginnen Sie bei dem Schritt über Ihrer aktuellen
Version und arbeiten Sie sich nach unten durch – oder, wenn Sie von 0.12 kommen,
beginnen Sie unten und arbeiten Sie sich nach oben vor.

| Ihre Version | Lesen | Was sich für Sie ändert |
|---|---|---|
| **0.27 – 0.28** | [0.27 → 0.29](/docs/upgrading/0-27-to-0-29/) | Alles, was der Admin an Ihren Code übergibt, ist die Zeile des Servers mit der dazugehörigen ID: `context.data` und `browserCallbacks` des Browsers übergeben ISO-Strings und Fremdschlüssel, wo sie zuvor `Date`s und Relation-Objekte übergeben haben, was kein Compiler erkennt; die `Entity`-Daten-Hooks werden intern; und Callbacks, Panels, das Seitenpanel und die Auswahl akzeptieren `row` und `id` anstelle von `entity` und `entityId`. 0.28 enthält keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Ein Cron-Zeitplan, der beide Tagesfelder einschränkt, wird bei jedem der beiden ausgeführt und läuft daher häufiger; ein Zeitplan mit einer fehlerhaften Zahl wird abgelehnt, sodass dieser Job nicht mehr ausgeführt wird. Ein Schlüssel, dessen `isId`-Strategie von seinem Typ nicht erfüllt werden kann, stoppt den Boot-Vorgang. Auf Rebase Cloud schlägt ein Deploy oder Preview fehl, wenn eine Funktions- oder Cron-Datei nicht geladen werden kann. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Ein Schreibvorgang, der eine Multi-Hop-`via`-Relation benennt, ein Rollenname, der nicht genau eine Rolle ist, ein Local-Storage-Page-Token von vor dem Upgrade und ein nicht funktionsfähiger Functions-Upstream werden abgelehnt. OAuth-Sign-in wickelt ein nicht verifiziertes Konto ab, anstatt `local-account-unverified` zurückzugeben, der MCP-Server sendet `REBASE_TOKEN` nicht mehr an die App und generierte Typen verwerfen den Schlüssel eines `excludeFromApi`-belongsTo. Auf Rebase Cloud werden `rebase cloud webhooks` und `--scale-to-zero true` eingestellt, und ältere Token müssen möglicherweise neu erstellt werden. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` bei einer REST-Liste wird zum Schalter für die Anzahl hinter `meta.total`, sodass ein Filter auf eine Spalte namens `count` in `?where=` verschoben werden muss; `list_collections` des Remote-MCP sendet seine Auflistung nur im Textblock ohne `structuredContent`; und `@rebasepro/app` exportiert nicht mehr die spanische Übersetzungstabelle `es`. Ein einfaches `OPTIONS` an eine Route ohne Handler, kollidierende Tabellennamen beim Booten, ein Upsert auf die users-Collection, `page` mit `offset`, ein leerer String bei einem Pflichtfeld und das Passwort eines Administrators, das die Passwortrichtlinie nicht erfüllt, werden abgelehnt. Sitzungen dauern standardmäßig 30 Tage Inaktivität, `client.cron` ruft `/api/admin/cron` auf, Offline-Lesezugriffe, die nicht vollständig beantwortet werden können, schlagen mit `OFFLINE` fehl, und einige interne Exporte sowie ungenutzte Props wurden entfernt. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | Das von `db push` und `db generate` gerenderte SQL wird von `drizzle/` in das nicht-gecommittete `.rebase/sql/` verschoben, das Flag `--generate` von `rebase dev` entfällt, da `dev` die SDK-Typen immer neu generiert, und eine Live-Schema-Bearbeitung committet kein SQL. Berechtigungen (Permissions) werden zu Scopes: Admin-Oberflächen fragen nach einem Scope statt nach der Admin-Rolle, API-Schlüssel enthalten Scopes statt einer Berechtigungsliste und eines `admin`-Flags, und `schema-admin` ist kein Administrator mehr. Ein relatives `--collections` wird von dort gelesen, wo der Befehl ausgeführt wird, ein Upsert in eine gelöschte Zeile (trashed row) und ein Update, das einen Schlüssel ändert, werden abgelehnt, der Remote-MCP-Endpunkt übernimmt die Argumente des SDKs, und offene Realtime-Sockets, Links zur E-Mail-Verifizierung, `signUp` und MFA-Wiederherstellungscodes ändern die Art und Weise, wie sie eine Sitzung behandeln. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Ein API-Schlüssel auf einem verschachtelten Pfad benötigt `read` auf seinen übergeordneten Elementen, unlesbare numerische Variablen und Sitzungslebensdauern verweigern den Boot-Vorgang, ein benutzerdefiniertes Auth-Repository benötigt `unlinkUserIdentity` und Gast-Upgrades verwenden das `register`-Captcha. 0.22 enthält keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` kompiliert in einem Collection-Callback nicht mehr – fragen Sie über `context.data` ab – und `selectedEntities` weicht einer Auswahl, die Zeilen repräsentieren kann, die noch niemand geladen hat. 0.19 und 0.20 enthalten keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Elf Breaking Changes, die meisten davon Compilerfehler statt stiller Verhaltensänderungen. `rebase.data` verschwindet zur Laufzeit, Peer-Bereiche verengen sich auf Carets (`^`), und die Node-Mindestversion wird auf 22.22.0 angehoben. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Die Admin-Pakete werden umbenannt, Ressourcen werden deklariert statt konfiguriert, und ein davor erstelltes Bundle bootet nicht auf einer aktuellen Laufzeitumgebung. 0.15 und 0.16 enthalten keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Jeder Wire-Schlüssel ist camelCase, und anonymer Sign-in ist Opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Der größte Schritt und der einzige, der ändert, **wer Ihre Daten lesen darf**. Er entfernt das `auth`-Schema, benennt Pakete um, ändert die Bedeutung von `id`, entfernt CJS, migriert das Admin-Panel auf react-router 8 und behebt drei Wege, über die ungewollter Zugriff gewährt werden konnte. |

Die Abschnitte jeder Seite sind in der Reihenfolge angeordnet, in der Sie die Änderungen vornehmen müssen, und jeder Abschnitt nennt das Symptom, das Sie sonst von der falschen Seite debuggen würden.

Anschließend, welchen Schritt auch immer Sie gemacht haben:

- [Die Upgrade-Checkliste](#upgrade-checkliste) unten – die Grep-Suchmuster und Befehle, die danach ausgeführt werden sollten, in einem Block zusammengefasst.

## Upgrade-Checkliste

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` sollte in Ihre CI eingebunden werden: Der Befehl beendet sich mit einem Exit-Code ungleich null, wenn eine Richtlinie noch die permissive Tautologie enthält oder durch einen früheren Push abgelöst wurde. Die `pg_policies`-Abfragen davor und danach sind die Minute dennoch wert – sie zeigen Ihnen die Ausdrücke selbst, was die einzige Möglichkeit ist, eine Fail-Open-Richtlinie zu erkennen, die in einer Schreibweise verfasst wurde, die der Detektor nicht abgleicht. Weder die Pakete noch das Typsystem weisen Sie darauf hin: Die Änderung befindet sich in der Datenbank, und `db push` ist das Einzige, was sie dorthin bringt.

## Auf eine frühere Version zurückgehen

Bevor Sie auf eine Version zurückgehen, die älter ist als die, mit der die Admin-Request-Begleitrichtlinien kamen (siehe [Changelog](/docs/changelog/)), machen Sie sie wirkungslos. Eine ältere Runtime entfernt nie eine Begleitrichtlinie, sodass eine Regel, die Sie nach dem Zurückgehen ändern, weiterhin jedem Admin jede Zeile freigäbe. Führen Sie `REVOKE rebase_admin_request FROM rebase_user_admin;` einmal pro Admin-Request-Rolle aus, oder entfernen Sie die `_ar_`-Richtlinien. [Admin-Lesezugriffe nutzen die Indizes des Owners](/docs/deployment/existing-database/#admin-reads-use-the-owners-indexes) erklärt sie.
