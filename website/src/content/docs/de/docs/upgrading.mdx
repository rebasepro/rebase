# Upgrade einer bestehenden App

Elf Schritte, die neuesten zuerst. Beginnen Sie bei dem Schritt über Ihrer aktuellen Version und arbeiten Sie
sich nach unten durch – oder beginnen Sie unten und arbeiten Sie sich nach oben, wenn Sie von 0.12 kommen.

| Ihre Version | Lesen | Was sich für Sie ändert |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Noch nicht veröffentlicht. Alles, was der Admin an Ihren Code übergibt, ist die Server-Zeile samt ihrer ID daneben: Die `context.data` und `browserCallbacks` des Browsers übergeben ISO-Strings und Fremdschlüssel dort, wo sie zuvor `Date`-Werte und Beziehungsobjekte übergeben haben, was kein Compiler abfängt; die `Entity`-Daten-Hooks werden intern; und Callbacks, Panels, das Seitenpanel sowie die Auswahl akzeptieren `row` und `id` anstelle von `entity` und `entityId`. 0.28 enthält keine Breaking Changes, daher ist dies ein einzelner Schritt ab 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Ein Cron-Zeitplan, der beide Tagesfelder einschränkt, wird bei jedem der beiden ausgeführt, läuft also häufiger, und ein Zeitplan mit einer fehlerhaften Zahl wird abgelehnt, sodass dieser Job nicht mehr ausgeführt wird. Ein Schlüssel, dessen Typ die `isId`-Strategie nicht erfüllen kann, verhindert den Boot-Vorgang. Auf Rebase Cloud schlägt ein Deploy oder eine Preview fehl, wenn eine Funktions- oder Cron-Datei nicht geladen werden kann. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Ein Schreibvorgang, der eine Multi-Hop-`via`-Relation benennt, ein Rollenname, der nicht genau eine Rolle ist, ein Local-Storage-Page-Token von vor dem Upgrade und ein nicht funktionsfähiger Functions-Upstream werden abgelehnt. Die OAuth-Anmeldung bestätigt ein nicht verifiziertes Konto, anstatt `local-account-unverified` zurückzugeben, der MCP-Server sendet kein `REBASE_TOKEN` mehr an die App und generierte Typen entfernen den Schlüssel eines `excludeFromApi`-belongsTo. Auf Rebase Cloud wurden `rebase cloud webhooks` und `--scale-to-zero true` eingestellt, und ältere Token müssen möglicherweise neu erstellt werden. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` bei einer REST-Liste wird zum Schalter für die Anzahl hinter `meta.total`, sodass ein Filter auf eine Spalte namens `count` in `?where=` gehört; `list_collections` des Remote-MCPs sendet seine Auflistung nur im Textblock ohne `structuredContent`; und `@rebasepro/app` exportiert die spanische Übersetzungstabelle `es` nicht mehr. Ein einfaches `OPTIONS` auf eine Route ohne Handler, kollidierende Tabellennamen beim Booten, ein Upsert auf die Users-Collection, `page` zusammen mit `offset`, ein leerer String in einem Pflichtfeld und das Passwort eines Administrators, das gegen die Passwortrichtlinie verstößt, werden abgewiesen. Sitzungen dauern standardmäßig 30 Tage Inaktivität, `client.cron` ruft `/api/admin/cron` auf, Offline-Lesevorgänge, die nicht vollständig beantwortet werden können, schlagen mit `OFFLINE` fehl, und einige interne Exporte sowie ungenutzte Props wurden entfernt. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | Das SQL-Rendering von `db push` und `db generate` wandert von `drizzle/` in das nicht versionierte `.rebase/sql/`, das `--generate`-Flag von `rebase dev` entfällt, da `dev` die SDK-Typen immer neu generiert, und eine Live-Schema-Bearbeitung committet kein SQL. Berechtigungen (Permissions) werden zu Scopes: Admin-Oberflächen fragen nach einem Scope statt nach der Admin-Rolle, API-Keys enthalten Scopes anstelle einer Berechtigungsliste und eines `admin`-Flags, und `schema-admin` ist kein Administrator mehr. Ein relatives `--collections` wird von dem Verzeichnis aus gelesen, in dem der Befehl ausgeführt wird, ein Upsert in eine gelöschte (trashed) Zeile und ein Update, das einen Schlüssel ändert, werden abgewiesen, der Remote-MCP-Endpunkt übernimmt die Argumente des SDKs, und offene Realtime-Sockets, E-Mail-Verifizierungslinks, `signUp` und MFA-Wiederherstellungscodes ändern ihren Umgang mit Sitzungen. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Ein API-Key auf einem geschachtelten Pfad benötigt `read`-Rechte auf den übergeordneten Elementen, unlesbare numerische Variablen und Sitzungslaufzeiten verweigern den Boot-Vorgang, ein benutzerdefiniertes Auth-Repository erfordert `unlinkUserIdentity`, und Gast-Upgrades verwenden das `register`-Captcha. 0.22 enthält keine Breaking Changes, daher ist dies ein einzelner Schritt ab 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` kompiliert in einem Collection-Callback nicht mehr – fragen Sie über `context.data` ab – und `selectedEntities` weicht einer Selektion, die auch für Zeilen stehen kann, die niemand geladen hat. 0.19 und 0.20 enthalten keine Breaking Changes, daher ist dies ein einzelner Schritt ab 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Elf Breaking Changes, die meisten davon Compiler-Fehler statt stillschweigender Verhaltensänderungen. `rebase.data` entfällt zur Laufzeit, Peer-Bereiche verengen sich auf Caret-Präfixe und die Node-Mindestversion wird auf 22.22.0 angehoben. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Die Admin-Pakete werden umbenannt, Ressourcen werden deklariert statt konfiguriert und ein zuvor erstelltes Bundle lässt sich auf einer aktuellen Laufzeitumgebung nicht booten. 0.15 und 0.16 enthalten keine Breaking Changes, daher ist dies ein einzelner Schritt ab 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Jeder Wire-Key ist in camelCase und die anonyme Anmeldung erfordert ein Opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Der größte Schritt und der einzige, der ändert, **wer Ihre Daten lesen kann**. Er entfernt das `auth`-Schema, benennt Pakete um, ändert die Bedeutung von `id`, stellt CJS ein, migriert das Admin-Panel auf react-router 8 und behebt drei Fälle, in denen Zugriff gewährt werden konnte, den Sie nicht angefordert hatten. |

Die Abschnitte auf jeder Seite sind in der Reihenfolge angeordnet, in der Sie die Änderungen vornehmen müssen, und jeder Abschnitt nennt
das Symptom, das Sie andernfalls an falscher Stelle debuggen würden.

Anschließend, unabhängig davon, welchen Schritt Sie durchgeführt haben:

- [Die Upgrade-Checkliste](#upgrade-checklist) unten – die Grep-Suchmuster und Befehle, die danach
  ausgeführt werden sollten, in einem Block zusammengefasst.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` ist der Befehl, der in die CI eingebunden werden sollte: Er bricht mit einem Exit-Code ungleich null ab, wenn eine Richtlinie noch die freizügige Tautologie enthält oder wenn eine Richtlinie durch einen früheren Push ersetzt wurde. Die `pg_policies`-Abfragen davor und danach sind die Minute allemal wert – sie zeigen Ihnen die Ausdrücke selbst, was die einzige Möglichkeit ist, eine Fail-Open-Richtlinie zu erkennen, die in einer Schreibweise verfasst ist, die der Detektor nicht erkennt. Weder die Pakete noch das Typsystem weisen darauf hin: Die Änderung existiert in der Datenbank, und `db push` ist das Einzige, was sie dorthin bringt.
