# Upgrade einer bestehenden App

Elf Schritte, der neueste zuerst. Beginnen Sie bei dem Schritt direkt über Ihrer aktuellen Version und arbeiten
Sie sich nach unten durch – oder, wenn Sie von 0.12 kommen, fangen Sie ganz unten an und arbeiten sich nach oben.

| Ihre Version | Anleitung | Auswirkungen |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Noch nicht veröffentlicht. Alles, was der Admin an Ihren Code übergibt, ist die Zeile des Servers mit ihrer ID daneben: `context.data` und `browserCallbacks` des Browsers übergeben ISO-Strings und Fremdschlüssel, wo sie zuvor `Date`s und Relation-Objekte übergeben haben, was kein Compiler erkennt; die `Entity`-Daten-Hooks werden intern; und Callbacks, Panels, das Side-Panel sowie die Selektion akzeptieren `row` und `id` anstelle von `entity` und `entityId`. 0.28 deklariert keine Breaking Changes, daher ist dies ein einziger Schritt von 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Ein Cron-Zeitplan, der beide Tagesfelder einschränkt, wird bei jedem der beiden ausgeführt, läuft also häufiger, und ein Zeitplan mit einer fehlerhaften Zahl wird abgelehnt, sodass dieser Job gestoppt wird. Ein Schlüssel, dessen `isId`-Strategie von seinem Typ nicht erfüllt werden kann, verhindert das Booten. Auf Rebase Cloud schlägt ein Deploy oder eine Vorschau fehl, wenn eine Funktions- oder Cron-Datei nicht geladen werden kann. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Ein Schreibvorgang, der eine Multi-Hop-`via`-Relation benennt, ein Rollenname, der nicht genau einer Rolle entspricht, ein Local-Storage-Page-Token von vor dem Upgrade und ein nicht funktionsfähiger Functions-Upstream werden abgewiesen. Der OAuth-Login gleicht ein nicht verifiziertes Konto ab, anstatt mit `local-account-unverified` zu antworten, der MCP-Server sendet `REBASE_TOKEN` nicht mehr an die App, und generierte Typen entfernen den Schlüssel eines `excludeFromApi`-`belongsTo`. Auf Rebase Cloud werden `rebase cloud webhooks` und `--scale-to-zero true` eingestellt, und ältere Tokens müssen möglicherweise neu erstellt werden. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` bei einer REST-Liste wird zum Schalter für die Anzahl hinter `meta.total`, sodass ein Filter auf eine Spalte namens `count` in `?where=` platziert werden muss; `list_collections` des Remote-MCPs sendet seine Auflistung nur im Textblock, ohne `structuredContent`; und `@rebasepro/app` exportiert die spanische Übersetzungstabelle `es` nicht mehr. Ein einfacher `OPTIONS`-Request an eine Route ohne Handler, kollidierende Tabellennamen beim Booten, ein Upsert auf die `users`-Collection, `page` mit `offset`, ein leerer String bei einem Pflichtfeld und das Passwort eines Administrators, das die Passwortrichtlinie verletzt, werden abgelehnt. Sitzungen bleiben standardmäßig 30 Tage lang bei Inaktivität gültig, `client.cron` ruft `/api/admin/cron` auf, Offline-Lesezugriffe, die nicht vollständig beantwortet werden können, schlagen mit `OFFLINE` fehl, und einige interne Exporte sowie ungenutzte Props wurden entfernt. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | Das von `db push` und `db generate` erzeugte SQL wandert aus `drizzle/` in das nicht versionierte `.rebase/sql/`, das Flag `--generate` von `rebase dev` entfällt, da `dev` die SDK-Typen immer neu generiert, und eine Live-Schemaänderung committet kein SQL. Berechtigungen (Permissions) werden zu Scopes: Admin-Oberflächen fragen nach einem Scope anstelle der Admin-Rolle, API-Schlüssel enthalten Scopes anstelle einer Berechtigungsliste und eines `admin`-Flags, und `schema-admin` ist kein Administrator mehr. Ein relativer Pfad für `--collections` wird relativ zum Ausführungsort des Befehls gelesen, ein Upsert in eine im Papierkorb befindliche Zeile (`trashed row`) und ein Update, das einen Primärschlüssel ändert, werden abgelehnt, der Remote-MCP-Endpunkt übernimmt die Argumente des SDKs, und offene Realtime-Sockets, E-Mail-Verifizierungslinks, `signUp` sowie MFA-Wiederherstellungscodes ändern ihren Umgang mit Sitzungen. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Ein API-Schlüssel für einen verschachtelten Pfad benötigt `read` auf seinen übergeordneten Pfaden, unlesbare numerische Variablen und Sitzungslebensdauern verweigern das Booten, ein benutzerdefiniertes Auth-Repository benötigt `unlinkUserIdentity`, und Gast-Upgrades verwenden das `register`-Captcha. 0.22 deklariert keine Breaking Changes, daher ist dies ein einziger Schritt von 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` kompiliert in einem Collection-Callback nicht mehr – führen Sie Abfragen über `context.data` durch – und `selectedEntities` weicht einer Selektion, die auch Zeilen repräsentieren kann, die noch niemand geladen hat. 0.19 und 0.20 deklarieren keine Breaking Changes, daher ist dies ein einziger Schritt von 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Elf Breaking Changes, die meisten davon Compiler-Fehler statt unbemerkter Verhaltensänderungen. `rebase.data` verschwindet zur Laufzeit, Peer-Bereiche verengen sich auf Caret-Präfixe (`^`) und die minimale Node-Version steigt auf 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Die Admin-Pakete werden umbenannt, Ressourcen werden deklariert statt konfiguriert, und ein zuvor erstelltes Bundle bootet auf einer aktuellen Laufzeitumgebung nicht mehr. 0.15 und 0.16 enthalten keine Breaking Changes, daher ist dies ein einziger Schritt von 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Jeder Wire-Key verwendet camelCase und die anonyme Anmeldung ist nun Opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Der größte Schritt und der einzige, der ändert, **wer Ihre Daten lesen kann**. Er entfernt das `auth`-Schema, benennt Pakete um, ändert die Bedeutung von `id`, stellt die Unterstützung für CJS ein, migriert das Admin-Panel auf react-router 8 und behebt drei Möglichkeiten, über die unbeabsichtigt Zugriff gewährt werden konnte. |

Die Abschnitte jeder Seite sind in der Reihenfolge aufgebaut, in der Sie die Änderungen durchführen müssen, und jeder
nennt das Symptom, das Sie sonst von der falschen Seite aus untersuchen würden.

Anschließend, welchen Schritt auch immer Sie durchgeführt haben:

- [Die Upgrade-Checkliste](#upgrade-checkliste) unten — die grep-Befehle und Kommandos,
  die sich danach lohnen, zusammengefasst in einem Block.

## Upgrade-Checkliste

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` ist der Befehl, der in die CI eingebunden werden sollte: Er schlägt
fehl (Exit-Code ungleich null), wenn eine Policy noch immer die freizügige Tautologie enthält oder
wenn eine frühere Aktualisierung eine Policy abgelöst hat. Die Leseabfragen von `pg_policies`
davor und danach sind die investierte Minute allemal wert — sie zeigen Ihnen die eigentlichen
Ausdrücke, was die einzige Möglichkeit ist, eine Fail-Open-Policy zu erkennen, deren Formulierung
vom Detector nicht erfasst wird. Weder die Pakete noch das Typsystem werden Sie darauf hinweisen:
Die Änderung liegt in der Datenbank, und `db push` ist das Einzige, was sie dorthin bringt.
