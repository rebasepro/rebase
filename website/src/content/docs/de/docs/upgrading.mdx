# Upgrade einer bestehenden App

Dreizehn Schritte, die neuesten zuerst. Beginnen Sie bei der Version direkt über Ihrer aktuellen und arbeiten Sie sich nach unten vor – oder beginnen Sie ganz unten und arbeiten Sie sich nach oben, wenn Sie von 0.12 kommen.

| Sie nutzen | Lesen | Was sich ändert |
|---|---|---|
| **0.30** | [0.30 → 0.31](/docs/upgrading/0-30-to-0-31/) | Tabellen in `backend/schema` (`defineTable`) ersetzen `config/collections`, und es gibt kein Config-Paket mehr: Führen Sie `rebase migrate collections-to-tables` aus, wodurch das Projekt verschoben und nachgewiesen wird, dass das generierte SQL unverändert bleibt. Das Admin-Panel rendert die vom Server bereitgestellten Tabellen, angepasst über `frontend/src/cms`; das SDK verwendet `data.table(slug)` und `tables: tablesDictionary`; Bundles nutzen Format 3, daher vor dem Deployment neu bauen; MongoDB wird eingestellt. |
| **0.29** | [0.29 → 0.30](/docs/upgrading/0-29-to-0-30/) | Ein mit `initializeRebaseBackend` gestartetes Backend speichert das Refresh-Token in einem Cookie, sofern nicht `cookieAuth: false` gesetzt ist. Ein Aufrufer, der es ohne `x-rebase-auth-flow: json` aus dem Body liest, erhält daher `""`. |
| **0.27 – 0.28** | [0.27 → 0.29](/docs/upgrading/0-27-to-0-29/) | Alles, was der Admin an Ihren Code übergibt, ist die Zeile des Servers mit ihrer ID daneben: Die `context.data` und `browserCallbacks` des Browsers übergeben ISO-Strings und Fremdschlüssel, wo sie zuvor `Date`-Werte und Beziehungsobjekte übergeben haben, was kein Compiler erkennt; die `Entity`-Daten-Hooks werden intern; und Callbacks, Panels, das Seitenpanel sowie die Auswahl akzeptieren `row` und `id` statt `entity` und `entityId`. 0.28 deklariert keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Ein Cron-Schedule, der beide Tagesfelder einschränkt, wird bei jedem der beiden ausgeführt, läuft also häufiger, und ein Schedule mit einer fehlerhaften Zahl wird abgelehnt, sodass dieser Job gestoppt wird. Ein Schlüssel, dessen `isId`-Strategie von seinem Typ nicht erfüllt werden kann, stoppt den Boot-Vorgang. Auf Rebase Cloud schlägt ein Deploy oder Preview fehl, wenn eine Funktions- oder Cron-Datei nicht geladen werden kann. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Ein Schreibvorgang, der eine Multi-Hop-`via`-Relation benennt, ein Rollenname, der nicht genau eine Rolle ist, ein Local-Storage-Page-Token von vor dem Upgrade und ein nicht funktionsfähiger Functions-Upstream werden abgelehnt. Die OAuth-Anmeldung schließt ein nicht verifiziertes Konto ab, anstatt mit `local-account-unverified` zu antworten, der MCP-Server sendet `REBASE_TOKEN` nicht mehr an die App, und generierte Typen entfernen den Schlüssel eines `excludeFromApi`-belongsTo. Auf Rebase Cloud werden `rebase cloud webhooks` und `--scale-to-zero true` eingestellt, und ältere Tokens müssen möglicherweise neu erstellt werden. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` bei einer REST-Liste steuert nun die Zählung hinter `meta.total`, sodass ein Filter auf eine Spalte namens `count` innerhalb von `?where=` platziert werden muss; `list_collections` des Remote-MCPs sendet seine Auflistung nur im Textblock, ohne `structuredContent`; und `@rebasepro/app` exportiert die spanische Übersetzungstabelle `es` nicht mehr. Ein einfaches `OPTIONS` an eine Route ohne Handler, kollidierende Tabellennamen beim Booten, ein Upsert auf der Users-Collection, `page` mit `offset`, ein leerer String in einem Pflichtfeld und das Passwort eines Administrators, das die Passwortrichtlinie verletzt, werden abgewiesen. Sessions dauern standardmäßig 30 Tage Inaktivität, `client.cron` ruft `/api/admin/cron` auf, Offline-Lesevorgänge, die nicht vollständig beantwortet werden können, schlagen mit `OFFLINE` fehl, und einige interne Exporte sowie ungenutzte Props wurden entfernt. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | Die von `db push` und `db generate` erzeugten SQL-Dateien wandern aus `drizzle/` in das nicht versionierte `.rebase/sql/`, das Flag `--generate` von `rebase dev` entfällt, da `dev` die SDK-Typen immer neu generiert, und eine Live-Schema-Bearbeitung committet kein SQL. Berechtigungen werden zu Scopes: Admin-Oberflächen fragen nach einem Scope statt der Admin-Rolle, API-Keys enthalten Scopes anstelle einer Berechtigungsliste und eines `admin`-Flags, und `schema-admin` ist kein Administrator mehr. Ein relativer Pfad `--collections` wird relativ zum Ausführungsort des Befehls gelesen, ein Upsert in eine gelöschte Zeile und ein Update, das einen Schlüssel ändert, werden abgelehnt, der Remote-MCP-Endpunkt akzeptiert die SDK-Argumente, und offene Realtime-Sockets, E-Mail-Verifizierungslinks, `signUp` sowie MFA-Wiederherstellungscodes ändern ihren Umgang mit Sessions. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Ein API-Key auf einem verschachtelten Pfad benötigt `read` auf übergeordneten Elementen, unlesbare numerische Variablen und Session-Lebensdauern verhindern den Boot-Vorgang, ein benutzerdefiniertes Auth-Repository benötigt `unlinkUserIdentity`, und Gast-Upgrades verwenden das `register`-Captcha. 0.22 deklariert keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` kompiliert in einem Collection-Callback nicht mehr – fragen Sie über `context.data` ab – und `selectedEntities` weicht einer Selektion, die Zeilen repräsentieren kann, die niemand geladen hat. 0.19 und 0.20 deklarieren keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Elf Breaking Changes, die meisten davon Compiler-Fehler statt stiller Verhaltensänderungen. `rebase.data` entfällt zur Laufzeit, Peer-Ranges werden auf Carets beschränkt, und die Mindestversion für Node steigt auf 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Die Admin-Pakete werden umbenannt, Ressourcen werden deklariert statt konfiguriert, und ein zuvor erstelltes Bundle lässt sich auf einer aktuellen Laufzeitumgebung nicht mehr starten. 0.15 und 0.16 enthalten keine Breaking Changes, daher ist dies ein einzelner Schritt von 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Jeder Wire-Key ist in camelCase, und anonyme Anmeldungen sind Opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Der größte Schritt und der einzige, der ändert, **wer Ihre Daten lesen kann**. Er entfernt das `auth`-Schema, benennt Pakete um, ändert die Bedeutung von `id`, entfernt CJS, migriert das Admin-Panel auf react-router 8 und behebt drei Fälle, in denen Zugriff gewährt werden konnte, den Sie nicht angefordert hatten. |

Die Abschnitte jeder Seite sind in der Reihenfolge angeordnet, in der Sie vorgehen müssen, und jeder nennt das Symptom, das Sie andernfalls an der falschen Stelle debuggen würden.

Unabhängig davon, welchen Schritt Sie durchgeführt haben:

- [Die Upgrade-Checkliste](#upgrade-checklist) unten – die Greps und Befehle, die es sich lohnt, danach auszuführen, in einem Block zusammengefasst.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result

--- 0.30 → 0.31 ---
[ ] bump every @rebasepro package to 0.31 first, then pnpm install
[ ] rebase migrate collections-to-tables on a clean tree; read the manual steps
[ ] move config/index.ts `callbacks` to backend/hooks.ts by hand, if you had them
[ ] rebase generate-sdk; rebase db push --dry-run plans no change
[ ] run the git rm line the codemod printed (your own config/ modules may stay)
[ ] send a to-one relation as its key, not { id } — that is a 400 now
[ ] call /api/docs signed in, or set REBASE_ENABLE_SWAGGER=true to publish it
[ ] rename the MCP tools in prompts and allow-lists (list_tables, query_table, …)
[ ] rebuild the bundle and deploy — a format-2 bundle is refused
```

`rebase doctor --policies` sollte in Ihre CI eingebunden werden: Der Befehl beendet sich mit einem Exit-Code ungleich null, wenn eine Policy noch die freizügige Tautologie enthält oder von einem früheren Push abgelöst wurde. Die `pg_policies`-Abfragen davor und danach sind die Minute dennoch wert – sie zeigen Ihnen die Ausdrücke selbst, was die einzige Möglichkeit ist, eine Fail-Open-Policy zu erkennen, die in einer Schreibweise verfasst ist, die der Detektor nicht erkennt. Weder die Pakete noch das Typsystem weisen darauf hin: Die Änderung existiert in der Datenbank, und `db push` ist das Einzige, was sie dorthin bringt.

## Rollback eines Releases

Bevor Sie auf ein Release zurückrollen, das älter ist als dasjenige, mit dem die Admin-Request-Companions eingeführt wurden (siehe [Changelog](/docs/changelog/)), müssen Sie diese deaktivieren. Eine ältere Laufzeitumgebung entfernt Companions niemals, sodass eine Regel, die Sie nach dem Rollback ändern, weiterhin jedem Admin Zugriff auf jede Zeile gewähren würde. Führen Sie `REVOKE rebase_admin_request FROM rebase_user_admin;` einmal pro Admin-Request-Rolle aus oder löschen Sie die `_ar_`-Policies. [Admin reads use the owner's indexes](/docs/deployment/existing-database/#admin-reads-use-the-owners-indexes) erklärt diese Zusammenhänge.
