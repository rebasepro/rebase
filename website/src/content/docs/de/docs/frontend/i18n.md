## Übersicht

Jede vom Admin-Panel gerenderte Zeichenfolge stammt von einem Schlüssel (Key). Sieben Locales werden
standardmäßig mitgeliefert — Englisch, Spanisch, Deutsch, Französisch, Italienisch, Portugiesisch und Hindi — und ein
Projekt kann jeden Schlüssel überschreiben, eine eigene Sprache hinzufügen oder eigene
Komponenten anhand derselben Tabelle übersetzen.

Drei Dinge erledigen die Arbeit:

| | |
|---|---|
| `<Rebase locale>` | mit welcher Sprache gestartet werden soll |
| `<Rebase translations>` | was jeder Schlüssel pro Locale besagt |
| `useTranslation()` | Auslesen eines Schlüssels aus Ihrer eigenen Komponente |

## Sprache auswählen

```tsx
<Rebase client={client} authController={authController} locale="es">
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

`locale` ist die *anfängliche* Sprache. Wenn ein Benutzer eine Sprache im
Sprachmenü auswählt, wird diese Auswahl im Browser gespeichert und hat beim
nächsten Besuch Vorrang vor der Prop — eine Änderung von `locale` im Code überschreibt
nicht die Einstellung eines Benutzers. Alles, wofür Rebase keine Zeichenfolge hat,
fällt auf Englisch zurück, anstatt einen Schlüssel zu rendern.

## Zeichenfolgen anpassen

`translations` ist nach Locale und dann nach Schlüssel strukturiert. Partiell: Geben Sie die Handvoll an,
die Sie ändern möchten, und alles andere bleibt unverändert.

```tsx
<Rebase
    client={client}
    authController={authController}
    translations={{
        en: { save: "Publish", delete_confirmation_title: "Unpublish?" },
        es: { save: "Publicar", delete_confirmation_title: "¿Despublicar?" }
    }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

Derselbe Aufbau fügt eine Sprache hinzu, die Rebase nicht von Haus aus mitbringt. Übergeben Sie ihr einen vollständigen Satz an Schlüsseln
und setzen Sie `locale` darauf:

```tsx
<Rebase
    client={client}
    authController={authController}
    locale="nl"
    translations={{ nl: { save: "Opslaan", cancel: "Annuleren" } }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

Schlüssel, die Sie weglassen, fallen auf Englisch zurück, sodass ein unvollständiger Satz eine funktionierende
Übersetzung darstellt und nicht zu Fehlern führt.

### Wo sich die Schlüssel befinden

Die gesamte Tabelle ist `RebaseTranslations` — ein einziges Interface mit jedem Schlüssel darin, sodass
Ihr Editor sie automatisch vervollständigt und ein Tippfehler ein Typfehler ist. Die englischen Werte befinden sich
in `packages/app/src/locales/en.ts`, welches die Referenz dafür ist, was jeder Schlüssel
tatsächlich besagt.

Die Namen orientieren sich an dem Bereich, zu dem sie gehören: `save`, `cancel`, `delete_confirmation_title`
für das Panel, `studio_*` für die Entwickler-Tools (`studio_tool_sql`,
`studio_group_database`, `studio_backups_denied_title`).

## Eigene Komponenten übersetzen

`useTranslation()` bietet Ihnen dieselbe Tabelle, die auch Ihre benutzerdefinierten Views, Felder und
Aktionen auslesen können:

```tsx
import { useTranslation } from "@rebasepro/app";

function PublishButton() {
    const { t } = useTranslation();
    return <Button>{t("save")}</Button>;
}
```

Interpolation verwendet dieselbe `{{name}}`-Syntax wie die integrierten Zeichenfolgen:

```tsx
t("add_to_field", { fieldName: "Tags" });
```

Ihre eigenen Schlüssel werden genau wie alle anderen über `translations` übergeben — ein Schlüssel, den Rebase nicht
deklariert, wird dennoch aufgelöst, sodass Sie die Zeichenfolgen Ihrer Komponente in dieselbe
Tabelle einfügen können, anstatt einen zweiten i18n-Stack daneben zu betreiben.

`t` gibt außerdem den Schlüssel selbst zurück, wenn keine Übereinstimmung gefunden wird, was die ehrlichste
Antwort ist und einen fehlenden Schlüssel in der Benutzeroberfläche sichtbar macht, anstatt eine leere Stelle anzuzeigen.

## Eigene Texte des UI-Kits

Einige Zeichenfolgen gehören zu `@rebasepro/ui` selbst und nicht zum Admin-Panel: "No entries found",
"All 12 entries loaded" und "Error loading data" der Listen- und Kartenansichten, der Fehlertitel der Tabelle, die Bezeichnungen der Suchleiste und relative
Datumsangaben wie "5m ago". Innerhalb einer Rebase-App stammen sie aus denselben
Übersetzungen (`no_entries_found`, `all_entries_loaded`,
`error_loading_data_message`, `search`, `clear_search`, `relative_*`) und folgen
der Sprache wie jede andere Zeichenfolge.

Wenn Sie das Kit eigenständig verwenden, spricht es Englisch, es sei denn, Sie umschließen es mit einem
`UiLabelsProvider`. Jedes Label, das Sie weglassen, behält seinen englischen Standardwert:

```tsx
import { UiLabelsProvider } from "@rebasepro/ui";

<UiLabelsProvider labels={{
    noEntriesFound: "Nessuna voce trovata",
    allEntriesLoaded: (count) => `Tutte le ${count} voci caricate`,
    relativeTime: { minutesAgo: (count) => `${count} min fa` }
}}>
    <ListView data={rows} renderRow={renderRow}/>
</UiLabelsProvider>
```

`useUiLabels()` liest die aktiven Labels aus, und `formatRelativeTime` aus
`@rebasepro/utils` akzeptiert `labels: useUiLabels().relativeTime`, um ein Datum auf
dieselbe Weise auszugeben.

## Gruppennamen sind keine Labels

Die `group` einer `AppView` ist ein Bezeichner: Die Drawer-Navigation klappt danach zusammen, die Studio-Startseite
sortiert danach und `navigationGroupMappings` weist ihr Icons zu.
Sie dort zu übersetzen, wo sie deklariert wird, bricht alle drei Funktionen in jeder Sprache außer
derjenigen, in die Sie übersetzt haben.

Deklarieren Sie die Gruppe auf Englisch und überlassen Sie dem Header die Übersetzung — die eigenen
Gruppen von Rebase haben `studio_group_*`-Schlüssel und werden nach Namen nachgeschlagen; eine eigene
Gruppe wird genau so gerendert, wie sie geschrieben wurde.

```tsx
// Richtig: Der Name ist stabil, die Überschrift wird für die integrierten Gruppen lokalisiert.
{ slug: "queues", name: "Queues", group: "Compute", view: <QueuesView/> }
```
