## O que é o Rebase?

O Rebase é o **backend de código aberto para PostgreSQL**, com um **painel de administração** para a sua equipe, desenvolvido com React e TypeScript. Ele oferece tudo o que você precisa para construir uma aplicação pronta para produção no **PostgreSQL**:

- **Schema como Código** — Declare suas tabelas do Postgres em TypeScript, cada uma com uma postura de segurança a nível de linha (row-level security) obrigatória. O Rebase gera as tabelas e suas políticas, endpoints de API REST, um SDK tipado e uma interface CRUD completa a partir dessa única fonte da verdade.
- **Painel de Administração Instantâneo** — Um painel elegante e rápido baseado em React, com tabelas em estilo planilha, listas, formulários, quadros Kanban, edição inline e sincronização em tempo real.
- **Backend Integrado** — Autenticação (senhas, magic links, códigos de uso único, MFA, chaves de API e doze provedores OAuth/OIDC), armazenamento de arquivos (local, S3 ou GCS), Row Level Security, histórico de entidades e tempo real via WebSocket — tudo integrado.
- **Radicalmente Extensível** — Se você consegue criar em React, você pode adicionar ao Rebase. Campos personalizados, visualizações personalizadas, plugins e acesso total a hooks internos.

:::tip
O Rebase funciona de ambas as formas, e o seu código não muda entre elas. **Faça auto-hospedagem (self-host)** — você é o dono dos dados, do código e da máquina onde ele é executado. Ou faça o deploy do mesmo projeto no **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), que é o mesmo Rebase gerenciado para você; ele já está em produção com tenants reais hoje e sendo liberado em lotes durante o beta privado. Pense nele como uma alternativa de código aberto ao Supabase ou Retool, onde *você* decide quem o opera.
:::

## Escolha o seu caminho

O Rebase é um backend e um painel de administração que compartilham um servidor. Comece por aquele que você procura:

| Eu quero… | Comece aqui | O que você obtém |
|---|---|---|
| **Um backend e um painel de administração** | [Quickstart](/docs/getting-started/quickstart/) | Tabelas em TypeScript, uma interface CRUD gerada, uma API REST, autenticação, armazenamento e recursos em tempo real |
| **Apenas a API, sobre meu próprio banco de dados** | [Backend only](/docs/getting-started/headless/) | Uma API REST headless e SDK sobre o seu PostgreSQL existente — sem painel de administração, sem arquivos de tabela |

Nenhuma das opções é um caminho sem volta: um projeto headless ganha um painel de administração ao adicionar um frontend, que renderiza todas as tabelas servidas pelo backend, e qualquer um dos dois pode definir suas tabelas em `backend/schema/` quando desejar tê-las em código.

## Início Rápido

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

O `init` gera um `.env` pronto para execução para você — nenhuma edição é necessária. Em seguida:

```bash
pnpm install
pnpm run dev
```

Essa é toda a primeira execução. Não há banco de dados para instalar nem etapa de schema:
sem nenhuma `DATABASE_URL` configurada, o `rebase dev` inicia um PostgreSQL gerenciado (PGlite) no
diretório do projeto, gera o schema a partir das suas tabelas e cria
as tabelas na inicialização.

**Verifique as URLs na saída do terminal.** O `rebase dev` escolhe uma porta livre por projeto
em vez de portas fixas, de modo que elas variam entre projetos e entre máquinas.
A primeira conta que você registrar se torna o admin — na sua máquina. Uma
implantação em produção, em vez disso, define seu admin através de `REBASE_ADMIN_EMAIL` e
`REBASE_ADMIN_PASSWORD` (consulte [Configuração](/docs/getting-started/configuration/)).

Para usar seu próprio Postgres, descomente `DATABASE_URL` no `.env` e execute
`pnpm run dev` novamente.

→ Siga o [guia de Início Rápido](/docs/getting-started/quickstart) completo para um passo a passo detalhado, incluindo como conectar seu próprio banco de dados.

## Principais Recursos

| Recurso | Descrição |
|---------|-----------|
| **Visualizações em Planilha** | Tabela rápida e virtualizada com edição inline, filtragem, ordenação e busca por texto |
| **Visualização em Lista** | Visualização em lista vertical limpa e responsiva para qualquer tabela |
| **Quadro Kanban** | Visualização em quadro drag-and-drop agrupada por qualquer coluna do tipo enum |
| **Relações** | Um-para-um, um-para-muitos, muitos-para-muitos com tabelas de junção e joins multi-hop |
| **Row Level Security** | Políticas RLS do Postgres compiladas a partir do `rls` que cada tabela deve declarar |
| **Autenticação** | JWT + refresh tokens, doze provedores OAuth/OIDC, magic links, códigos de uso único, MFA via TOTP, chaves de API com escopo, controle de acesso baseado em funções (RBAC) |
| **Armazenamento de Arquivos** | Sistema de arquivos local, compatível com S3 ou Google Cloud Storage, com campos de upload e navegador de arquivos |
| **Sincronização em Tempo Real** | Atualizações em tempo real via WebSocket entre todos os clientes conectados |
| **Histórico de Entidades** | Trilha de auditoria completa para cada criação, atualização e exclusão |
| **API REST** | Endpoints CRUD gerados automaticamente para cada tabela |
| **Importação/Exportação de Dados** | Importação de CSV, JSON e Excel com mapeamento de campos; exportação em CSV/JSON |
| **SDK Tipado** | SDK em JavaScript com tipagem estática (type-safe) para suas aplicações frontend |
| **Sistema de Plugins** | Estenda cada parte da interface — barra de ferramentas, formulários, campos, página inicial |
| **Aprimoramento de Dados com IA** | Autocompletar com tecnologia de LLM para campos de texto |
| **Tarefas Agendadas (Cron Jobs)** | Tarefas em segundo plano agendadas com monitoramento, logs e painel no Studio |
| **Funções Personalizadas** | Rotas Hono baseadas em arquivos com acesso ao banco de dados, públicas por padrão: o token do chamador é lido quando enviado, e `requireAuth` protege uma rota |
| **Serviço de E-mail** | SMTP integrado para redefinição de senha, verificação e e-mails transacionais |
| **Ramificação de Banco de Dados** | Cópias isoladas instantâneas do seu banco de dados para desenvolvimento, homologação ou testes |
| **Webhooks** | Notificações de saída assinadas com HMAC em INSERT, UPDATE, DELETE |
| **Canais de Transmissão** | Canais WebSocket para mensagens em tempo real entre clientes conectados |
| **Rastreamento de Presença** | Rastreie usuários online e sincronize o estado compartilhado entre os participantes |
