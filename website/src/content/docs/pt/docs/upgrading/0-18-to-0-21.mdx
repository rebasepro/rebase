# Atualizando de 0.18 → 0.21

**A versão 0.21.0 foi lançada.** Estas são as entradas `### Breaking` de sua
[seção de changelog](/docs/changelog/), uma a uma, com o que cada uma exige
que você altere. As versões 0.19 e 0.20 não declaram nenhuma breaking change,
portanto, este é um salto único a partir da 0.18 — leia antes de migrar para a 0.21,
não depois.

Ambas são erros de compilação em vez de alterações silenciosas de comportamento:
o build aponta para cada linha que precisa de edição, e o grep abaixo de cada
seção os encontra antes que o build o faça.

---

## 31. `context.client.data` não compila mais em um callback de coleção

`RebaseCallContext["client"]` agora é `RebaseCallbackClient`: `RebaseClient`
sem `data`. No lado do servidor, esse cliente é o singleton `rebase`, que não
possui `data` desde a 0.18, de modo que `context.client.data.collection(…)` compilava
e depois lançava `Cannot read properties of undefined (reading 'collection')` em
cada chamada. Em vez disso, agora é um erro de compilação.

**O que alterar:** faça consultas por meio de `context.data`, o acessador que as
consultas de um callback sempre deveriam usar. Ele é executado com os privilégios
de quem disparou o callback, na própria transação da gravação. O
[guia de callbacks](/docs/collections/callbacks/) aborda o que cada acessador no
contexto pode alcançar.

```diff lang="ts"
 afterSave: async ({ context }) => {
-    await context.client.data.audit_logs.create({ action: "approved" });
+    await context.data.audit_logs.create({ action: "approved" });
 }
```

```bash
grep -rn "client\.data\b" config
```

`context.client.dataAsAdmin` ainda está disponível para um callback que precisa
ver o que um administrador pode ver. `admin.browserCallbacks` também muda: a
sintaxe antiga funcionava lá, porque o cliente do painel carrega `data`, e ela deixa
de compilar da mesma forma. `useRebaseContext().client` em um componente React
mantém seu `data`.

## 32. `selectedEntities` foi removido: uma seleção consiste em linhas ou em uma query

Uma visualização de coleção agora pode selecionar todas as linhas que correspondem
ao seu filtro, não apenas as linhas que já foram carregadas, portanto, o
`SelectionController` não retorna mais um `Entity[]`. `selectionController.selection`
é uma união `EntitySelection`: `{ type: "entities", entities }` para linhas marcadas
manualmente, ou `{ type: "query", query, excluded, count? }` para cada linha que
corresponde a uma query, a maioria das quais ninguém leu.

**O que alterar:** uma ação personalizada que lê a seleção converte-a em linhas
com `resolveSelection` de `@rebasepro/cms`. Ela retorna as linhas marcadas de
uma só vez e lê uma seleção por query uma página por vez — com um callback de
progresso opcional — lançando um erro em vez de retornar um prefixo quando a query
corresponder a mais de 20.000 linhas.

```diff lang="tsx" no-verify
 const handlePublish = async () => {
-    for (const entity of selectionController.selectedEntities) {
+    const selected = await resolveSelection({
+        selection: selectionController.selection,
+        accessor: data.collection(path)
+    });
+    for (const entity of selected) {
         await data.collection(entity.path).update(entity.id, { status: "published" });
     }
 };
```

```bash
grep -rn "selectedEntities" config frontend
```

Três mudanças menores acompanham essa alteração:

- `selectionController.selectedEntities.length` → `selectionController.selectedCount`.
  Ele é `undefined`, nunca 0, quando todas as linhas que correspondem a uma query
  estão selecionadas e a coleção não pode ser contada — renderize esse caso,
  não use um valor padrão.
- `setSelectedEntities(prev => …)` → `setSelection(prev => …)`, que recebe
  e retorna um `EntitySelection`. `setSelectedEntities(rows)` com um array
  ainda funciona.
- A verificação para "algo está selecionado" é `selectionController.hasSelection`.

`isEntitySelected` e `toggleEntitySelection` permanecem inalterados e são o que
um checkbox por linha deve continuar usando. O
[exemplo de ações de coleção](/docs/frontend/entity-actions/#collection-actions)
demonstra o padrão completo.
