# Imports movidos no 0.31

<span class="since-badge" data-since="0.31">Desde 0.31</span>

Os pacotes do kernel descrevem apenas tabelas, portanto, o que descreve uma collection da forma como o painel administrativo a renderiza foi movido para `@rebasepro/cms-types`, e a elevação de migração para `@rebasepro/common/migrate` ([seção 135 do guia de atualização](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

O comando `rebase migrate sdk-calls` (parte de `rebase migrate collections-to-tables`) move cada import abaixo para o seu novo pacote — mesclado a um import daquele pacote que o arquivo já possua, mantendo `import type`, `type` inline e aliases `as` — e adiciona o pacote às dependências do pacote do workspace que está importando; execute `pnpm install` em seguida. Um import de um nome removido, um import de namespace, um `export *`, um `import()` dinâmico ou um `require()` que use um nome movido é uma etapa manual numerada.

Esta lista foi gerada a partir de `tooling/scripts/headless-guard/moved-symbols.json`, a tabela lida pelo codemod. Consulte [`rebase migrate`](/docs/cli/schema/#rebase-migrate) para o comando e [Personalizando uma tabela](/docs/frontend/customize-table/) para saber onde os tipos do painel são usados.
