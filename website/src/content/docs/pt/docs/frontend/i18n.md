## Visão Geral

Cada string que o painel de administração renderiza vem de uma chave. Sete idiomas já vêm integrados — inglês, espanhol, alemão, francês, italiano, português e híndi — e um projeto pode sobrescrever qualquer chave, adicionar um idioma próprio ou traduzir seus próprios componentes usando a mesma tabela.

Três elementos realizam o trabalho:

| | |
|---|---|
| `<Rebase locale>` | em qual idioma iniciar |
| `<Rebase translations>` | o que cada chave diz, por locale |
| `useTranslation()` | ler uma chave a partir do seu próprio componente |

## Escolhendo o idioma

```tsx
<Rebase client={client} authController={authController} locale="es">
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

`locale` é o idioma *inicial*. Um usuário que escolhe um idioma no menu de idiomas tem essa escolha memorizada em seu navegador, e ela prevalece sobre a prop na sua próxima visita — alterar `locale` no código não substitui a configuração do usuário. Qualquer coisa para a qual o Rebase não tenha uma string recorre ao inglês (fallback) em vez de renderizar uma chave.

## Alterando o que uma string diz

`translations` é indexado por locale e, em seguida, por chave. Parcial: defina apenas o punhado que você deseja alterar e todo o resto permanecerá como estava.

```tsx
<Rebase
    client={client}
    authController={authController}
    translations={{
        en: { save: "Publish", delete_confirmation_title: "Unpublish?" },
        es: { save: "Publicar", delete_confirmation_title: "¿Despublicar?" }
    }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

A mesma estrutura adiciona um idioma que o Rebase não fornece nativamente. Forneça a ele um conjunto completo de chaves e defina `locale` para ele:

```tsx
<Rebase
    client={client}
    authController={authController}
    locale="nl"
    translations={{ nl: { save: "Opslaan", cancel: "Annuleren" } }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

As chaves omitidas recorrem ao inglês (fallback), de modo que um conjunto parcial é uma tradução funcional, não quebrada.

### Onde as chaves estão

A tabela inteira é `RebaseTranslations` — uma única interface com todas as chaves nela, para que seu editor as autocomplete e um erro de digitação seja um erro de tipo. Seus valores em inglês ficam em `packages/app/src/locales/en.ts`, que é a referência para o que cada chave realmente diz.

Os nomes seguem a superfície à qual pertencem: `save`, `cancel`, `delete_confirmation_title` para o painel, `studio_*` para as ferramentas de desenvolvedor (`studio_tool_sql`, `studio_group_database`, `studio_backups_denied_title`).

## Traduzindo seus próprios componentes

`useTranslation()` fornece a mesma tabela que suas visualizações personalizadas, campos e ações podem ler:

```tsx
import { useTranslation } from "@rebasepro/app";

function PublishButton() {
    const { t } = useTranslation();
    return <Button>{t("save")}</Button>;
}
```

A interpolação usa a mesma sintaxe `{{name}}` das strings integradas:

```tsx
t("add_to_field", { fieldName: "Tags" });
```

Suas próprias chaves passam por `translations` como quaisquer outras — uma chave que o Rebase não declara ainda é resolvida, portanto, você pode colocar as strings do seu componente na mesma tabela em vez de executar uma segunda pilha de i18n em paralelo.

`t` também retorna a própria chave quando nada corresponde, o que é a resposta ideal e torna uma chave ausente visível na UI em vez de deixá-la em branco.

## As próprias palavras do kit de UI

Algumas strings pertencem ao próprio `@rebasepro/ui` em vez do admin: os textos "No entries found", "All 12 entries loaded" e "Error loading data" das visualizações de lista e cartões, o título de erro da tabela, os nomes da barra de busca e datas relativas como "5m ago". Dentro de uma aplicação Rebase, elas vêm das mesmas traduções (`no_entries_found`, `all_entries_loaded`, `error_loading_data_message`, `search`, `clear_search`, `relative_*`) e acompanham o idioma como qualquer outra string.

Usando o kit isoladamente, ele funciona em inglês até que você o envolva em um `UiLabelsProvider`. Qualquer rótulo omitido mantém seu padrão em inglês:

```tsx
import { UiLabelsProvider } from "@rebasepro/ui";

<UiLabelsProvider labels={{
    noEntriesFound: "Nessuna voce trovata",
    allEntriesLoaded: (count) => `Tutte le ${count} voci caricate`,
    relativeTime: { minutesAgo: (count) => `${count} min fa` }
}}>
    <ListView data={rows} renderRow={renderRow}/>
</UiLabelsProvider>
```

`useUiLabels()` lê os rótulos em vigor, e `formatRelativeTime` do `@rebasepro/utils` aceita `labels: useUiLabels().relativeTime` para exibir uma data da mesma forma.

## Nomes de grupos não são rótulos

O `group` de uma `AppView` é um identificador: o menu lateral (drawer) é recolhido por ele, a página inicial do Studio ordena por ele, e `navigationGroupMappings` anexa ícones a ele. Traduzi-lo onde é declarado quebra todos os três em todos os idiomas, exceto naquele para o qual você traduziu.

Declare o grupo em inglês e deixe o cabeçalho se traduzir sozinho — os grupos nativos do Rebase têm chaves `studio_group_*` e são consultados por nome; um grupo criado por você é renderizado como foi escrito.

```tsx
// Right: the name is stable, the heading is localized for the built-in groups.
{ slug: "queues", name: "Queues", group: "Compute", view: <QueuesView/> }
```
