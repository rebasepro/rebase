# Atualizando um aplicativo existente

Treze etapas, da mais recente para a mais antiga. Comece na etapa acima da versão em que você está e siga
para baixo — ou, se você estiver vindo da 0.12, comece de baixo e suba.

| Você está na | Leia | O que isso causa |
|---|---|---|
| **0.31** | [o changelog da 0.32.0](/docs/changelog/) | A versão 0.32 não declara nenhuma breaking change: atualize todos os pacotes `@rebasepro`. Dois pontos perceptíveis por scripts: um comando CLI destrutivo (`api-keys revoke`, `db branch delete`, `cloud env unset`, `cloud compute set`, …) pede confirmação primeiro e, sem terminal ou sob `--json`, recusa com `confirmation_required` até que você passe `--yes`; e as ferramentas `rebase_cloud_deploy`, `rebase_cloud_env_set`, `rebase_cloud_rollback` e `rebase_cloud_provision` do servidor MCP local atuam apenas com `confirm: true`. `REALTIME_CDC=auto` agora lê o write-ahead log onde o banco de dados permitir; defina `REALTIME_CDC=trigger` para manter a captura por gatilho. |
| **0.30** | [0.30 → 0.31](/docs/upgrading/0-30-to-0-31/) | Tabelas em `backend/schema` (`defineTable`) substituem `config/collections`, e não há mais pacote de configuração: execute `rebase migrate collections-to-tables`, que move o projeto e comprova que o SQL gerado não foi alterado. O painel administrativo renderiza as tabelas fornecidas pelo servidor, customizadas a partir de `frontend/src/cms`; o SDK utiliza `data.table(slug)` e `tables: tablesDictionary`; os bundles estão no formato 3, portanto recompile antes de implantar; o suporte ao MongoDB foi descontinuado. |
| **0.29** | [0.29 → 0.30](/docs/upgrading/0-29-to-0-30/) | Um backend inicializado com `initializeRebaseBackend` mantém o refresh token em um cookie, a menos que defina `cookieAuth: false`, de modo que um chamador que o leia do corpo sem `x-rebase-auth-flow: json` recebe `""`. |
| **0.27 – 0.28** | [0.27 → 0.29](/docs/upgrading/0-27-to-0-29/) | Tudo o que o admin entrega ao seu código é a linha do servidor acompanhada de seu id: o `context.data` e os `browserCallbacks` do navegador entregam strings ISO e chaves estrangeiras onde antes entregavam `Date`s e objetos de relação, o que nenhum compilador detecta; os hooks de dados de `Entity` tornam-se internos; e callbacks, painéis, o painel lateral e a seleção recebem `row` e `id` no lugar de `entity` e `entityId`. A versão 0.28 não declara breaking changes, portanto este é um salto único a partir da 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Um agendamento cron que restringe ambos os campos de dia é executado em qualquer um deles, rodando com mais frequência, e um agendamento com um número malformado é recusado, fazendo com que o job pare de rodar. Uma chave cuja estratégia de `isId` não puder ser atendida pelo seu tipo impede a inicialização. No Rebase Cloud, um deploy ou preview falha quando um arquivo de função ou cron não carrega. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Uma gravação nomeando uma relação `via` de múltiplos saltos, um nome de role que não seja um role único, um token de página do local storage anterior à atualização e um upstream de functions que não possa funcionar são recusados. O login via OAuth valida uma conta não verificada em vez de responder `local-account-unverified`, o servidor MCP não envia mais `REBASE_TOKEN` para a aplicação, e os tipos gerados removem a chave de um belongsTo com `excludeFromApi`. No Rebase Cloud, `rebase cloud webhooks` e `--scale-to-zero true` foram descontinuados, e tokens mais antigos podem precisar ser recriados. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` em uma listagem REST torna-se o seletor para a contagem por trás de `meta.total`, portanto um filtro em uma coluna chamada `count` deve ir dentro de `?where=`; o `list_collections` do MCP remoto envia sua listagem apenas no bloco de texto, sem `structuredContent`; e `@rebasepro/app` não exporta mais a tabela de tradução em espanhol `es`. Uma requisição simples de `OPTIONS` para uma rota sem manipulador, nomes de tabelas em conflito na inicialização, um upsert na coleção de usuários, `page` com `offset`, uma string vazia em um campo obrigatório e a senha de um administrador que viole a política de senhas são recusados. As sessões duram 30 dias de inatividade por padrão, `client.cron` chama `/api/admin/cron`, leituras offline que não puderem ser respondidas integralmente falham com `OFFLINE`, e algumas exportações internas e propriedades não utilizadas foram removidas. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | O SQL renderizado por `db push` e `db generate` é movido para fora de `drizzle/` para o diretório não versionado `.rebase/sql/`, a flag `--generate` de `rebase dev` foi removida porque `dev` sempre regenera os tipos do SDK, e uma edição de schema ao vivo não realiza commit de SQL. Permissões tornam-se escopos: interfaces administrativas solicitam um escopo em vez do papel de admin, chaves de API mantêm escopos em vez de uma lista de permissões e uma flag `admin`, e `schema-admin` não é mais um administrador. Um caminho relativo em `--collections` é lido de onde o comando é executado, um upsert em uma linha excluída e uma atualização que altera uma chave são recusados, o endpoint MCP remoto recebe os argumentos do SDK, e sockets de realtime abertos, links de verificação de e-mail, `signUp` e códigos de recuperação de MFA alteram o modo como tratam uma sessão. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Uma chave de API em um caminho aninhado precisa de permissão de `read` em seus pais, variáveis numéricas ilegíveis e tempos de vida de sessão inválidos impedem a inicialização, um repositório de autenticação customizado requer `unlinkUserIdentity`, e atualizações de convidados passam pelo captcha de `register`. A versão 0.22 não declara breaking changes, portanto este é um salto único a partir da 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` deixa de compilar em um callback de coleção — faça consultas através de `context.data` — e `selectedEntities` dá lugar a uma seleção que pode representar linhas que ninguém carregou. As versões 0.19 e 0.20 não declaram breaking changes, portanto este é um salto único a partir da 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Onze breaking changes, a maioria erros de compilação em vez de alterações silenciosas de comportamento. `rebase.data` desaparece em tempo de execução, os intervalos de peer dependencies são restritos a carets (^), e a versão mínima do Node passa para 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Os pacotes de admin foram renomeados, os recursos passam a ser declarados em vez de configurados, e um bundle compilado anteriormente não inicializará em um runtime atual. As versões 0.15 e 0.16 não quebram nada, portanto este é um salto único a partir da 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Todas as chaves trafegadas na rede passam a ser camelCase, e o login anônimo torna-se opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | O maior salto e o único que altera **quem pode ler seus dados**. Ele remove o schema `auth`, renomeia pacotes, altera o significado de `id`, descarta CJS, migra o painel administrativo para o react-router 8 e corrige três formas pelas quais acessos poderiam ser concedidos sem que você tivesse solicitado. |

As seções de cada página estão na ordem em que devem ser executadas, e cada uma aponta
o sintoma que, de outra forma, você depuraria a partir da ponta errada.

Em seguida, independentemente da etapa percorrida:

- [O checklist de atualização](#upgrade-checklist) abaixo — os greps e comandos que
  vale a pena executar em seguida, em um único bloco.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result

--- 0.30 → 0.31 ---
[ ] bump every @rebasepro package to 0.31 first, then pnpm install
[ ] rebase migrate collections-to-tables on a clean tree; read the manual steps
[ ] move config/index.ts `callbacks` to backend/hooks.ts by hand, if you had them
[ ] rebase generate-sdk; rebase db push --dry-run plans no change
[ ] run the git rm line the codemod printed (your own config/ modules may stay)
[ ] send a to-one relation as its key, not { id } — that is a 400 now
[ ] call /api/docs signed in, or set REBASE_ENABLE_SWAGGER=true to publish it
[ ] rename the MCP tools in prompts and allow-lists (list_tables, query_table, …)
[ ] rebuild the bundle and deploy — a format-2 bundle is refused

--- 0.31 → 0.32 ---
[ ] bump every @rebasepro package to 0.32, then pnpm install
[ ] add --yes to scripted destructive CLI commands (they refuse with confirmation_required)
[ ] rebase verify — fix any rls-policy-recursion it reports
[ ] rebase build — it warns when config/index.ts still exports storageAuthorize
```

`rebase doctor --policies` é o comando ideal para integrar ao CI: ele retorna código de saída diferente de zero
em caso de políticas que ainda contenham a tautologia permissiva ou em políticas substituídas por um push
anterior. As consultas a `pg_policies` antes e depois ainda valem o minuto gasto —
elas mostram as expressões reais, o que é a única forma de detectar uma
política fail-open escrita em uma sintaxe que o detector não identifica. Nem os
pacotes nem o sistema de tipos avisarão: a alteração reside no banco de dados, e o
`db push` é a única coisa que a aplica lá.

## Revertendo um release

Antes de reverter para uma versão anterior à que introduziu companions de admin-request (consulte o [changelog](/docs/changelog/)), torne-os inertes. Um runtime mais antigo nunca remove um companion, portanto, uma regra alterada após o rollback continuaria permitindo acesso total de qualquer admin a qualquer linha. Execute `REVOKE rebase_admin_request FROM rebase_user_admin;` uma vez por role de admin request, ou remova as políticas `_ar_`. O documento [Leituras de admin usam os índices do proprietário](/docs/deployment/existing-database/#admin-reads-use-the-owners-indexes) explica esse funcionamento.
