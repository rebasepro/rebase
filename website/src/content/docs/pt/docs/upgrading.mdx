# Atualizando um aplicativo existente

Onze etapas, da mais recente para a mais antiga. Comece na etapa imediatamente acima da versão em que você está e desça — ou, se estiver vindo da 0.12, comece de baixo e suba.

| Você está na versão | Leia | O que isso afeta |
|---|---|---|
| **0.27 – 0.28** | [0.27 → 0.29](/docs/upgrading/0-27-to-0-29/) | Tudo o que o admin passa para o seu código é a linha do servidor com o seu id ao lado: o `context.data` do navegador e `browserCallbacks` passam strings ISO e chaves estrangeiras onde antes passavam `Date`s e objetos de relação, o que nenhum compilador detecta; os hooks de dados de `Entity` tornam-se internos; e callbacks, painéis, o painel lateral e a seleção recebem `row` e `id` em vez de `entity` e `entityId`. A versão 0.28 não declara breaking changes, portanto, esta é uma única etapa a partir da 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Um agendamento cron que restringe ambos os campos de dia é executado em qualquer um deles, portanto executa com mais frequência, e um agendamento com um número malformado é recusado, fazendo com que o job pare de executar. Uma chave cuja estratégia `isId` não possa ser atendida pelo seu tipo impede a inicialização. No Rebase Cloud, um deploy ou preview falha quando um arquivo de function ou cron não carrega. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Uma escrita especificando uma relação `via` multi-hop, um nome de role que não seja uma única role, um token de página no local storage anterior ao upgrade e um upstream de functions que não funciona são recusados. O login via OAuth resolve uma conta não verificada em vez de responder `local-account-unverified`, o servidor MCP não envia mais `REBASE_TOKEN` para o app, e os tipos gerados removem a chave de um belongsTo com `excludeFromApi`. No Rebase Cloud, `rebase cloud webhooks` e `--scale-to-zero true` foram descontinuados, e tokens mais antigos podem precisar ser criados novamente. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` em uma listagem REST torna-se o modificador para a contagem por trás de `meta.total`, portanto um filtro em uma coluna chamada `count` deve ir dentro de `?where=`; o `list_collections` do MCP remoto envia sua listagem apenas no bloco de texto, sem `structuredContent`; e `@rebasepro/app` não exporta mais a tabela de tradução em espanhol `es`. Um `OPTIONS` simples para uma rota sem manipulador, nomes de tabela em conflito na inicialização, um upsert na coleção users, `page` com `offset`, uma string vazia em um campo obrigatório e a senha de um administrador que viole a política de senhas são recusados. As sessões duram 30 dias de inatividade por padrão, `client.cron` chama `/api/admin/cron`, leituras offline que não puderem ser respondidas integralmente falham com `OFFLINE`, e algumas exportações internas e props não utilizadas foram removidas. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | A renderização SQL de `db push` e `db generate` passa de `drizzle/` para a pasta não versionada `.rebase/sql/`, a flag `--generate` do `rebase dev` foi removida porque `dev` sempre regenera os tipos do SDK, e uma edição de schema ao vivo não commita nenhum SQL. Permissões tornam-se escopos: interfaces de admin solicitam um escopo em vez da role admin, chaves de API contêm escopos em vez de uma lista de permissões e uma flag `admin`, e `schema-admin` não é mais um administrador. Um caminho relativo em `--collections` é lido a partir de onde o comando é executado, um upsert em uma linha excluída (trashed) e um update que altere uma chave são recusados, o endpoint remoto do MCP aceita os argumentos do SDK, e sockets realtime abertos, links de verificação de e-mail, `signUp` e códigos de recuperação de MFA mudam a forma como tratam uma sessão. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Uma chave de API em um caminho aninhado precisa de `read` em seus ancestrais, variáveis numéricas ilegíveis e tempos de vida de sessão inválidos impedem a inicialização, um repositório de autenticação customizado precisa de `unlinkUserIdentity`, e upgrades de convidados passam a exigir o captcha de `register`. A versão 0.22 não declara breaking changes, portanto, esta é uma única etapa a partir da 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` deixa de compilar em um callback de coleção — faça consultas por meio de `context.data` — e `selectedEntities` dá lugar a uma seleção que pode representar linhas que ninguém carregou. As versões 0.19 e 0.20 não declaram breaking changes, portanto, esta é uma única etapa a partir da 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Onze breaking changes, a maioria erros de compilação em vez de alterações silenciosas de comportamento. `rebase.data` desaparece em tempo de execução, os intervalos de peer dependencies são restritos a circunflexos (carets), e a versão mínima do Node passa para 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Os pacotes de admin são renomeados, recursos são declarados em vez de configurados, e um bundle compilado anteriormente não inicializará em um runtime atual. As versões 0.15 e 0.16 não quebram nada, portanto, esta é uma única etapa a partir da 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Todas as chaves de transmissão (wire) passam a ser camelCase, e o login anônimo torna-se opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | A maior etapa, e a única que altera **quem pode ler seus dados**. Ela remove o schema `auth`, renomeia pacotes, altera o significado de `id`, descontinua CJS, migra o painel admin para o react-router 8 e corrige três maneiras pelas quais acessos poderiam ser concedidos sem que você tivesse solicitado. |

As seções de cada página estão na ordem em que devem ser executadas, e cada uma aponta o sintoma que você, de outra forma, investigaria pelo lado errado.

Em seguida, independentemente da etapa realizada:

- [O checklist de atualização](#checklist-de-atualização) abaixo — os greps e comandos que valem a pena executar depois, em um único bloco.

## Checklist de atualização

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` é o comando a ser integrado ao CI: ele retorna código diferente de zero em caso de políticas que ainda contenham a tautologia permissiva, e em políticas substituídas por um push anterior. As consultas a `pg_policies` antes e depois ainda valem o minuto gasto — elas mostram as próprias expressões, que é a única forma de identificar uma política do tipo fail-open escrita de uma maneira que o detector não reconheça. Nem os pacotes nem o sistema de tipos avisarão você: a alteração reside no banco de dados, e `db push` é a única coisa que a aplica lá.
