:::tip[Conectando o Claude aos seus próprios projetos?]
Esse é o [Rebase connector](/docs/ai/rebase-connector/): um conector para
todos eles, e um servidor auto-hospedado conecta-se a ele com `rebase cloud connect`. Esta
página é para as pessoas que **usam** o seu aplicativo.
:::

O [servidor MCP](/docs/ai/mcp/) é uma ferramenta de desenvolvedor: ele roda na sua máquina e armazena uma chave de serviço ou uma chave de API. Um backend implantado também pode servir o MCP diretamente, em `/mcp`, para as pessoas que usam o seu aplicativo. Um assistente conectado por uma delas lê e grava no projeto **como essa pessoa**, e cada chamada é executada sob sua própria segurança em nível de linha (row-level security).

Ele fica desativado a menos que você o ative, e ambas as variáveis são obrigatórias:

```bash
REBASE_MCP_ENABLED=true
REBASE_PUBLIC_URL=https://app.example.com   # this deployment's real origin
```

Sem `REBASE_PUBLIC_URL`, um segredo JWT ou um driver de dados capaz de delimitar uma consulta a um único usuário, o endpoint se recusa a inicializar e informa o motivo no log de inicialização. Nenhum `REBASE_ROLE` o ativa.

- **OAuth, com uma tela de consentimento.** Um cliente localiza o servidor de autorização por meio de `/.well-known/oauth-protected-resource`, registra a si mesmo (o registro dinâmico fica ativo por padrão; `REBASE_MCP_OPEN_REGISTRATION=false` o limita aos clientes que você registrar) e direciona a pessoa para uma tela de consentimento que realiza o login por meio do seu `/auth/login` existente. Uma conta com segundo fator de autenticação é então solicitada a fornecer seu código autenticador ou um código de recuperação, por meio das rotas existentes de `/auth/mfa/challenge`. Quando o frontend do seu próprio aplicativo mantém uma sessão no mesmo navegador, a tela oferece essa conta, e o botão Permitir consente como ela sem necessidade de senha; é assim que alguém que faz login apenas com Google, GitHub ou link por e-mail se conecta. Caso contrário, o login é feito com senha, e quem não tiver uma deve defini-la primeiro via `/auth/forgot-password` ("Esqueci minha senha" do seu aplicativo); a tela informa isso. Ela também exibe o host para o qual o código de autorização é enviado e indica que esse host não é verificado: qualquer pessoa pode registrar um cliente com qualquer nome, portanto o host é a parte que o usuário pode verificar.
- **Nove ferramentas, três escopos.** Os mesmos [escopos](/docs/backend/roles-and-scopes/) que qualquer credencial usa. `data:read` oferece `list_collections`, `describe_collection`, `query_collection`, `show_collection`, `count_documents` e `get_document`; `data:write` adiciona `create_document` e `update_document`; `data:delete` adiciona `delete_document`. Um cliente que não solicita nada recebe `data:read`. Cada um se restringe a uma coleção: `data:read:posts` lista, descreve e lê `posts` e nada mais. Um escopo determina quais ferramentas são disponibilizadas e quais coleções elas alcançam, não quais linhas: uma lista vazia pode ser o RLS funcionando, e o `data:write` ainda assim não pode gravar uma linha que a pessoa não poderia.
- **`show_collection` coloca as linhas diante da pessoa.** Ele recebe os argumentos de `query_collection` e retorna a mesma página, além das colunas que o painel de administração exibe. Um cliente que renderiza MCP Apps, como o Claude, o abre como uma tabela na conversa: a pessoa pode carregar mais linhas e, caso a conexão tenha `data:write`, editar uma célula diretamente. Cada salvamento é uma chamada de `update_document` feita em nome dela, sob seu RLS, e o modelo é informado sobre o que foi alterado. Um cliente sem suporte a MCP Apps, como o Claude Code ou Cursor, não exibe nenhuma tabela, e o modelo lê a página exatamente como leria a partir de `query_collection`.
- **Concessões feitas antes da versão 0.24 mantêm seu alcance.** `mcp:read` é interpretado como `data:read`, e `mcp:write` como `data:write data:delete`, tanto em concessões armazenadas quanto em tokens já emitidos.
- **Uma chave de API também funciona.** `/mcp` também aceita `Authorization: Bearer rk_…`, para um cliente configurado com um cabeçalho em vez de um fluxo OAuth. A chave tem acesso às ferramentas que seus escopos `data:*` cobrem, atuando como quem ela representa: uma [chave pessoal](/docs/backend/api-keys/#personal-keys) como seu proprietário, uma chave de serviço como `api-key:<id>`.
- **O vocabulário do SDK, as respostas do REST.** As ferramentas recebem o que o SDK recebe — `where` (`{"status": ["==", "paid"]}`), `orderBy` (`["created_at", "desc"]` ou `"created_at:desc"`), `limit`, `offset`, `searchString` e `data` para uma gravação — e fazem a leitura pelo caminho de `GET /api/data/<collection>`, de modo que uma linha retorne como o REST a entrega (datas em formato ISO, um `belongsTo` como sua chave estrangeira, por exemplo, `authorId`) e possa ser enviada de volta em uma atualização sem alterações. `query_collection` responde `{ data, meta }` com `meta.total` e `meta.hasMore`, e `count_documents` `{ count }`. Assim como no REST, um `limit` acima de 1000, um argumento não declarado e a edição ou exclusão de uma linha na lixeira (404) são recusados; definir o campo de exclusão lógica (soft-delete) como `null` a restaura. `deleted: "only"` (ou `"include"`) em `query_collection` e `count_documents` lê a lixeira, assim como o `?deleted=` do REST faz, para que uma linha movida para a lixeira por `delete_document` possa ser encontrada novamente para restauração. Sua descrição informa ao modelo que a exclusão só é permanente se a coleção não tiver um campo de exclusão lógica.
- **A listagem nomeia as coleções; `describe_collection` fornece o schema de uma delas.** `list_collections` retorna o `name`, `title` e `description` de cada coleção, e `describe_collection { collection }` retorna os schemas OpenAPI de `row` e `create` dessa coleção, além de `softDeleteField` onde as linhas vão para a lixeira. As descrições das ferramentas orientam o modelo a descrever uma coleção antes de gravar nela. A listagem de um projeto com 200 coleções tem cerca de 5 mil tokens, e cada descrição fica abaixo de 1 mil; com todos os schemas na listagem, seriam cerca de 150 mil tokens.
- **Um token exclusivo para este endpoint.** Um token de acesso MCP é recusado por `/api/data`, `/api/admin` e pelo WebSocket, garantindo que conectar um assistente não repasse uma sessão completa a ele.

Cada requisição para `/mcp` relê a conta da pessoa. Uma conta excluída ou desativada, ou uma ação de "desconectar de todos os dispositivos" ou alteração de senha após a emissão do token, interrompe imediatamente um cliente conectado com um erro 401. Um rebaixamento de permissão entra em vigor na sua próxima chamada de ferramenta. Cada renovação (refresh) realiza as mesmas verificações e recusa essa concessão em definitivo. Uma sessão de convidado não tem permissão para consentir de forma alguma.

Uma limitação. Desconectar um cliente (`DELETE /api/oauth/grants/:clientId`, usando a sessão da própria pessoa) revoga seus tokens de atualização (refresh tokens) imediatamente, mas um token de acesso já emitido continuará funcionando até expirar, o que ocorre em até uma hora.

As rotas estão em [Endpoints](/docs/backend/endpoints/#mcp-surface) e as variáveis em [Configuração](/docs/getting-started/configuration/#mcp-surface).
