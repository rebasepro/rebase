Uma coluna do tipo array é uma lista que o formulário repete. Uma coluna `jsonb` é um documento: o
CMS constrói um formulário para ela quando a coluna descreve sua estrutura com
[`json.*`](/docs/schema/json/) e oferece edição livre de chave/valor quando não o
faz.

```ts
// backend/schema/pages.ts
import { defineTable, col, json } from "@rebasepro/server/schema";

export const pages = defineTable("pages", {
    columns: {
        id:       col.uuid().primaryKey().defaultRandom(),
        tags:     col.text().array(),
        settings: col.jsonb().$type<{ theme?: "light" | "dark"; pinned?: boolean }>(),
        address:  col.jsonb(json.object({
            street: json.string().required(),
            city:   json.string(),
            zip:    json.string(),
        })),
        body:     col.jsonb(json.array(json.oneOf({
            paragraph: json.string(),
            image:     json.storage({ path: "pages/images/", accept: ["image/*"] }),
            quote:     json.object({ text: json.string().required(), author: json.string() }),
        }))),
    },
    rls: "admin-only",
});
```

## Arrays

<span class="since-badge" data-since="0.31">Desde 0.31</span>

Uma coluna array (`col.text().array()`) é uma lista repetível do campo do item: `tags` acima
é uma lista de campos de entrada de texto. O método `.validate({ minItems, maxItems, uniqueItems })` no
array define quantos itens o formulário aceita.

<FieldWidgetPreview client:only="react" variant="repeat" />

Um array de um conjunto fechado, `col.text({ enum: [...] }).array()`, é uma
seleção múltipla; consulte [conjuntos fechados](/docs/collections/properties/#closed-sets-of-values).
Uma coluna `col.storage().multiple()` é um upload de múltiplos arquivos; consulte
[Upload de arquivos](/docs/collections/file-uploads/#several-files).

## Documentos com estrutura

<span class="since-badge" data-since="0.31">Desde 0.31</span>

`col.jsonb(json.object({ … }))` é um grupo de campos, um por chave, cada um sendo o campo
que seu construtor `json.*` requer: `json.string()` é um campo de texto, `json.number()` um
número, `json.date()` um seletor de data, `json.storage()` um campo de upload. Uma chave
`.required()` é obrigatória no formulário, e um `.default()` preenche o formulário de um
novo registro.

<FieldWidgetPreview client:only="react" variant="group" />

`json.array(of)` repete seu item. Um array de `json.oneOf({ … })` é um editor de
blocos: cada variante é um tipo de bloco que o usuário pode adicionar, reordenar e remover.
`body` acima contém parágrafos, imagens e citações.

<FieldWidgetPreview client:only="react" variant="block" />

Um `json.oneOf` isolado, fora de um array, e `json.unknown()` não possuem
campo estruturado: eles são editados como JSON livre.

## Documentos sem estrutura

<span class="since-badge" data-since="0.31">Desde 0.31</span>

`col.jsonb().$type<T>()` tipa o documento para o TypeScript, mas `T` é apagado quando o
código é executado, portanto o servidor e o CMS não sabem nada sobre ele. `settings` acima é
editado como pares livres de chave/valor. Forneça à coluna uma estrutura `json.*` quando o CMS
deve renderizar um formulário para ela.

## Personalizando itens e chaves aninhadas

<span class="since-badge" data-since="0.31">Desde 0.31</span>

```tsx
// frontend/src/cms/pages.tsx
import { customizeTable } from "@rebasepro/cms";
import type { pages } from "../../../backend/schema/pages";

export const pagesCms = customizeTable<typeof pages>("pages", {
    fields: {
        tags: { sortable: false, of: { previewAsTag: true } },
        address: {
            spreadChildren: true,
            fieldOrder: ["zip", "city", "street"],
            fields: {
                street: { name: "Street and number" },
                zip:    { name: "Postal code", span: 1 },
            },
        },
        body: {
            expanded: true,
            oneOf: {
                paragraph: { markdown: true },
                quote:     { fields: { author: { name: "Who said it" } } },
            },
        },
    },
});
```

Em um array:

| Opção | Efeito |
|---|---|
| `of` | As opções de cada item: qualquer opção de campo, aninhada tão profundamente quanto o item for. |
| `sortable` | Os itens podem ser reordenados arrastando. |
| `canAddElements` | Itens podem ser adicionados. |
| `expanded` | Todos os itens abertos ao carregar. |
| `minimalistView` | Itens sem sua moldura e cabeçalho. |
| `oneOf` | Para uma lista de blocos tipados: as opções de cada variante, pelo nome da variante. |
| `enumLabels`, `enumOrder`, `storage` | Definidos no array, aplicados a cada item. |

Em um documento:

| Opção | Efeito |
|---|---|
| `fields` | As opções de cada chave, por chave; cada uma aceita qualquer opção de campo, incluindo seus próprios `fields`. |
| `fieldOrder` | A ordem na qual as chaves são exibidas. |
| `previewFields` | As chaves exibidas quando o documento é renderizado como uma prévia. |
| `spreadChildren` | As chaves dispostas como se fossem campos do próprio registro. |
| `expanded` | As chaves abertas ao carregar. |
| `minimalistView` | As chaves sem a moldura do documento. |
| `keyValue` | Edite como pares livres de chave/valor, mesmo quando a coluna possui uma estrutura. |

`fields`, `fieldOrder` e `previewFields` são tipados pelas chaves do documento,
quer a coluna seja `col.jsonb().$type<T>()` ou tenha uma estrutura `json.*`. No entanto, em uma
coluna `col.jsonb().$type<T>()`, o CMS não possui uma estrutura à qual aplicá-los: eles são
ignorados, com um aviso em desenvolvimento. Opções aninhadas para uma chave, variante ou
item que o documento não possui são ignoradas da mesma forma.
