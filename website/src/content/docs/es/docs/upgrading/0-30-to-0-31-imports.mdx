# Importaciones que cambiaron de lugar en 0.31

<span class="since-badge" data-since="0.31">Desde 0.31</span>

Los paquetes del kernel solo describen tablas, por lo que todo lo que describe una colección tal como la representa el panel de administración se movió a `@rebasepro/cms-types`, y la elevación de migración a `@rebasepro/common/migrate` ([sección 135 de la guía de actualización](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

`rebase migrate sdk-calls` (parte de `rebase migrate collections-to-tables`) mueve cada una de las importaciones que figuran a continuación a su nuevo paquete —fusionándolas en una importación de dicho paquete que el archivo ya tenga, conservando `import type`, `type` en línea y los alias `as`— y añade el paquete a las dependencias del paquete del workspace que lo importa; ejecute `pnpm install` después. Una importación de un nombre eliminado, una importación de espacio de nombres (namespace import), un `export *`, un `import()` dinámico o un `require()` que use un nombre reubicado es un paso manual numerado.

Esta lista se genera a partir de `tooling/scripts/headless-guard/moved-symbols.json`, la tabla que lee el codemod. Consulte [`rebase migrate`](/docs/cli/schema/#rebase-migrate) para conocer el comando, y [Personalizar una tabla](/docs/frontend/customize-table/) para ver dónde se utilizan los tipos del panel.
