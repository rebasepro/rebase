# Actualización de 0.18 → 0.21

**0.21.0 ya está disponible.** Estas son las entradas de `### Breaking` de su
[sección del registro de cambios](/docs/changelog/), una por una, junto con lo que cada una le pide
cambiar. 0.19 y 0.20 no declaran ningún cambio disruptivo, por lo que este es un salto único desde
0.18; léalo antes de migrar a 0.21, no después.

Ambos son errores de compilación en lugar de cambios silenciosos de comportamiento: la compilación señala
cada línea que necesita edición, y el grep debajo de cada sección los encuentra
antes de que lo haga la compilación.

---

## 31. `context.client.data` ya no compila en un callback de colección

`RebaseCallContext["client"]` ahora es `RebaseCallbackClient`: `RebaseClient`
sin `data`. En el servidor, ese cliente es el singleton `rebase`, que no ha tenido
`data` desde la versión 0.18, por lo que `context.client.data.collection(…)` compilaba y luego
lanzaba `Cannot read properties of undefined (reading 'collection')` en cada
llamada. Ahora, en su lugar, es un error de compilación.

**Qué cambiar:** realice las consultas a través de `context.data`, el descriptor de acceso que las
consultas de un callback siempre debieron usar. Se ejecuta con los privilegios de lo que haya
desencadenado el callback, en la propia transacción de escritura. La
[guía de callbacks](/docs/collections/callbacks/) cubre a qué puede acceder cada descriptor de acceso en el
contexto.

```diff lang="ts"
 afterSave: async ({ context }) => {
-    await context.client.data.audit_logs.create({ action: "approved" });
+    await context.data.audit_logs.create({ action: "approved" });
 }
```

```bash
grep -rn "client\.data\b" config
```

`context.client.dataAsAdmin` sigue estando disponible para un callback que deba ver lo que un
administrador puede ver. `admin.browserCallbacks` también cambia: la sintaxis anterior se ejecutaba allí,
porque el cliente del panel incluye `data`, y deja de compilar de la misma manera.
`useRebaseContext().client` en un componente de React conserva su `data`.

## 32. `selectedEntities` ya no existe: una selección son filas o una consulta

Una vista de colección ahora puede seleccionar cada fila que coincida con su filtro, no solo
las filas que ha cargado, por lo que `SelectionController` ya no entrega un
`Entity[]`. `selectionController.selection` es una unión de tipo `EntitySelection`:
`{ type: "entities", entities }` para filas marcadas manualmente, o
`{ type: "query", query, excluded, count? }` para cada fila que coincida con una consulta,
la mayoría de las cuales nadie ha leído.

**Qué cambiar:** una acción personalizada que lea la selección la convierte en filas
con `resolveSelection` de `@rebasepro/cms`. Devuelve las filas marcadas de
inmediato, y lee una selección de consulta página por página —con un callback de progreso
opcional—, lanzando un error en lugar de devolver un prefijo cuando la consulta coincide con más
de 20 000 filas.

```diff lang="tsx" no-verify
 const handlePublish = async () => {
-    for (const entity of selectionController.selectedEntities) {
+    const selected = await resolveSelection({
+        selection: selectionController.selection,
+        accessor: data.collection(path)
+    });
+    for (const entity of selected) {
         await data.collection(entity.path).update(entity.id, { status: "published" });
     }
 };
```

```bash
grep -rn "selectedEntities" config frontend
```

Tres cambios menores vienen acompañados de esto:

- `selectionController.selectedEntities.length` → `selectionController.selectedCount`.
  Es `undefined`, nunca 0, cuando se selecciona cada fila que coincide con una consulta y
  la colección no se puede contar; renderice ese caso, no le asigne un valor por defecto.
- `setSelectedEntities(prev => …)` → `setSelection(prev => …)`, que recibe
  y devuelve un `EntitySelection`. `setSelectedEntities(rows)` con un array
  sigue funcionando.
- La comprobación para saber "si hay algo seleccionado" es `selectionController.hasSelection`.

`isEntitySelected` y `toggleEntitySelection` no han cambiado y son lo que una
casilla de verificación por fila debería seguir usando. El
[ejemplo de acciones de colección](/docs/frontend/entity-actions/#collection-actions)
muestra el patrón completo.
