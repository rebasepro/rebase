Una columna de tipo array es una lista que el formulario repite. Una columna `jsonb` es un documento: el
CMS crea un formulario para ella cuando la columna describe su estructura con
[`json.*`](/docs/schema/json/), y ofrece edición libre de clave/valor cuando no
lo hace.

```ts
// backend/schema/pages.ts
import { defineTable, col, json } from "@rebasepro/server/schema";

export const pages = defineTable("pages", {
    columns: {
        id:       col.uuid().primaryKey().defaultRandom(),
        tags:     col.text().array(),
        settings: col.jsonb().$type<{ theme?: "light" | "dark"; pinned?: boolean }>(),
        address:  col.jsonb(json.object({
            street: json.string().required(),
            city:   json.string(),
            zip:    json.string(),
        })),
        body:     col.jsonb(json.array(json.oneOf({
            paragraph: json.string(),
            image:     json.storage({ path: "pages/images/", accept: ["image/*"] }),
            quote:     json.object({ text: json.string().required(), author: json.string() }),
        }))),
    },
    rls: "admin-only",
});
```

## Arrays

<span class="since-badge" data-since="0.31">Since 0.31</span>

Una columna de tipo array (`col.text().array()`) es una lista repetible del campo del elemento: `tags` arriba
es una lista de entradas de texto. `.validate({ minItems, maxItems, uniqueItems })` en el
array define cuántos elementos acepta el formulario.

<FieldWidgetPreview client:only="react" variant="repeat" />

Un array de un conjunto cerrado, `col.text({ enum: [...] }).array()`, es en cambio una
selección múltiple; consulta [conjuntos cerrados](/docs/collections/properties/#closed-sets-of-values).
Una columna `col.storage().multiple()` es una subida de múltiples archivos; consulta
[Subida de archivos](/docs/collections/file-uploads/#several-files).

## Documentos con estructura

<span class="since-badge" data-since="0.31">Since 0.31</span>

`col.jsonb(json.object({ … }))` es un grupo de campos, uno por clave, correspondiendo cada uno al campo
que su constructor `json.*` solicita: `json.string()` una entrada de texto, `json.number()` un
número, `json.date()` un selector de fecha, `json.storage()` un campo de subida de archivos. Una
clave con `.required()` es obligatoria en el formulario, y un `.default()` rellena el formulario de un
nuevo registro.

<FieldWidgetPreview client:only="react" variant="group" />

`json.array(of)` repite su elemento. Un array de `json.oneOf({ … })` es un editor
de bloques: cada variante es un tipo de bloque que un usuario puede añadir, reordenar y eliminar.
`body` arriba contiene párrafos, imágenes y citas.

<FieldWidgetPreview client:only="react" variant="block" />

Un `json.oneOf` por sí solo, fuera de un array, y `json.unknown()` no tienen un
campo estructurado: se editan como JSON libre.

## Documentos sin estructura

<span class="since-badge" data-since="0.31">Since 0.31</span>

`col.jsonb().$type<T>()` tipa el documento para TypeScript, pero `T` se elimina cuando el
código se ejecuta, por lo que el servidor y el CMS no saben nada sobre él. `settings` arriba se
edita como pares clave/valor libres. Asigna a la columna una estructura `json.*` cuando el CMS
deba dibujar un formulario para ella.

## Personalizar elementos y claves anidadas

<span class="since-badge" data-since="0.31">Since 0.31</span>

```tsx
// frontend/src/cms/pages.tsx
import { customizeTable } from "@rebasepro/cms";
import type { pages } from "../../../backend/schema/pages";

export const pagesCms = customizeTable<typeof pages>("pages", {
    fields: {
        tags: { sortable: false, of: { previewAsTag: true } },
        address: {
            spreadChildren: true,
            fieldOrder: ["zip", "city", "street"],
            fields: {
                street: { name: "Street and number" },
                zip:    { name: "Postal code", span: 1 },
            },
        },
        body: {
            expanded: true,
            oneOf: {
                paragraph: { markdown: true },
                quote:     { fields: { author: { name: "Who said it" } } },
            },
        },
    },
});
```

En un array:

| Opción | Efecto |
|---|---|
| `of` | Las opciones de cada elemento: cualquier opción de campo, anidada a la misma profundidad que el elemento. |
| `sortable` | Los elementos se pueden reordenar arrastrando. |
| `canAddElements` | Se pueden añadir elementos. |
| `expanded` | Todos los elementos abiertos al cargar. |
| `minimalistView` | Elementos sin su marco ni encabezado. |
| `oneOf` | Para una lista de bloques tipados: las opciones de cada variante, por nombre de variante. |
| `enumLabels`, `enumOrder`, `storage` | Definidas en el array, aplicadas a cada elemento. |

En un documento:

| Opción | Efecto |
|---|---|
| `fields` | Las opciones de cada clave, por clave; cada una acepta cualquier opción de campo, incluyendo sus propios `fields`. |
| `fieldOrder` | El orden en el que se muestran las claves. |
| `previewFields` | Las claves mostradas cuando el documento se dibuja como vista previa. |
| `spreadChildren` | Las claves distribuidas como si fueran campos propios del registro. |
| `expanded` | Las claves abiertas al cargar. |
| `minimalistView` | Las claves sin el marco del documento. |
| `keyValue` | Editar como pares clave/valor libres, incluso cuando la columna tiene una estructura. |

`fields`, `fieldOrder` y `previewFields` están tipados por las claves del documento,
tanto si la columna es `col.jsonb().$type<T>()` como si tiene una estructura `json.*`. Sin embargo, en una
columna `col.jsonb().$type<T>()`, el CMS no tiene una estructura a la cual aplicarlos: se
omiten, mostrando una advertencia en desarrollo. Las opciones anidadas para una clave, una variante o
un elemento que el documento no tiene se omiten de la misma manera.
