# Actualizar una aplicación existente

Trece saltos, los más recientes primero. Comienza en el que esté justo por encima de la versión en la que te encuentras y avanza hacia abajo — o, si vienes de la 0.12, comienza desde abajo y avanza hacia arriba.

| Estás en | Lee | Qué impacto tiene |
|---|---|---|
| **0.31** | [el registro de cambios de 0.32.0](/docs/changelog/) | 0.32 no declara cambios incompatibles: actualiza todos los paquetes `@rebasepro`. Dos cosas que un script notará: un comando destructivo de CLI (`api-keys revoke`, `db branch delete`, `cloud env unset`, `cloud compute set`, …) solicita confirmación primero, y sin terminal o con `--json` se rechaza con `confirmation_required` hasta que pases `--yes`; además, `rebase_cloud_deploy`, `rebase_cloud_env_set`, `rebase_cloud_rollback` y `rebase_cloud_provision` del servidor MCP local solo actúan con `confirm: true`. `REALTIME_CDC=auto` ahora lee el write-ahead log donde la base de datos lo permite; establece `REALTIME_CDC=trigger` para mantener la captura mediante triggers. |
| **0.30** | [0.30 → 0.31](/docs/upgrading/0-30-to-0-31/) | Las tablas en `backend/schema` (`defineTable`) reemplazan a `config/collections`, y ya no existe el paquete config: ejecuta `rebase migrate collections-to-tables`, lo que migra el proyecto y confirma que el SQL generado no ha cambiado. El panel de administración muestra las tablas que sirve el servidor, personalizadas desde `frontend/src/cms`; el SDK pasa a usar `data.table(slug)` y `tables: tablesDictionary`; los bundles tienen formato 3, así que vuelve a compilar antes de desplegar; MongoDB queda retirado. |
| **0.29** | [0.29 → 0.30](/docs/upgrading/0-29-to-0-30/) | Un backend iniciado con `initializeRebaseBackend` almacena el token de actualización en una cookie a menos que configure `cookieAuth: false`, por lo que quien lo lea del body sin `x-rebase-auth-flow: json` recibirá `""`. |
| **0.27 – 0.28** | [0.27 → 0.29](/docs/upgrading/0-27-to-0-29/) | Todo lo que el admin pasa a tu código es la fila del servidor con su id al lado: `context.data` y `browserCallbacks` del navegador devuelven cadenas ISO y claves foráneas donde antes entregaban objetos `Date` y de relación, lo cual ningún compilador detecta; los hooks de datos de `Entity` pasan a ser internos; y los callbacks, paneles, el panel lateral y la selección reciben `row` e `id` en lugar de `entity` y `entityId`. 0.28 no declara cambios incompatibles, por lo que es un solo salto desde 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Una programación de cron que restrinja ambos campos de día se ejecuta en cualquiera de los dos, por lo que se ejecuta con más frecuencia, y se rechaza una programación con un número mal formado, con lo que ese job deja de ejecutarse. Una clave cuya estrategia `isId` no pueda ser satisfecha por su tipo detiene el arranque. En Rebase Cloud, un deploy o preview falla si un archivo de función o de cron no se carga. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Se rechaza una escritura que especifique una relación `via` de múltiples saltos, un nombre de rol que no sea un único rol, un token de página en local storage anterior a la actualización y un upstream de functions que no pueda operar. El inicio de sesión con OAuth valida una cuenta no verificada en lugar de responder `local-account-unverified`, el servidor MCP ya no envía `REBASE_TOKEN` a la app y los tipos generados descartan la clave de un belongsTo con `excludeFromApi`. En Rebase Cloud, `rebase cloud webhooks` y `--scale-to-zero true` quedan retirados, y puede ser necesario volver a generar los tokens antiguos. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` en un listado REST pasa a ser el modificador para el conteo tras `meta.total`, por lo que un filtro sobre una columna llamada `count` debe ir dentro de `?where=`; `list_collections` del MCP remoto envía su listado solo en el bloque de texto, sin `structuredContent`; y `@rebasepro/app` ya no exporta la tabla de traducción al español `es`. Se rechazan las peticiones `OPTIONS` simples a una ruta sin manejador, nombres de tablas en colisión al arrancar, un upsert en la colección users, `page` con `offset`, una cadena vacía en un campo requerido y contraseñas de administrador que no cumplan la directiva de contraseñas. Las sesiones duran 30 días de inactividad por defecto, `client.cron` llama a `/api/admin/cron`, las lecturas sin conexión que no puedan responderse por completo fallan con `OFFLINE`, y se eliminan algunas exportaciones internas y props sin uso. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | El SQL generado por `db push` y `db generate` se traslada fuera de `drizzle/` hacia `.rebase/sql/` (sin commit), la opción `--generate` de `rebase dev` desaparece porque `dev` siempre regenera los tipos del SDK, y editar el esquema en vivo no realiza commit de SQL. Los permisos se convierten en scopes: las interfaces de administración solicitan un scope en lugar del rol admin, las API keys almacenan scopes en lugar de una lista de permisos y un flag `admin`, y `schema-admin` deja de ser administrador. Un valor relativo en `--collections` se resuelve desde donde se ejecuta el comando, se rechaza un upsert sobre una fila en la papelera y una actualización que modifique una clave, el endpoint del MCP remoto acepta los argumentos del SDK, y los sockets realtime abiertos, los enlaces de verificación de email, `signUp` y los códigos de recuperación de MFA cambian su tratamiento de la sesión. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Una API key en una ruta anidada requiere `read` en sus ancestros, variables numéricas ilegibles y duraciones de sesión no válidas impiden el arranque, un repositorio de autenticación personalizado requiere `unlinkUserIdentity`, y las conversiones de cuentas de invitado aplican el captcha de `register`. 0.22 no declara cambios incompatibles, por lo que es un solo salto desde 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` deja de compilar en un callback de colección — realiza las consultas mediante `context.data` — y `selectedEntities` se reemplaza por una selección capaz de representar filas que nadie ha cargado. 0.19 y 0.20 no declaran cambios incompatibles, por lo que es un solo salto desde 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Once cambios incompatibles, la mayoría errores de compilación en lugar de cambios silenciosos de comportamiento. `rebase.data` desaparece en tiempo de ejecución, los rangos de dependencias peer se acotan a carets (^), y la versión mínima de Node sube a 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Se renombran los paquetes de administración, los recursos se declaran en lugar de configurarse, y un bundle generado antes de esta versión no arrancará en un runtime actual. 0.15 y 0.16 no introducen cambios incompatibles, por lo que es un solo salto desde 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Todas las claves de la API pasan a camelCase y el inicio de sesión anónimo pasa a ser opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | El salto más grande, y el único que cambia **quién puede leer tus datos**. Elimina el esquema `auth`, renombra paquetes, modifica el significado de `id`, descarta CJS, migra el panel de administración a react-router 8 y corrige tres vías por las cuales se podía conceder acceso no solicitado. |

Las secciones de cada página siguen el orden en el que debes aplicarlas, y cada una detalla el síntoma que de otro modo tendrías que depurar partiendo del punto equivocado.

Después, independientemente del salto realizado:

- [La lista de verificación de actualización](#upgrade-checklist) a continuación — los greps y comandos que conviene ejecutar al terminar, reunidos en un solo bloque.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result

--- 0.30 → 0.31 ---
[ ] bump every @rebasepro package to 0.31 first, then pnpm install
[ ] rebase migrate collections-to-tables on a clean tree; read the manual steps
[ ] move config/index.ts `callbacks` to backend/hooks.ts by hand, if you had them
[ ] rebase generate-sdk; rebase db push --dry-run plans no change
[ ] run the git rm line the codemod printed (your own config/ modules may stay)
[ ] send a to-one relation as its key, not { id } — that is a 400 now
[ ] call /api/docs signed in, or set REBASE_ENABLE_SWAGGER=true to publish it
[ ] rename the MCP tools in prompts and allow-lists (list_tables, query_table, …)
[ ] rebuild the bundle and deploy — a format-2 bundle is refused

--- 0.31 → 0.32 ---
[ ] bump every @rebasepro package to 0.32, then pnpm install
[ ] add --yes to scripted destructive CLI commands (they refuse with confirmation_required)
[ ] rebase verify — fix any rls-policy-recursion it reports
[ ] rebase build — it warns when config/index.ts still exports storageAuthorize
```

`rebase doctor --policies` es el que debes conectar en CI: devuelve un código de salida distinto de cero ante cualquier directiva que aún conserve la tautología permisiva o que haya sido reemplazada por un push anterior. Las lecturas de `pg_policies` antes y después siguen mereciendo ese minuto: muestran las expresiones en sí, lo cual es la única manera de detectar una directiva fail-open escrita con una sintaxis que el analizador no reconozca. Ni los paquetes ni el sistema de tipos te avisarán: el cambio reside en la base de datos, y `db push` es lo único que lo aplica allí.

## Revertir una versión

Antes de revertir a una versión anterior a la que introdujo los companions de admin-request (consulta el [registro de cambios](/docs/changelog/)), déjalos inactivos. Un runtime anterior nunca elimina un companion, por lo que cualquier regla modificada tras el rollback seguiría permitiendo el acceso a todos los administradores para todas las filas. Ejecuta `REVOKE rebase_admin_request FROM rebase_user_admin;` una vez por cada rol de solicitud de admin, o elimina las políticas `_ar_`. En [Las lecturas de administración usan los índices del propietario](/docs/deployment/existing-database/#admin-reads-use-the-owners-indexes) se explican en detalle.
