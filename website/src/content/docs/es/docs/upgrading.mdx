# Actualizar una aplicación existente

Once saltos, el más reciente primero. Comienza en el que esté justo por encima de la versión en la que te encuentras y avanza hacia abajo — o, si vienes de la 0.12, comienza desde abajo y avanza hacia arriba.

| Estás en | Leer | En qué te afecta |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Aún no publicada. Todo lo que el admin entrega a tu código es la fila del servidor con su id al lado: `context.data` y `browserCallbacks` del navegador entregan cadenas ISO y claves foráneas donde antes entregaban `Date`s y objetos de relación, lo cual ningún compilador detecta; los hooks de datos de `Entity` pasan a ser internos; y los callbacks, paneles, el panel lateral y la selección toman `row` e `id` en lugar de `entity` y `entityId`. La versión 0.28 no declara cambios incompatibles, por lo que este es un solo salto desde la 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Una programación de cron que restringe ambos campos de día se ejecuta en cualquiera de los dos, por lo que se ejecuta con más frecuencia, y una programación con un número mal formado se rechaza, por lo que esa tarea deja de ejecutarse. Una clave cuya estrategia `isId` no puede ser cumplida por su tipo detiene el inicio. En Rebase Cloud, un despliegue o vista previa falla cuando un archivo de función o de cron no se carga. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Se rechazan una escritura que nombre una relación `via` de múltiples saltos, un nombre de rol que no sea un único rol, un token de página de almacenamiento local anterior a la actualización y un upstream de funciones que no pueda funcionar. El inicio de sesión OAuth resuelve una cuenta no verificada en lugar de responder `local-account-unverified`, el servidor MCP ya no envía `REBASE_TOKEN` a la aplicación, y los tipos generados eliminan la clave de un belongsTo con `excludeFromApi`. En Rebase Cloud, se retiran `rebase cloud webhooks` y `--scale-to-zero true`, y es posible que sea necesario volver a crear los tokens antiguos. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` en una lista REST se convierte en el interruptor para el conteo detrás de `meta.total`, por lo que un filtro en una columna llamada `count` va dentro de `?where=`; `list_collections` del MCP remoto envía su listado únicamente en el bloque de texto, sin `structuredContent`; y `@rebasepro/app` ya no exporta la tabla de traducción al español `es`. Se rechazan un `OPTIONS` simple a una ruta sin controlador, colisiones de nombres de tablas al inicio, un upsert en la colección users, `page` con `offset`, una cadena vacía en un campo obligatorio y la contraseña de un administrador que no cumpla con la política de contraseñas. Las sesiones duran 30 días de inactividad por defecto, `client.cron` llama a `/api/admin/cron`, las lecturas sin conexión que no se puedan responder por completo fallan con `OFFLINE`, y se han eliminado algunas exportaciones internas y props no utilizadas. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | El renderizado SQL de `db push` y `db generate` se traslada fuera de `drizzle/` al directorio no rastreado `.rebase/sql/`, el flag `--generate` de `rebase dev` desaparece porque `dev` siempre regenera los tipos del SDK, y una edición de esquema en vivo no hace commit de SQL. Los permisos se convierten en scopes: las interfaces de administración solicitan un scope en lugar del rol de administrador, las claves de API contienen scopes en lugar de una lista de permisos y un flag `admin`, y `schema-admin` ya no es un administrador. Un valor relativo para `--collections` se lee desde donde se ejecuta el comando, se rechazan un upsert en una fila eliminada y una actualización que cambie una clave, el endpoint del MCP remoto toma los argumentos del SDK, y los sockets de realtime abiertos, los enlaces de verificación de correo electrónico, `signUp` y los códigos de recuperación de MFA cambian la forma en que tratan una sesión. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Una clave de API en una ruta anidada necesita permisos de `read` en sus padres, las variables numéricas ilegibles y las duraciones de sesión no válidas impiden el arranque, un repositorio de autenticación personalizado necesita `unlinkUserIdentity`, y las mejoras de cuenta de invitado requieren el captcha de `register`. La versión 0.22 no declara cambios incompatibles, por lo que este es un solo salto desde la 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` deja de compilar en un callback de colección — consulta a través de `context.data` — y `selectedEntities` da paso a una selección que puede representar filas que nadie ha cargado. Las versiones 0.19 y 0.20 no declaran cambios incompatibles, por lo que este es un solo salto desde la 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Once cambios incompatibles, la mayoría errores de compilación en lugar de cambios de comportamiento silenciosos. `rebase.data` desaparece en tiempo de ejecución, los rangos de dependencias peer se restringen a acentos circunflejos (carets) y la versión mínima de Node pasa a ser 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | Los paquetes de admin se renombran, los recursos se declaran en lugar de configurarse y un bundle generado antes no arrancará en un runtime actual. Las versiones 0.15 y 0.16 no rompen nada, por lo que este es un solo salto desde la 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Cada clave en tránsito pasa a ser camelCase y el inicio de sesión anónimo pasa a ser opcional (opt-in). |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | El salto más grande y el único que cambia **quién puede leer tus datos**. Elimina el esquema `auth`, renombra paquetes, cambia lo que significa `id`, descarta CJS, traslada el panel de administración a react-router 8 y corrige tres formas en las que se podía conceder acceso que no habías solicitado. |

Las secciones de cada página están en el orden en que debes aplicarlas, y cada una indica el síntoma que de otro modo intentarías depurar por el camino equivocado.

Luego, independientemente del salto que hayas realizado:

- [La lista de verificación de actualización](#upgrade-checklist) a continuación — los greps y comandos que vale la pena ejecutar después, en un solo bloque.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` es el comando que conviene integrar en CI: finaliza con un código distinto de cero si una política todavía contiene la tautología permisiva o si una política fue sustituida por un push anterior. Las lecturas de `pg_policies` antes y después siguen mereciendo el minuto que toman — te muestran las expresiones en sí, que es la única manera de detectar una política que falla abierta (fail-open) escrita de una forma que el detector no reconoce. Ni los paquetes ni el sistema de tipos te lo dirán: el cambio reside en la base de datos, y `db push` es lo único que lo aplica allí.
