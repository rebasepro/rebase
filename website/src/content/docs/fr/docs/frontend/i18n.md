## Vue d'ensemble

Chaque chaîne affichée par le panneau d'administration provient d'une clé. Sept langues sont fournies
par défaut — anglais, espagnol, allemand, français, italien, portugais et hindi — et un
projet peut surcharger n'importe quelle clé, ajouter sa propre langue ou traduire ses propres
composants en s'appuyant sur la même table.

Trois éléments réalisent ce travail :

| | |
|---|---|
| `<Rebase locale>` | la langue de départ |
| `<Rebase translations>` | la valeur de chaque clé, par locale |
| `useTranslation()` | la lecture d'une clé depuis votre propre composant |

## Choisir la langue

```tsx
<Rebase client={client} authController={authController} locale="es">
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

`locale` est la langue *initiale*. Si un utilisateur en choisit une depuis le menu
des langues, ce choix est mémorisé dans son navigateur et prend le pas sur la prop
lors de sa visite suivante — modifier `locale` dans le code n'outrepasse pas les
préférences de l'utilisateur. Toute chaîne non définie dans Rebase bascule vers l'anglais
plutôt que d'afficher une clé brute.

## Modifier le texte d'une chaîne

`translations` est indexé par locale, puis par clé. Il est partiel : indiquez simplement
la poignée de clés que vous souhaitez modifier et tout le reste demeure inchangé.

```tsx
<Rebase
    client={client}
    authController={authController}
    translations={{
        en: { save: "Publish", delete_confirmation_title: "Unpublish?" },
        es: { save: "Publicar", delete_confirmation_title: "¿Despublicar?" }
    }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

La même structure permet d'ajouter une langue non fournie par Rebase. Fournissez-lui un jeu
complet de clés et définissez `locale` en conséquence :

```tsx
<Rebase
    client={client}
    authController={authController}
    locale="nl"
    translations={{ nl: { save: "Opslaan", cancel: "Annuleren" } }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

Les clés que vous omettez basculent vers l'anglais, de sorte qu'un ensemble partiel constitue
une traduction fonctionnelle, et non cassée.

### Emplacement des clés

L'ensemble de la table est typé par `RebaseTranslations` — une interface contenant chaque clé,
ce qui permet à votre éditeur de les auto-compléter et transforme une faute de frappe en erreur de type.
Ses valeurs en anglais se trouvent dans `packages/app/src/locales/en.ts`, qui sert de référence
pour le texte réel de chaque clé.

Les noms correspondent à la zone à laquelle ils appartiennent : `save`, `cancel`, `delete_confirmation_title`
pour le panneau, `studio_*` pour les outils de développement (`studio_tool_sql`,
`studio_group_database`, `studio_backups_denied_title`).

## Traduire vos propres composants

`useTranslation()` vous donne accès à la même table que vos vues personnalisées, champs et
actions peuvent consulter :

```tsx
import { useTranslation } from "@rebasepro/app";

function PublishButton() {
    const { t } = useTranslation();
    return <Button>{t("save")}</Button>;
}
```

L'interpolation utilise la même syntaxe `{{name}}` que les chaînes intégrées :

```tsx
t("add_to_field", { fieldName: "Tags" });
```

Vos propres clés transitent par `translations` comme n'importe quelles autres — une clé que Rebase ne
déclare pas est tout de même résolue, ce qui vous permet de placer les chaînes de vos composants dans
la même table plutôt que d'exécuter une seconde stack d'i18n en parallèle.

`t` renvoie également la clé elle-même si aucune correspondance n'est trouvée, ce qui constitue une
réponse prévisible et rend visible dans l'interface utilisateur une clé manquante plutôt que d'afficher du vide.

## Les textes propres au kit d'interface utilisateur (UI kit)

Quelques chaînes appartiennent directement à `@rebasepro/ui` plutôt qu'à l'admin : "No entries found",
"All 12 entries loaded" et "Error loading data" des vues en liste et en cartes, le titre d'erreur
du tableau, les libellés de la barre de recherche et les dates relatives telles que "5m ago".
Au sein d'une application Rebase, elles proviennent des mêmes traductions (`no_entries_found`,
`all_entries_loaded`, `error_loading_data_message`, `search`, `clear_search`, `relative_*`) et suivent
la langue choisie comme toutes les autres chaînes.

Si vous utilisez le kit de manière autonome, il est en anglais jusqu'à ce que vous l'englobiez
dans un `UiLabelsProvider`. Tout libellé omis conserve sa valeur anglaise par défaut :

```tsx
import { UiLabelsProvider } from "@rebasepro/ui";

<UiLabelsProvider labels={{
    noEntriesFound: "Nessuna voce trovata",
    allEntriesLoaded: (count) => `Tutte le ${count} voci caricate`,
    relativeTime: { minutesAgo: (count) => `${count} min fa` }
}}>
    <ListView data={rows} renderRow={renderRow}/>
</UiLabelsProvider>
```

`useUiLabels()` permet de lire les libellés actifs, et `formatRelativeTime` issu de
`@rebasepro/utils` prend `labels: useUiLabels().relativeTime` pour afficher une date
de la même manière.

## Les noms de groupes ne sont pas des libellés

Le `group` d'une `AppView` est un identifiant : le panneau latéral (drawer) se replie en fonction de lui,
la page d'accueil de Studio s'ordonne selon lui, et `navigationGroupMappings` lui associe des icônes.
Le traduire là où il est déclaré casse ces trois fonctionnalités dans toutes les langues sauf
celle dans laquelle vous l'avez traduit.

Déclarez le groupe en anglais et laissez l'en-tête se traduire de lui-même — les groupes propres à
Rebase disposent de clés `studio_group_*` et sont résolus par leur nom ; un groupe personnalisé
s'affiche tel qu'il est écrit.

```tsx
// Correct : le nom est stable, l'en-tête est localisé pour les groupes intégrés.
{ slug: "queues", name: "Queues", group: "Compute", view: <QueuesView/> }
```
