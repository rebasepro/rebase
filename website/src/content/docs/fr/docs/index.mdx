## Qu'est-ce que Rebase ?

Rebase est le **backend open source pour PostgreSQL**, doté d'un **panneau d'administration** pour votre équipe, conçu avec React et TypeScript. Il vous offre tout ce dont vous avez besoin pour concevoir une application prête pour la production sur **PostgreSQL** :

- **Schema as Code** — Déclarez vos tables Postgres en TypeScript, chacune avec une politique requise de sécurité au niveau des lignes (Row-Level Security). Rebase génère les tables et leurs politiques, les points de terminaison de l'API REST, un SDK typé et une interface CRUD complète à partir de cette source unique de vérité.
- **Panneau d'administration instantané** — Un panneau moderne et rapide basé sur React avec des tables de type tableur, des listes, des formulaires, des tableaux Kanban, l'édition en ligne et la synchronisation en temps réel.
- **Backend intégré** — Authentification (mots de passe, liens magiques, codes à usage unique, MFA, clés d'API et douze fournisseurs OAuth/OIDC), stockage de fichiers (local, S3 ou GCS), Row Level Security, historique des entités et temps réel via WebSocket — tout est intégré nativement.
- **Radicalement extensible** — Si vous pouvez le concevoir avec React, vous pouvez l'ajouter à Rebase. Champs personnalisés, vues personnalisées, plugins et accès complet aux hooks internes.

:::tip
Rebase fonctionne dans les deux cas, et votre code ne change pas entre les deux. **Auto-hébergez-le** — vous contrôlez les données, le code et la machine sur laquelle il s'exécute. Ou déployez le même projet sur **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), qui est le même Rebase géré pour vous ; il est en production avec de vrais utilisateurs aujourd'hui et s'ouvre par vagues pendant sa phase de bêta privée. Voyez-le comme une alternative open source à Supabase ou Retool où c'est *vous* qui décidez qui l'opère.
:::

## Choisissez votre voie

Rebase est un backend et un panneau d'administration qui partagent un même serveur. Commencez par ce qui vous intéresse :

| Je souhaite… | Commencez ici | Ce que vous obtenez |
|---|---|---|
| **Un backend et un panneau d'administration** | [Démarrage rapide](/docs/getting-started/quickstart/) | Des tables en TypeScript, une interface CRUD générée, une API REST, l'authentification, le stockage et le temps réel |
| **Uniquement l'API, sur ma propre base de données** | [Backend uniquement](/docs/getting-started/headless/) | Une API REST headless et un SDK sur votre base PostgreSQL existante — sans panneau d'administration, sans fichiers de tables |

Aucune de ces voies n'est à sens unique : un projet headless peut intégrer un panneau d'administration en ajoutant un frontend, qui affiche chaque table desservie par le backend, et chacun peut déclarer ses tables dans `backend/schema/` lorsqu'il souhaite les gérer sous forme de code.

## Démarrage rapide

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` génère pour vous un fichier `.env` prêt à l'emploi — aucune modification nécessaire. Ensuite :

```bash
pnpm install
pnpm run dev
```

C'est tout pour la première exécution. Il n'y a aucune base de données à installer et aucune étape de schéma : si `DATABASE_URL` n'est pas définie, `rebase dev` démarre un PostgreSQL géré (PGlite) dans le répertoire du projet, génère le schéma à partir de vos tables et crée les tables au démarrage.

**Lisez les URL affichées dans la sortie.** `rebase dev` choisit un port disponible par projet plutôt que des ports fixes, ils diffèrent donc selon les projets et les machines. Le premier compte que vous enregistrez devient l'administrateur — sur votre machine. Un déploiement en production définit plutôt son administrateur avec `REBASE_ADMIN_EMAIL` et `REBASE_ADMIN_PASSWORD` (voir [Configuration](/docs/getting-started/configuration/)).

Pour utiliser plutôt votre propre base Postgres, décommentez `DATABASE_URL` dans `.env` et réexécutez `pnpm run dev`.

→ Suivez le [guide de démarrage rapide](/docs/getting-started/quickstart) complet pour un pas-à-pas détaillé, incluant la connexion à votre propre base de données.

## Fonctionnalités principales

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

| Fonctionnalité | Description |
|---------|-------------|
| **Vues Tableur** | Table virtualisée et rapide avec édition en ligne, filtrage, tri et recherche textuelle |
| **Vue Liste** | Vue sous forme de liste verticale, claire et responsive pour n'importe quelle table |
| **Tableau Kanban** | Vue tableau en glisser-déposer groupée par n'importe quelle colonne d'énumération |
| **Relations** | Un-à-un, un-à-plusieurs, plusieurs-à-plusieurs avec tables de jonction et jointures multi-niveaux |
| **Row Level Security** | Politiques RLS Postgres compilées à partir de la configuration `rls` que chaque table doit déclarer |
| **Authentification** | JWT + jetons de rafraîchissement, douze fournisseurs OAuth/OIDC, liens magiques, codes à usage unique, MFA TOTP, clés d'API restreintes, contrôle d'accès basé sur les rôles |
| **Stockage de fichiers** | Système de fichiers local, compatible S3 ou Google Cloud Storage, avec champs d'upload et navigateur de fichiers |
| **Synchronisation en temps réel** | Mises à jour en direct via WebSocket pour tous les clients connectés |
| **Historique des entités** | Journal d'audit complet pour chaque création, mise à jour et suppression |
| **API REST** | Points de terminaison CRUD générés automatiquement pour chaque table |
| **Import/Export de données** | Import CSV, JSON et Excel avec mappage de champs ; export CSV/JSON |
| **Éditeur de collections** | Éditeur visuel de schéma qui écrit votre code TypeScript dans `backend/schema` via manipulation d'AST |
| **SDK typé** | SDK JavaScript sécurisé au niveau des types pour vos applications frontend |
| **Système de plugins** | Étendez chaque partie de l'interface — barre d'outils, formulaires, champs, page d'accueil |
| **Enrichissement de données par IA** | Autocomplétion propulsée par LLM pour les champs texte |
| **Tâches Cron** | Tâches d'arrière-plan planifiées avec supervision, journalisation et tableau de bord Studio |
| **Fonctions personnalisées** | Routes Hono basées sur des fichiers, montées automatiquement avec middleware d'authentification et accès à la base de données |
| **Service d'e-mails** | SMTP intégré pour la réinitialisation de mot de passe, la vérification et les e-mails transactionnels |
| **Branches de base de données** | Copies isolées instantanées de votre base de données pour le dev, le staging ou les tests |
| **Webhooks** | Notifications sortantes signées par HMAC lors des opérations INSERT, UPDATE, DELETE |
| **Canaux de diffusion** | Canaux WebSocket pour la messagerie en temps réel entre les clients connectés |
| **Suivi de présence** | Suivez les utilisateurs en ligne et synchronisez l'état partagé entre les participants |
