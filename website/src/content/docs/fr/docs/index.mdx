## Qu'est-ce que Rebase ?

Rebase est le **backend open source pour PostgreSQL**, doté d'un **panneau d'administration** pour votre équipe, conçu avec React et TypeScript. Il vous offre tout ce dont vous avez besoin pour créer une application prête pour la production sur **PostgreSQL** :

- **Schéma as Code** — Déclarez vos tables Postgres en TypeScript, chacune avec une posture de sécurité au niveau des lignes (RLS) obligatoire. Rebase génère les tables et leurs politiques, les points de terminaison de l'API REST, un SDK typé et une interface CRUD complète à partir de cette unique source de vérité.
- **Panneau d'administration instantané** — Un panneau basé sur React, élégant et rapide, avec des vues en tableau type tableur, des listes, des formulaires, des tableaux Kanban, l'édition en ligne et la synchronisation en temps réel.
- **Backend intégré** — Authentification (mots de passe, liens magiques, codes à usage unique, MFA, clés API et douze fournisseurs OAuth/OIDC), stockage de fichiers (local, S3 ou GCS), Row Level Security, historique des entités et temps réel par WebSocket — le tout intégré nativement.
- **Radicalement extensible** — Si vous pouvez le concevoir en React, vous pouvez l'ajouter à Rebase. Champs personnalisés, vues personnalisées, plugins et accès complet aux hooks internes.

:::tip
Rebase fonctionne de l'une ou l'autre manière, et votre code ne change pas entre les deux. **Auto-hébergez-le** — vous possédez les données, le code et la machine sur laquelle il tourne. Ou déployez le même projet sur **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), qui est le même Rebase opéré pour vous ; il est déjà actif avec de vrais locataires et s'ouvre par vagues pendant sa bêta privée. Voyez-le comme une alternative open source à Supabase ou Retool où *vous* décidez de qui l'administre.
:::

## Choisissez votre approche

Rebase est un backend et un panneau d'administration qui partagent un même serveur. Commencez par ce qui vous intéresse :

| Je souhaite… | Commencer ici | Ce que vous obtenez |
|---|---|---|
| **Un backend et un panneau d'administration** | [Guide de démarrage rapide](/docs/getting-started/quickstart/) | Des tables en TypeScript, une interface CRUD générée, une API REST, l'auth, le stockage et le temps réel |
| **Uniquement l'API, sur ma propre base de données** | [Backend uniquement](/docs/getting-started/headless/) | Une API REST headless et un SDK sur votre PostgreSQL existant — sans panneau d'administration ni fichiers de tables |

Aucune des options n'est définitive : un projet headless peut intégrer un panneau d'administration en ajoutant un frontend, qui affiche chaque table servie par le backend, et chacun peut définir ses tables dans `backend/schema/` lorsqu'il souhaite les gérer sous forme de code.

## Démarrage rapide

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` génère un fichier `.env` prêt à l'emploi — aucune modification n'est nécessaire. Ensuite :

```bash
pnpm install
pnpm run dev
```

C'est tout ce qu'il faut pour la première exécution. Il n'y a aucune base de données à installer ni aucune étape de schéma : si aucun `DATABASE_URL` n'est configuré, `rebase dev` démarre un PostgreSQL géré (PGlite) dans le répertoire du projet, génère le schéma à partir de vos tables et crée les tables au démarrage.

**Consultez les URL dans la sortie de commande.** `rebase dev` choisit un port libre par projet plutôt que des ports fixes, ils diffèrent donc selon les projets et les machines. Le premier compte que vous enregistrez devient l'administrateur — sur votre machine. Un déploiement en production définit plutôt son administrateur via `REBASE_ADMIN_EMAIL` et `REBASE_ADMIN_PASSWORD` (voir [Configuration](/docs/getting-started/configuration/)).

Pour utiliser votre propre base Postgres à la place, décommentez `DATABASE_URL` dans le fichier `.env` et relancez `pnpm run dev`.

→ Suivez le [Guide de démarrage rapide](/docs/getting-started/quickstart) complet pour un pas-à-pas détaillé, y compris la méthode pour connecter votre propre base de données.

## Fonctionnalités principales

| Fonctionnalité | Description |
|---------|-------------|
| **Vues type tableur** | Tableau virtualisé et rapide avec édition en ligne, filtrage, tri et recherche textuelle |
| **Vue Liste** | Vue en liste verticale, claire et responsive pour n'importe quelle table |
| **Tableau Kanban** | Vue en tableau avec glisser-déposer, groupée par n'importe quelle colonne d'énumération (enum) |
| **Relations** | Un-à-un, un-à-plusieurs, plusieurs-à-plusieurs avec tables de jonction et jointures multi-niveaux |
| **Row Level Security** | Politiques RLS Postgres compilées à partir de la déclaration `rls` que chaque table doit définir |
| **Authentification** | JWT + jetons de rafraîchissement, douze fournisseurs OAuth/OIDC, liens magiques, codes à usage unique, MFA TOTP, clés API restreintes, contrôle d'accès basé sur les rôles |
| **Stockage de fichiers** | Système de fichiers local, compatible S3 ou Google Cloud Storage, avec champs d'upload et explorateur |
| **Synchronisation temps réel** | Mises à jour en direct via WebSocket sur tous les clients connectés |
| **Historique des entités** | Piste d'audit complète pour chaque création, modification et suppression |
| **API REST** | Points de terminaison CRUD générés automatiquement pour chaque table |
| **Import/Export de données** | Import CSV, JSON et Excel avec mappage de champs ; export CSV/JSON |
| **SDK typé** | SDK JavaScript sécurisé au niveau des types (type-safe) pour vos applications frontend |
| **Système de plugins** | Étendez chaque partie de l'interface — barre d'outils, formulaires, champs, page d'accueil |
| **Enrichissement de données par IA** | Autocomplétion assistée par LLM pour les champs textuels |
| **Tâches Cron** | Tâches de fond planifiées avec surveillance, journalisation et tableau de bord Studio |
| **Fonctions personnalisées** | Routes Hono basées sur des fichiers avec accès à la base de données, publiques par défaut : le jeton de l'appelant est lu lorsqu'il est transmis, et `requireAuth` protège une route |
| **Service d'e-mails** | SMTP intégré pour la réinitialisation de mot de passe, la vérification et les e-mails transactionnels |
| **Branching de base de données** | Copies isolées instantanées de votre base de données pour le dev, le staging ou les tests |
| **Webhooks** | Notifications sortantes signées par HMAC lors des événements INSERT, UPDATE, DELETE |
| **Canaux de diffusion** | Canaux WebSocket pour la messagerie en temps réel entre clients connectés |
| **Suivi de présence** | Suivez les utilisateurs en ligne et synchronisez l'état partagé entre les participants |
