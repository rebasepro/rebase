Chaque échec renvoyé par un backend Rebase utilise une enveloppe unique et comporte un `code` stable. Le code est l'élément sur lequel baser vos branchements conditionnels : le message est rédigé pour un humain et peut être reformulé, le statut est partagé par une douzaine de problèmes différents, alors que le code ne présente aucun de ces deux inconvénients.

## L'enveloppe

```json
{
  "error": {
    "message": "Schema drift: table \"posts\" does not exist.",
    "code": "SCHEMA_DRIFT",
    "details": { "dbCode": "42P01" },
    "requestId": "6f1b2f3e-8a0c-4d1b-9c3e-2a5b7c9d1e0f"
  }
}
```

- **`message`** — lisible par un humain. Pour un code `4xx`, il s'agit du propre message du serveur ; pour un `5xx`, il est délibérément générique, car le texte sous-jacent peut citer un hôte, un rôle ou un nom de colonne.
- **`code`** — l'une des valeurs ci-dessous. Stable d'une version mineure à l'autre.
- **`details`** — facultatif, et jamais garanti. Voir les règles ci-dessous.
- **`requestId`** — présent chaque fois que la requête est passée par le middleware de request-ID, c'est-à-dire sur toutes les routes sous `basePath`.

### `X-Request-ID`

Chaque requête sous `basePath` reçoit un identifiant : l'en-tête `X-Request-ID` de l'appelant lorsqu'il s'agit d'un UUID, sinon un nouvel identifiant généré pour l'occasion. Il est renvoyé en écho dans la réponse sous la forme `X-Request-ID`, inclus dans l'enveloppe d'erreur sous le champ `requestId`, et associé à la ligne de log du serveur correspondant à cette requête.

Il s'agit de la clé de jointure. Mentionnez-le dans un rapport de bug et un opérateur pourra retrouver l'unique ligne de log expliquant l'échec, contenant la raison qui n'a jamais été montrée au client.

Envoyer votre propre identifiant permet à une trace de traverser les sauts réseau : une passerelle ou un exécuteur de tâches qui transmet l'en-tête conserve un ID unique à travers tous les services ayant traité la requête. Une valeur invalide est ignorée plutôt que rejetée — un en-tête malformé provenant d'un appelant ne mérite pas de faire échouer une requête — ne présumez donc pas que l'ID envoyé est identique à l'ID reçu. Lisez l'en-tête de réponse.

### Ce que contient `details`

Le champ `details` a une vocation diagnostique et non contractuelle. Trois règles l'encadrent :

1. **Tout ce qu'une route définit explicitement est toujours renvoyé.** Il s'agit des erreurs propres à l'appelant décrites avec précision : quel champ de filtre était inconnu, quelle relation n'est pas modifiable, quelle valeur ne correspondait pas à son type.
2. **Les diagnostics de base de données sont épurés en production.** Lorsque l'échec provient de Postgres, `details.dbCode` — le SQLSTATE — est toujours présent : il désigne la classe du problème sans rien révéler sur les données. `dbMessage`, `detail` et `hint` ne sont ajoutés que lorsque `NODE_ENV` n'est pas `production`, car Postgres y insère le contenu des lignes. Le code `23505` renvoie `Key (email)=(a@b.c) already exists.`, ce qui répond à la question « cette personne est-elle inscrite ? » pour n'importe quelle adresse testée.
3. **Ne basez jamais vos branchements logiques sur `details`.** Basez-les sur `code`. Ce qui se trouve sous `details` correspond à ce qui était utile à un humain à cet endroit du code, et cela est sujet à changement.

## Interpréter un statut

| Statut | Ce qu'il indique sur la requête |
| --- | --- |
| `400` | Malformée, ou demandant un élément inexistant dans le schéma. Corrigez la requête. |
| `401` | Non authentifié, ou identifiant expiré. Connectez-vous ou actualisez la session. |
| `403` | Authentifié, mais non autorisé. Réessayer avec la même identité ne servira à rien. |
| `404` | Route, table ou ligne inexistante — ou ligne masquée par la sécurité au niveau des lignes (RLS). |
| `409` | Conflit avec l'état existant : un doublon ou une écriture concurrente. |
| `413` `415` `422` | Le corps est trop volumineux, le type de média est incorrect, ou la requête est rejetée sémantiquement. |
| `429` | Limite de débit atteinte (rate limit). Ralentissez ; le message indique pendant combien de temps. |
| `500` | Le serveur ou sa base de données est en faute, pas l'appelant. Consultez les logs. |
| `501` | La route existe, mais ce déploiement ne peut pas la servir — fonctionnalité désactivée ou non configurée. |
| `502` `503` `504` | Une dépendance était inaccessible, non configurée ou trop lente. |

## Authentification et comptes

| Code | Statut | Signification | Action |
| --- | --- | --- | --- |
| `AAL2_REQUIRED` | 403 | La route nécessite un second facteur et la session n'en possède qu'un. | Complétez le challenge MFA, puis réessayez. |
| `ALREADY_VERIFIED` | 400 | L'adresse ou le facteur est déjà vérifié. | Rien — l'état souhaité est déjà atteint. |
| `ACCOUNT_OUTRANKS_CALLER` | 403 | Le compte en cours de modification, de réinitialisation ou de suppression détient un rôle ou un scope que l'appelant n'a pas. `details.beyond` les énumère. | Demandez à quelqu'un qui les possède d'effectuer la modification. |
| `ANONYMOUS_AUTH_DISABLED` | 403 | La connexion anonyme est désactivée sur ce serveur. | Activez-la, ou connectez-vous avec une identité réelle. |
| `ANONYMOUS_NOT_ALLOWED` | 403 | Une session invité a tenté d'approuver une connexion d'appareil. Un invité n'a pas de compte à associer à un appareil. | Connectez-vous avec un compte, puis approuvez la demande. |
| `API_KEY_SELF_MANAGEMENT_FORBIDDEN` | 403 | Une clé d'API a tenté de lister, créer, modifier ou révoquer des clés d'API, qu'il s'agisse de son propre type ou de clés personnelles. | Gérez les clés en tant qu'utilisateur détenant `keys:write`, ou à l'aide de la clé de service. |
| `AUTH_MIDDLEWARE_MISSING` | 500 | Une route protégée a été exécutée sans middleware d'authentification Rebase en amont, les identifiants de l'appelant n'ont donc jamais été examinés. | Montez l'application via le routeur de fonctions plutôt que directement sur votre propre serveur. |
| `BOOTSTRAP_ANONYMOUS` | 403 | L'initialisation (bootstrap) du premier administrateur a été tentée par un appelant anonyme. | Connectez-vous d'abord. |
| `BOOTSTRAP_COMPLETED` | 403 | Le premier administrateur existe déjà. | Demandez à un administrateur existant d'attribuer le rôle. |
| `BOOTSTRAP_NOT_FIRST_USER` | 403 | L'initialisation est réservée au tout premier utilisateur, ce qui n'est pas le cas ici. | Demandez à un administrateur existant d'attribuer le rôle. |
| `CAPTCHA_FAILED` | 400 | Le fournisseur a rejeté le jeton CAPTCHA. | Résolvez un nouveau challenge. |
| `CAPTCHA_REQUIRED` | 400 | La route requiert un jeton CAPTCHA et aucun n'a été transmis. | Incluez le jeton. |
| `CHALLENGE_EXHAUSTED` | 401 | Trop de codes erronés saisis pour un même challenge MFA. | Démarrez un nouveau challenge. |
| `CONFIRMATION_REQUIRED` | 400 | Une opération DDL destructrice (`DELETE /api/admin/db/tables/:table` ou `DELETE …/columns/:column`) a été appelée sans `{ confirm: "<name>" }`. | Renvoyez la requête avec le nom exact de la cible dans `confirm`, ou passez `dryRun: true` pour prévisualiser le SQL. |
| `DDL_REJECTED` | 400, ou 409 si l'objet existe déjà | PostgreSQL a rejeté une instruction exécutée par `/api/admin/db/*` pour votre compte — un type, une valeur par défaut, une condition de politique, un nom déjà pris. Le message est celui de Postgres, et `details.dbCode` contient son SQLSTATE. | Modifiez l'élément mentionné dans le message et renvoyez la requête ; `dryRun: true` permet de vérifier le SQL au préalable. |
| `DEVICE_LOGIN_DECIDED` | 409 | La connexion de l'appareil a déjà été approuvée ou refusée. Une décision ne peut être prise qu'une seule fois. | Démarrez une nouvelle tentative sur l'appareil. |
| `DEVICE_LOGIN_EXPIRED` | 410 | Le délai de dix minutes pour la connexion de l'appareil a expiré avant qu'une décision ne soit prise. | Démarrez une nouvelle tentative sur l'appareil. |
| `DEVICE_LOGIN_NOT_FOUND` | 404 | Aucune connexion d'appareil ne correspond à ce code utilisateur. Le polling de l'appareil lui-même renvoie plutôt les codes en minuscules de la RFC 8628 : `authorization_pending`, `slow_down`, `access_denied`, `expired_token`, `invalid_grant`. | Comparez le code avec celui affiché sur l'appareil. |
| `EMAIL_EXISTS` | 409 | Un compte utilisant cette adresse existe déjà — lors de l'inscription, d'une modification d'adresse, ou en suivant un lien de changement d'adresse alors qu'un autre compte s'en est emparé entre-temps. | Connectez-vous, ou demandez une réinitialisation de mot de passe ; pour un changement d'adresse, choisissez-en une autre. |
| `EMAIL_NOT_CONFIGURED` | 503 | Des liens magiques ou des codes OTP ont été demandés alors que le serveur ne dispose d'aucun service d'envoi d'e-mails configuré. | Configurez SMTP, ou utilisez une autre méthode de connexion. |
| `EMAIL_NOT_VERIFIED` | 403 | Une connexion OAuth a trouvé un compte existant avec la même adresse, mais le fournisseur ne l'a pas vérifiée ; le compte n'est donc pas lié. | Connectez-vous avec la méthode existante, puis faites un `POST /auth/link/<provider>`. |
| `CSRF_REFUSED` | 403 | La protection CSRF est active (`csrf: { origin }`) et une requête dépourvue d'en-tête `Authorization` provient d'une origine non autorisée : soumission de formulaire authentifiée par cookie depuis un autre site, ou requête sans corps ni en-tête `Origin`. | Envoyez-la depuis une origine autorisée, avec un corps JSON, ou avec un en-tête `Authorization`. |
| `FACTOR_NOT_VERIFIED` | 400 | Le facteur MFA a été configuré mais n'a jamais été confirmé. | Confirmez le facteur. |
| `ID_EXISTS` | 409 | Un compte possède déjà l'identifiant que l'importation de comptes cherche à conserver (`POST /api/admin/users/import`). L'importation le signale comme `skipped` et laisse le compte tel quel. | Rien, si le compte a déjà été importé. Sinon, omettez `id` ou choisissez-en un autre. |
| `IDENTITY_ALREADY_LINKED` | 409 | Cette identité OAuth appartient déjà à un autre compte. | Connectez-vous avec celle-ci, ou dissociez-la d'abord sur l'autre compte. |
| `IMPERSONATION_FORBIDDEN` | 403 | Une requête a transmis `x-rebase-impersonate` alors que son appelant n'est pas autorisé à exécuter une requête en tant qu'autre utilisateur. Seule la session propre d'un administrateur connecté le peut, jamais une clé d'API ni la clé de service. | Envoyez-la avec une session d'administrateur, ou retirez l'en-tête. |
| `IMPERSONATION_INVALID` | 400 | L'en-tête `x-rebase-impersonate` a été envoyé vide. | Transmettez l'uid de l'utilisateur à usurper, ou retirez l'en-tête. |
| `IMPERSONATION_TARGET_NOT_FOUND` | 404 | `x-rebase-impersonate` ne désigne aucun utilisateur actif : aucun compte ne possède cet uid, ou le compte est désactivé. | Vérifiez l'uid. |
| `IMPERSONATION_UNAVAILABLE` | 501 | L'authentification de ce backend ne peut pas exécuter de requête au nom d'un autre utilisateur, car son `AuthAdapter` ne comporte pas de méthode `resolveUser`. | Implémentez `resolveUser` dans l'adaptateur, ou retirez l'en-tête. |
| `IMPERSONATION_UNSUPPORTED` | 400 | `x-rebase-impersonate` a été envoyé à une route qui ne supporte pas l'usurpation d'identité. Seules l'API de données et les fonctions personnalisées la prennent en charge, et le socket temps réel prend en charge `impersonate` lors de `AUTHENTICATE`. | Envoyez la requête sans cet en-tête. |
| `SIMULATION_FORBIDDEN` | 403 | Une requête a envoyé un en-tête `x-rebase-simulate-*` (le simulateur RLS) ou a interrogé `/api/admin/rls-simulator`, alors que son appelant n'est pas autorisé à simuler des accès. Seule la session d'un administrateur connecté le peut, jamais une clé d'API ni la clé de service. | Envoyez-la avec une session d'administrateur, ou retirez les en-têtes. |
| `SIMULATION_INVALID` | 400 | La simulation était malformée : un en-tête envoyé vide, `x-rebase-simulate-api-key-id` combiné avec un rôle ou un ID utilisateur, ou une simulation combinée avec `x-rebase-impersonate`. | Spécifiez un seul rôle (optionnellement avec un uid), un seul ID utilisateur, ou un seul ID de clé d'API. |
| `SIMULATION_READ_ONLY` | 403 | Une écriture, suppression, `_batch`, annulation d'historique ou fonction personnalisée appelée avec un verbe autre que `GET`/`HEAD`/`OPTIONS` comportait un en-tête `x-rebase-simulate-*`. Les accès simulés sont en lecture seule : l'écriture s'exécuterait avec l'identité simulée et non en tant qu'administrateur. Les lectures, y compris `POST …/query` et `…/count`, fonctionnent toujours. | Quittez le mode simulation pour apporter des modifications. |
| `SIMULATION_TARGET_NOT_FOUND` | 404 | La simulation ne désigne aucun utilisateur actif (un ID utilisateur envoyé sans rôle) ou aucune clé d'API active. | Vérifiez l'identifiant, ou envoyez un rôle avec l'uid pour simuler un uid sans compte associé. |
| `SIMULATION_UNAVAILABLE` | 501 | Ce backend ne peut pas simuler d'accès : son `AuthAdapter` n'a pas de `resolveUser` pour valider un administrateur, ou une clé a été ciblée sur un backend sans clés d'API. | Implémentez `resolveUser`, ou retirez les en-têtes. |
| `SIMULATION_UNSUPPORTED` | 400 | Un en-tête `x-rebase-simulate-*` a été envoyé à une route qui ne prend pas en charge les accès simulés. Seules l'API de données et les fonctions personnalisées les honorent. | Envoyez la requête sans ces en-têtes. |
| `GUEST_REFERENCED` | 409 | Un invité n'a pas pu être supprimé car une ligne propre au projet en a besoin via une clé étrangère avec `ON DELETE RESTRICT` ou `NO ACTION`. `DELETE /api/admin/guests` le signale pour chaque invité dans `skipped` et poursuit son exécution. | Supprimez la ligne concernée, ou conservez l'invité. |
| `INVALID_ACCOUNT` | 400 | Le compte est dans un état qui ne permet pas d'exécuter cette opération. | Consultez le message d'erreur. |
| `INVALID_CHALLENGE` | 400 | Le challenge MFA est inconnu ou a expiré. | Démarrez-en un nouveau. |
| `INVALID_CODE` | 400 / 401 | Le code OTP ou MFA est incorrect : 400 pour la connexion par code envoyé par e-mail (`/auth/otp/verify`), 401 pour l'enrôlement ou la validation d'un challenge MFA. | Réessayez avec le code en cours de validité. |
| `INVALID_CREDENTIALS` | 401 | E-mail ou mot de passe incorrect — sans préciser délibérément lequel. | Réessayez, ou réinitialisez le mot de passe. |
| `INVALID_PLATFORM_TOKEN` | 401 | Un jeton de plateforme `rpt_` a été refusé : signature invalide, mauvaise audience, expiré, ou durée de vie dépassant le plafond. Le message en précise la cause. | Demandez à la plateforme d'en générer un nouveau — sur Rebase Cloud, réexécutez la commande. |
| `INVALID_SCOPES` | 400 | Une clé a requis un élément qui n'est pas un scope : malformé, inconnu, ou assorti d'une cible non acceptée. `details.problems` en précise la cause ; `details.validScopes` liste les scopes qu'une clé peut détenir. Sont exclus `keys:read` et `keys:write`, qu'aucune clé ne peut détenir. | Utilisez un nom figurant dans la liste. Voir [Rôles et scopes](/docs/backend/roles-and-scopes/). |
| `INVALID_TOKEN` | 400 / 401 | Un jeton de vérification, de réinitialisation, de lien magique ou de changement d'adresse est malformé, inconnu, déjà utilisé ou expiré (400). Un identifiant de fournisseur OAuth ou un jeton de rafraîchissement non valide renvoie un 401. | Demandez un nouveau lien, ou reconnectez-vous. |
| `INVALID_USER_CODE` | 400 | Ce qui a été envoyé comme code de connexion d'appareil n'en est pas un : il doit comporter huit lettres, comme `BCDF-GHJK`. | Recopiez le code affiché sur l'appareil. |
| `INVALID_PASSWORD_HASH` | 400 | Le `passwordHash` d'un compte importé ne correspond pas au format spécifié par `passwordHashAlgorithm` : pour `bcrypt`, `$2a$`, `$2b$` ou `$2y$`, un coût de 04 à 31, suivi de 53 caractères. Un mot de passe en clair dans cette colonne en est la cause la plus fréquente. | Exportez la colonne dans laquelle l'autre système stocke le hachage (Supabase : `auth.users.encrypted_password`), ou omettez-la afin que le compte puisse se connecter par lien magique ou réinitialisation. |
| `INVALID_ID` | 400 | L'identifiant `id` d'un compte importé n'est pas autorisé : vide, supérieur à 128 caractères, contient des caractères autres que des lettres, chiffres et `_ - . : \|`, identifiant réservé (`service`, `anonymous`), ou valeur incompatible avec la colonne id de la table users (autre qu'un uuid pour une colonne `uuid`). | Corrigez l'identifiant, ou omettez-le pour laisser la table en générer un. |
| `INVALID_ROLE` | 400 | Le nom de rôle saisi n'est pas une chaîne, est vide, ou contient `,` `{` `}` `"` `\` ou un caractère de contrôle. Tout autre nom est accepté. |
| `KEY_MANAGEMENT_SCOPE` | 400 | Une clé a demandé les scopes `keys:read` ou `keys:write`. Aucune clé ne peut gérer les clés. `details.scopes` les énumère. | Retirez-les. |
| `KEY_OUTRANKS_CALLER` | 403 | Un détenteur de `keys:write` a tenté de modifier ou révoquer une clé de service possédant un rôle ou un scope qu'il n'a pas. | `LAST_ADMIN` | 403 | Cette modification laisserait le projet sans aucun administrateur. | Accordez d'abord le rôle d'administrateur à un autre utilisateur. |
| `MFA_REQUIRED` | 401 | Le mot de passe était correct et le compte dispose d'un second facteur vérifié : la connexion n'est donc qu'à moitié terminée. `details` contient un jeton à courte durée de vie restreint au challenge MFA — il ne s'agit pas d'une session. | Ouvrez un challenge et répondez-y ; la réponse au challenge délivrera la session. |
| `NO_SESSION` | 401 | Aucun cookie de session ou jeton de rafraîchissement n'a été présenté. Normal lors du premier chargement d'une page. | Connectez-vous. |

## `PG_<SQLSTATE>` — une contrainte rejetée par la base de données

Une écriture que Postgres rejette pour une raison liée aux *données de l'appelant* répond avec le SQLSTATE directement dans le code : `PG_23505`, `PG_23503`, etc. Il s'agit d'une famille de codes et non d'une liste finie — Postgres définit des centaines de SQLSTATE — mais seules deux classes sont susceptibles d'apparaître ici, étant les seules imputables aux données envoyées par l'appelant :

- **classe 23**, violation de contrainte d'intégrité : un doublon, une clé étrangère pointant vers une ressource inexistante, une colonne NOT NULL laissée vide ;
- **classe 22**, exception de données : une valeur incompatible avec le type de la colonne.

Tout le reste — coupure de connexion, colonne manquante, problème de droits — relève du serveur et conserve un code `500`. Dès lors, le test `code.startsWith("PG_")` permet d'identifier à coup sûr que « la ligne envoyée était incorrecte », les quatre ci-dessous étant ceux réellement rencontrés par un client. `details.dbCode` contient le même SQLSTATE pour chacun d'eux, et le message cite la contrainte concernée.

| Code | Statut | Signification | Action |
| --- | --- | --- | --- |
| `PG_22P02` | 400 | Une valeur n'a pas pu être convertie dans le type de la colonne — le pendant à l'écriture de `INVALID_FILTER_VALUE`. | Envoyez une valeur conforme au type de la colonne. |
| `PG_23502` | 400 | Une colonne marquée `NOT NULL` est restée vide. | Renseignez le champ, ou attribuez une valeur par défaut à la colonne. |
| `PG_23503` | 400 / 409 | À l'enregistrement, une clé étrangère pointe vers une ligne inexistante (400). À la suppression, d'autres lignes dépendent encore de celle-ci (409 ; une clé en `RESTRICT` déclenche `PG_23001`, également 409). | Créez d'abord la ligne cible ou corrigez l'identifiant ; pour une suppression, supprimez ou redirigez au préalable les lignes qui y font référence. |
| `PG_23505` | 409 | Violation d'une contrainte d'unicité. Le message précise le nom de la contrainte. | Utilisez une valeur différente, ou mettez à jour la ligne existante. |

`/reconcile/apply`. Un refus ne modifie rien ; seul `SCHEMA_RECONCILE_FAILED`
peut laisser un plan partiellement appliqué.

| Code | Statut | Signification | Action |
| --- | --- | --- | --- |
| `INVALID_RECONCILE` | 400 | Le corps n'est pas un objet JSON, ou `drop` n'est pas une liste de chaînes au format `"<table>.<column>"`. | Envoyez `{ "drop": ["voice_cache.wav"] }`, ou omettez `drop`. |
| `SCHEMA_RECONCILE_FAILED` | 400 | Une instruction a échoué en cours d'exécution. Les instructions précédentes ont bien été exécutées et restent appliquées ; `details.applied` les énumère. | Corrigez l'erreur signalée dans le message, puis relancez la planification : le nouveau plan exclura ce qui a déjà été appliqué. |
| `SCHEMA_RECONCILE_INVALID` | 400 | Le plan ne peut pas être appliqué, le message en détaillant les raisons : un `drop` qui n'est pas sous la forme `<table>.<column>`, qui ne mentionne pas de table/colonne valide, ou qui vise une colonne toujours déclarée dans la table. `details.plan` contient le plan. | Corrigez la liste `drop`. ### Pourquoi la table d'une branche ne peut pas être fusionnée

`BRANCH_MERGE_BLOCKED` indique chaque table rejetée dans `details.tables`, avec l'un
de ces codes. Ce même code figure sous l'attribut `blocked` de la table au sein du diff,
permettant à Studio de l'indiquer avant même qu'un utilisateur ne clique sur **Fusionner**.
Aucun ne constitue une réponse HTTP autonome.

| Code | Statut | Signification | Action |
| --- | --- | --- | --- |
| `COLUMNS_DIFFER` | — | Les colonnes de la table divergent entre la branche et son parent. La comparaison des lignes s'opère sur les colonnes communes. | Ajoutez les colonnes manquantes sur le parent avec vos migrations (`rebase db push`), puis procédez à la fusion. Une migration qui réécrit la table (changement de type de colonne) la fait passer en `TABLE_REWRITTEN` : fusionnez avant une telle opération, ou recréez la branche après coup. |
| `NO_PRIMARY_KEY` | — | La table n'a pas de clé primaire, les lignes ne peuvent donc être associées une à une ; le diff ne présente que le nombre total de lignes. | Attribuez une clé primaire à la table, ou déplacez ses lignes à la main. |
| `PRIMARY_KEY_DIFFERS` | — | Les colonnes de la clé primaire ou leurs types diffèrent entre les deux environnements. | Appliquez d'abord le schéma sur le parent. |
| `TABLE_ADDED` | — | La branche a créé la table. Une fusion ne crée jamais de table. | Créez-la d'abord sur le parent avec vos migrations, puis fusionnez ses lignes. |
| `TABLE_DROPPED` | — | La branche a supprimé la table. Une fusion ne supprime jamais de table. | Supprimez-la au moyen de vos migrations. |
| `TABLE_REWRITTEN` | — | L'un des côtés a réécrit l'intégralité des lignes de la table après la création de la branche — changement de type de colonne, `ADD COLUMN` avec valeur par défaut volatile, `VACUUM FULL`, `CLUSTER` — chaque ligne apparaît donc comme modifiée depuis, rendant impossible la distinction des changements respectifs. | Fusionnez la branche avant une telle migration, ou recréez la branche depuis le parent après son passage. |
| `TOO_LARGE` | — | La table contient plus de lignes d'un côté que le seuil maximal de comparaison ligne à ligne d'un diff (100 000 par défaut, `maxRowsPerTable`). | Augmentez `maxRowsPerTable` à la fois sur le diff et la fusion, ou déplacez les lignes par un autre moyen. |

## Codes génériques

Une route utilise l'un de ces codes lorsque rien de plus précis ne correspond.

| Code | Statut | Signification | Action |
| --- | --- | --- | --- |
| `BAD_REQUEST` | 400 | Requête malformée, sans code plus spécifique applicable. | Consultez le message d'erreur. |
| `UNAUTHORIZED` | 401 | Non authentifié, ou identifiant rejeté. | Connectez-vous ou rafraîchissez vos accès. |
| `FORBIDDEN` | 403 | Authentifié, mais action non autorisée. | Réessayer avec la même identité ne débloquera pas la situation. |
| `CONFLICT` | 409 | Conflit avec l'état existant des données. | Consultez le message d'erreur. |
| `INTERNAL_ERROR` | 500 | Un problème est survenu côté serveur. Le message est volontairement générique. | Transmettez le `requestId` ; l'explication détaillée figure dans les logs. |
| `NOT_CONFIGURED` | 503 | Une dépendance requise par cette route n'est pas configurée sur ce serveur. | Consultez le message d'erreur. |
| `SERVICE_UNAVAILABLE` | 503 | Un service dont dépend la requête est injoignable : bucket S3 ou MinIO, ou hôte ciblé par le `fetch()` d'une fonction refusant la connexion ou introuvable sur le réseau. Le log du serveur indique le nom d'hôte ; la réponse client ne le précise pas. Une base inaccessible renvoie `DATABASE_UNAVAILABLE`. Tout échec de connexion à un tel service tiers renvoie ce code. | Réessayez ; consultez les logs. |

## Maintenir l'exactitude de cette page

La commande `pnpm verify:docs` échoue si un code pouvant être émis par le serveur
est manquant dans ces tableaux, si un tableau liste un code qui ne peut jamais être émis,
si les statuts d'une ligne ne correspondent pas exactement à ceux avec lesquels le code est émis dans les sources,
ou si une famille de codes comme `PG_<SQLSTATE>` ne comporte pas de ligne pour un SQLSTATE
réellement rencontré par les appelants. L'étape de contrôle est définie dans
`tooling/scripts/docs-verify/check-error-codes.mjs`.

Ce script effectue d'abord son propre auto-test. L'analyse inspectant les codes dans le TypeScript plutôt que sur un serveur en fonctionnement, ses angles morts sont silencieux par conception : il arrivait par le passé qu'il ignore un code encapsulé dans un wrapper d'une ligne, ou placé après un message contenant une parenthèse `)`, affirmant alors à tort que « tous les codes émis par le serveur sont documentés » sur une page où il en manquait dix-sept. Désormais, le script teste une fixture présentant précisément ces cas particuliers avant d'analyser cette page, et refuse de rendre son verdict s'il ne parvient pas à les détecter.
