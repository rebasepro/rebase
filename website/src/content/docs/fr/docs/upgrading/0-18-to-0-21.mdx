# Mise à niveau 0.18 → 0.21

**La version 0.21.0 est disponible.** Voici les entrées `### Breaking` de sa
[section du journal des modifications](/docs/changelog/), une par une, avec les changements
que chacune requiert. Les versions 0.19 et 0.20 n'apportent aucun changement cassant,
il s'agit donc d'une seule étape depuis la 0.18 — lisez ceci avant de passer à la 0.21, pas après.

Les deux sont des erreurs de compilation plutôt que des changements de comportement silencieux : le build pointe
chaque ligne nécessitant une modification, et le grep sous chaque section les trouve
avant le build.

---

## 31. `context.client.data` ne compile plus dans un callback de collection

`RebaseCallContext["client"]` est désormais `RebaseCallbackClient` : `RebaseClient`
sans `data`. Côté serveur, ce client est le singleton `rebase`, qui n'a plus
de `data` depuis la 0.18, de sorte que `context.client.data.collection(…)` compilait puis
levait `Cannot read properties of undefined (reading 'collection')` à chaque
appel. C'est maintenant une erreur de compilation à la place.

**Ce qu'il faut changer :** faites vos requêtes via `context.data`, l'accesseur que les requêtes
d'un callback ont toujours été censées utiliser. Il s'exécute avec les privilèges de l'entité
qui a déclenché le callback, au sein de la transaction d'écriture elle-même. Le
[guide des callbacks](/docs/collections/callbacks/) détaille ce à quoi chaque accesseur sur le
contexte a accès.

```diff lang="ts"
 afterSave: async ({ context }) => {
-    await context.client.data.audit_logs.create({ action: "approved" });
+    await context.data.audit_logs.create({ action: "approved" });
 }
```

```bash
grep -rn "client\.data\b" config
```

`context.client.dataAsAdmin` reste disponible pour un callback qui doit accéder à ce qu'un
administrateur peut voir. `admin.browserCallbacks` change également : l'ancienne syntaxe y fonctionnait,
car le client du panneau inclut `data`, et elle ne compile plus non plus.
`useRebaseContext().client` dans un composant React conserve son `data`.

## 32. `selectedEntities` a disparu : une sélection correspond à des lignes ou à une requête

Une vue de collection peut désormais sélectionner chaque ligne correspondant à son filtre, pas seulement
les lignes qu'elle a chargées, donc `SelectionController` ne renvoie plus un
`Entity[]`. `selectionController.selection` est une union `EntitySelection` :
`{ type: "entities", entities }` pour les lignes cochées manuellement, ou
`{ type: "query", query, excluded, count? }` pour chaque ligne correspondant à une requête,
dont la plupart n'ont pas été lues.

**Ce qu'il faut changer :** une action personnalisée qui lit la sélection la transforme en lignes
avec `resolveSelection` de `@rebasepro/cms`. Elle renvoie immédiatement les lignes cochées,
et lit une sélection par requête une page à la fois — avec un callback de progression
optionnel — en levant une erreur plutôt qu'en retournant un préfixe lorsque la requête correspond à plus
de 20 000 lignes.

```diff lang="tsx" no-verify
 const handlePublish = async () => {
-    for (const entity of selectionController.selectedEntities) {
+    const selected = await resolveSelection({
+        selection: selectionController.selection,
+        accessor: data.collection(path)
+    });
+    for (const entity of selected) {
         await data.collection(entity.path).update(entity.id, { status: "published" });
     }
 };
```

```bash
grep -rn "selectedEntities" config frontend
```

Trois ajustements mineurs l'accompagnent :

- `selectionController.selectedEntities.length` → `selectionController.selectedCount`.
  Il vaut `undefined`, jamais 0, lorsque chaque ligne correspondant à une requête est sélectionnée et
  que la collection ne peut pas être dénombrée — gérez ce cas lors du rendu, ne lui donnez pas de valeur par défaut.
- `setSelectedEntities(prev => …)` → `setSelection(prev => …)`, qui reçoit
  et retourne un `EntitySelection`. `setSelectedEntities(rows)` avec un tableau
  continue de fonctionner.
- Pour vérifier si « quelque chose est sélectionné », utilisez `selectionController.hasSelection`.

`isEntitySelected` et `toggleEntitySelection` restent inchangés, et sont ce qu'une
case à cocher par ligne doit continuer à utiliser. L'
[exemple d'actions de collection](/docs/frontend/entity-actions/#collection-actions)
présente le modèle complet.
