# Imports déplacés en 0.31

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

Les packages du noyau décrivent uniquement les tables ; ainsi, ce qui décrit une collection telle qu'affichée par le panneau d'administration a été déplacé vers `@rebasepro/cms-types`, et les outils de migration d'élévation vers `@rebasepro/common/migrate` ([section 135 du guide de mise à niveau](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

`rebase migrate sdk-calls` (qui fait partie de `rebase migrate collections-to-tables`) déplace chaque import ci-dessous vers son nouveau package — fusionné dans un import existant de ce package si le fichier en comporte déjà un, tout en conservant `import type`, les `type` inline et les alias `as` — et ajoute le package aux dépendances du package de workspace concerné ; exécutez `pnpm install` ensuite. Un import d'un nom supprimé, un import d'espace de noms (namespace import), un `export *`, un `import()` dynamique ou un `require()` utilisant un nom déplacé constitue une étape manuelle numérotée.

Cette liste est générée à partir de `tooling/scripts/headless-guard/moved-symbols.json`, la table lue par le codemod. Consultez [`rebase migrate`](/docs/cli/schema/#rebase-migrate) pour la commande, et [Personnaliser une table](/docs/frontend/customize-table/) pour savoir où les types du panneau sont utilisés.
