Une colonne de type tableau (array) est une liste que le formulaire répète. Une colonne `jsonb` est un document : le
CMS génère un formulaire pour celui-ci lorsque la colonne décrit sa structure avec
[`json.*`](/docs/schema/json/), et propose une édition clé/valeur libre dans le cas
contraire.

```ts
// backend/schema/pages.ts
import { defineTable, col, json } from "@rebasepro/server/schema";

export const pages = defineTable("pages", {
    columns: {
        id:       col.uuid().primaryKey().defaultRandom(),
        tags:     col.text().array(),
        settings: col.jsonb().$type<{ theme?: "light" | "dark"; pinned?: boolean }>(),
        address:  col.jsonb(json.object({
            street: json.string().required(),
            city:   json.string(),
            zip:    json.string(),
        })),
        body:     col.jsonb(json.array(json.oneOf({
            paragraph: json.string(),
            image:     json.storage({ path: "pages/images/", accept: ["image/*"] }),
            quote:     json.object({ text: json.string().required(), author: json.string() }),
        }))),
    },
    rls: "admin-only",
});
```

## Tableaux

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

Une colonne de type tableau (`col.text().array()`) est une liste répétable du champ de l'élément : ci-dessus, `tags`
est une liste de champs de texte. `.validate({ minItems, maxItems, uniqueItems })` sur
le tableau définit le nombre d'éléments que le formulaire accepte.

<FieldWidgetPreview client:only="react" variant="repeat" />

Un tableau d'un ensemble fermé, `col.text({ enum: [...] }).array()`, est plutôt une
sélection multiple ; voir [ensembles fermés](/docs/collections/properties/#closed-sets-of-values).
Une colonne `col.storage().multiple()` est un téléversement de fichiers multiples ; voir
[Téléversements de fichiers](/docs/collections/file-uploads/#several-files).

## Documents avec une structure

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

`col.jsonb(json.object({ … }))` est un groupe de champs, un par clé, chacun correspondant au champ
demandé par son constructeur `json.*` : `json.string()` un champ texte, `json.number()` un
nombre, `json.date()` un sélecteur de date, `json.storage()` un champ de téléversement. Une
clé `.required()` est obligatoire dans le formulaire, et un `.default()` préremplit le formulaire
d'un nouvel enregistrement.

<FieldWidgetPreview client:only="react" variant="group" />

`json.array(of)` répète son élément. Un tableau de `json.oneOf({ … })` est un éditeur de
blocs : chaque variante est un type de bloc qu'un utilisateur peut ajouter, réorganiser et supprimer.
Ci-dessus, `body` contient des paragraphes, des images et des citations.

<FieldWidgetPreview client:only="react" variant="block" />

Un `json.oneOf` utilisé seul, en dehors d'un tableau, ainsi que `json.unknown()` ne disposent
d'aucun champ structuré : ils sont édités sous forme de JSON libre.

## Documents sans structure

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

`col.jsonb().$type<T>()` type le document pour TypeScript, mais `T` est effacé lors de l'exécution
du code, de sorte que le serveur et le CMS n'en savent rien. Ci-dessus, `settings` est
édité sous forme de paires clé/valeur libres. Donnez à la colonne une structure `json.*`
lorsque le CMS doit afficher un formulaire pour celle-ci.

## Personnalisation des éléments et des clés imbriquées

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

```tsx
// frontend/src/cms/pages.tsx
import { customizeTable } from "@rebasepro/cms";
import type { pages } from "../../../backend/schema/pages";

export const pagesCms = customizeTable<typeof pages>("pages", {
    fields: {
        tags: { sortable: false, of: { previewAsTag: true } },
        address: {
            spreadChildren: true,
            fieldOrder: ["zip", "city", "street"],
            fields: {
                street: { name: "Street and number" },
                zip:    { name: "Postal code", span: 1 },
            },
        },
        body: {
            expanded: true,
            oneOf: {
                paragraph: { markdown: true },
                quote:     { fields: { author: { name: "Who said it" } } },
            },
        },
    },
});
```

Sur un tableau :

| Option | Effet |
|---|---|
| `of` | Les options de chaque élément : n'importe quelle option de champ, imbriquée aussi profondément que l'élément. |
| `sortable` | Les éléments peuvent être réorganisés par glisser-déposer. |
| `canAddElements` | Des éléments peuvent être ajoutés. |
| `expanded` | Tous les éléments sont ouverts au chargement. |
| `minimalistView` | Les éléments sans leur cadre et leur en-tête. |
| `oneOf` | Pour une liste de blocs typés : les options de chaque variante, par nom de variante. |
| `enumLabels`, `enumOrder`, `storage` | Définis sur le tableau, appliqués à chaque élément. |

Sur un document :

| Option | Effet |
|---|---|
| `fields` | Les options de chaque clé, par clé ; chacune accepte toute option de champ, y compris ses propres `fields`. |
| `fieldOrder` | L'ordre dans lequel les clés sont affichées. |
| `previewFields` | Les clés affichées lorsque le document est présenté sous forme d'aperçu. |
| `spreadChildren` | Les clés sont disposées comme s'il s'agissait des propres champs de l'enregistrement. |
| `expanded` | Les clés sont ouvertes au chargement. |
| `minimalistView` | Les clés sans le cadre du document. |
| `keyValue` | Éditer sous forme de paires clé/valeur libres, même lorsque la colonne a une structure. |

`fields`, `fieldOrder` et `previewFields` sont typés selon les clés du document,
que la colonne soit définie avec `col.jsonb().$type<T>()` ou possède une structure `json.*`. Sur une
colonne `col.jsonb().$type<T>()`, cependant, le CMS n'a aucune structure à laquelle les appliquer : ils sont
ignorés, avec un avertissement en mode développement. Les options imbriquées pour une clé, une variante ou
un élément que le document ne possède pas sont ignorées de la même manière.
