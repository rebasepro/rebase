Un champ de fichier est une colonne [`col.storage()`](/docs/schema/columns/#storage-columns).
La colonne contient du texte, la clé de l'objet dans le bucket (ou son URL, si
la colonne le spécifie), et le CMS l'affiche sous la forme d'un champ de téléversement avec un aperçu.

Le fonctionnement d'un champ de stockage est divisé en deux parties, selon l'endroit où il s'exécute :

| Déclaré | Emplacement | Options |
|---|---|---|
| sur la colonne, dans `backend/schema` | lu par le serveur **et** le CMS | `path`, `source`, `accept`, `maxBytes`, `imageResize`, `public`, `fileName`, `metadata`, `includeBucketUrl`, `storeUrl` |
| dans `customizeTable`, dans `frontend/src/cms` | le navigateur uniquement | `storage.path(…)`, `storage.fileName(…)`, `storage.processFile`, `storage.postProcess`, `storage.previewUrl` |

Les options de la colonne sont sérialisables, elles transitent donc dans le descripteur
de la table et le serveur applique celles qu'il peut. Les options de `customizeTable` sont
des fonctions : elles ne peuvent pas atteindre le serveur et ne modèlent donc que les
téléversements effectués depuis le CMS.

## Un seul fichier

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

```ts
// backend/schema/listings.ts
import { defineTable, col } from "@rebasepro/server/schema";

export const listings = defineTable("listings", {
    columns: {
        id:     col.uuid().primaryKey().defaultRandom(),
        title:  col.text().notNull(),
        cover:  col.storage({ path: "listings/{id}/", accept: ["image/*"], maxBytes: "10MB",
                              imageResize: { maxWidth: 1600, format: "webp", quality: 80 } }),
        photos: col.storage({ path: "listings/{id}/gallery/", accept: ["image/*"] }).multiple(),
    },
    rls: "admin-only",
});
```

`cover` est un champ de téléversement qui accepte une image de 10 Mo au maximum,
redimensionnée à une largeur maximale de 1600 pixels et enregistrée au format WebP. Une colonne
dont l'option `accept` indique un type d'image s'affiche sous forme d'aperçu d'image, et la première
colonne de ce type remplit l'emplacement d'image de l'enregistrement dans les cartes et les listes.

## Plusieurs fichiers

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

`.multiple()` transforme la colonne en `TEXT[]` et le champ en téléversement multifichier,
réorganisable par glisser-déposer. Chaque option s'applique à chaque fichier.

## Options côté navigateur

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

```tsx
// frontend/src/cms/listings.tsx
import { customizeTable } from "@rebasepro/cms";
import type { listings } from "../../../backend/schema/listings";

export const listingsCms = customizeTable<typeof listings>("listings", {
    fields: {
        cover: {
            storage: {
                // A folder per listing title, computed in the browser.
                path: ({ values }) => `listings/${String(values.title ?? "untitled").toLowerCase()}/`,
                fileName: ({ file }) => `${Date.now()}-${file.name}`,
            },
            urlPreview: "image",
        },
        photos: {
            sortable: true,
            storage: { processFile: async (file) => file },
        },
    },
});
```

| `storage.` | S'exécute | Effet |
|---|---|---|
| `path(context)` | avant un téléversement | Le dossier de destination du fichier, remplaçant le modèle `path` de la colonne. |
| `fileName(context)` | avant un téléversement | Le nom du fichier stocké, remplaçant le modèle `fileName` de la colonne. Peut être asynchrone. |
| `processFile(file)` | avant un téléversement | Transforme le fichier (compression, suppression des métadonnées). |
| `postProcess(pathOrUrl)` | après un téléversement | Transforme le chemin ou l'URL avant son écriture dans la colonne. |
| `previewUrl(fileName)` | lors de l'affichage | L'URL pour prévisualiser un fichier stocké, lorsqu'elle ne correspond pas à la valeur du champ. |

`path` et `fileName` reçoivent le contexte du téléversement : le `file`, l'`id`
de l'enregistrement (absent lors d'un nouvel enregistrement), ses `values` telles qu'éditées,
la `propertyKey` et les règles de stockage résolues. Sur une colonne `.multiple()`, les mêmes
options `storage` sont définies directement sur le champ et s'appliquent à chaque fichier.

`urlPreview` définit la façon dont la valeur stockée est prévisualisée (`"image"`, `"video"`,
`"audio"`, `"file"`, ou `true` pour un lien), et `clearable` ajoute une commande permettant
de vider le champ.

## Ce que le serveur vérifie

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

`accept` et `maxBytes` sont appliqués par le serveur en fonction de **l'emplacement de destination
du fichier**. Le `path` d'une colonne correspond à l'endroit où vont ses fichiers, et c'est donc
également là que ses limites s'appliquent : tout téléversement dont la clé est un fichier situé
directement sous ce chemin doit les respecter, qu'il provienne du CMS, de `client.storage.putObject`,
d'un téléversement avec reprise, du navigateur de stockage de Studio ou de `curl`, qu'il nomme
la colonne ou non, sur le bucket propre à la colonne. Les espaces réservés correspondent à ce
que le CMS remplirait : `{id}`, `{rand}`, `{file}` et autres représentent un segment de chemin,
`{path}` un nombre quelconque. Le chemin d'une colonne avec `public: true` se trouve sous `public/`.

- Plusieurs colonnes partageant un même chemin : un fichier accepté par l'une d'elles est accepté.
- Un téléversement qui spécifie également sa colonne, comme le font les téléversements du CMS, est
  également soumis aux règles de cette colonne. Spécifier une colonne plus permissive ne débloque
  pas le chemin d'une colonne plus stricte.
- Une fonction `storage.path` dans `customizeTable` ne pouvant pas être lue par le serveur,
  un fichier téléversé sous le chemin qu'elle calcule n'est soumis aux limites de la colonne que si
  le téléversement spécifie la colonne, ce que font systématiquement les téléversements du CMS.
- Un chemin qu'aucune colonne ne revendique est uniquement soumis à la propre limite du bucket
  (`STORAGE_MAX_FILE_SIZE`).

`imageResize`, `processFile` et `postProcess` ont lieu dans le navigateur, avant l'envoi
des octets : un fichier téléversé d'une autre manière est stocké tel qu'il a été envoyé.

## Où un fichier peut être placé

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

`path` est une valeur par défaut, pas une limite stricte : rien sur le serveur ne confine un téléversement
à cet emplacement. Les autorisations d'écriture sont définies par des règles d'autorisation de stockage ; voir
[Stockage](/docs/backend/storage/).

## Les fichiers ne sont jamais supprimés à votre place

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

Vider un champ de fichier, remplacer son fichier ou supprimer la ligne conserve l'objet
stocké là où il se trouve. Chaque téléversement dispose de sa propre clé, un remplacement écrit
donc un nouvel objet et rien ne supprime le précédent : deux lignes pouvant contenir la même
clé, le CMS ne peut pas savoir si un fichier est inutilisé. Les objets vers lesquels aucune ligne
ne pointe restent dans le bucket et sont facturés jusqu'à ce que vous les supprimiez depuis le
navigateur de stockage de Studio, avec `client.storage.deleteObject(key)` ou à l'aide d'une
règle de cycle de vie sur le bucket. `rebase storage orphans` liste les fichiers qu'aucune
ligne ne mentionne et les supprime avec `--delete` ; voir [la CLI](/docs/cli/#rebase-storage).

## Déplacer une colonne vers un autre bucket

<span class="since-badge" data-since="0.31">Depuis 0.31</span>

Un champ de fichier stocke la clé de l'objet, pas son bucket. Modifier la `source` d'une
colonne fait pointer chaque valeur existante vers le nouveau bucket, où ces clés n'existent
pas, de sorte que les aperçus des fichiers plus anciens renvoient « introuvable ». Copiez
d'abord les objets vers le nouveau bucket sous les mêmes clés, à l'aide de
`rebase storage move --from <old> --to <new> --prefix <path>` ou des outils propres au fournisseur,
tels que `aws s3 sync` ou `gcloud storage cp`, ou conservez l'ancien bucket pour les fichiers existants.
