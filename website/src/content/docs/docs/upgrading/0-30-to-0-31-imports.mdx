# Imports that moved in 0.31

<span class="since-badge" data-since="0.31">Since 0.31</span>

The kernel packages describe tables only, so what describes a collection as the admin panel draws it moved to `@rebasepro/cms-types`, and the migration lift to `@rebasepro/common/migrate` ([section 135 of the upgrade guide](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

`rebase migrate sdk-calls` (part of `rebase migrate collections-to-tables`) moves each import below to its new package — merged into an import of that package the file already has, `import type`, inline `type` and `as` aliases kept — and adds the package to the importing workspace package's dependencies; run `pnpm install` afterwards. An import of a removed name, a namespace import, an `export *`, a dynamic `import()` or a `require()` that uses a moved name is a numbered manual step.

This list is written from `tooling/scripts/headless-guard/moved-symbols.json`, the table the codemod reads. See [`rebase migrate`](/docs/cli/schema/#rebase-migrate) for the command, and [Customizing a table](/docs/frontend/customize-table/) for where the panel's types are used.
