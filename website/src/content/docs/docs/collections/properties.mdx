## Overview

Properties define the columns in your database table and how they are rendered in the admin UI. Each property has a `type` that determines:

- The **database column type** (via Drizzle schema generation)
- The **form field** component
- The **table cell** renderer
- The **validation** rules

## Property Types

| Type | Description | PostgreSQL Column |
|------|-------------|-------------------|
| `string` | Text, select, markdown, file upload, URL, email | `varchar`, `text`, `jsonb` |
| `number` | Integer, decimal, currency | `integer`, `numeric`, `bigint`, `serial` |
| `boolean` | True/false toggle | `boolean` |
| `date` | Date, datetime, timestamp | `timestamp`, `date` |
| `array` | Ordered list of values | `jsonb` |
| `map` | Key-value object | `jsonb` |
| `geopoint` | Latitude/longitude pair | `jsonb` |
| `reference` | Embedded reference to another entity | `varchar` (stores ID) |
| `relation` | SQL foreign key relation | Uses the `relations` array |
| `vector` | Embedding, for nearest-neighbour search | `VECTOR(n)` (pgvector) |
| `binary` | Raw bytes, read and written as base64 | `bytea` |

## Common Properties

All property types share these options:

| Property | Type | Description |
|----------|------|-------------|
| `type` | `string` | **Required.** Data type (see above) |
| `name` | `string` | Display label. Defaults to the property key, prettified — `publishDate` → "Publish Date". Set it when that derivation is wrong: `"URL"` rather than "Url". |
| `description` | `string` | Help text shown below the field |
| `defaultValue` | `any` | Default value for new entities |
| `validation` | `object` | Validation rules |
| `propertyConfig` | `string` | Registered property config key |
| `columnName` | `string` | Explicit database column name (bypasses snake_case conversion) |
| `callbacks` | `PropertyCallbacks` | Hooks for `afterRead` and `beforeSave` transforms |
| `excludeFromApi` | `boolean` | Never mention this column on the API surface, in either direction — for a password hash or a verification token. The value is still written and queryable server-side; it is stripped from every row the API serves, for every caller including admins and service keys, and it is absent from the generated `Row`, `Insert` and `Update` types and from the OpenAPI schema |
| `metadata` | `Record<string, unknown>` | Anything your own code needs to hang off a property. Rebase does not read it; it survives serialization unchanged |
| `dynamicProps` | `function` | Dynamic property builder (see [Conditional fields](/docs/collections/validation-and-conditions/#conditional-fields)). **Admin form only — not enforced by the API or the database.** |
| `conditions` | `PropertyConditions` | Declarative JSON Logic conditions. **Admin form only — not enforced by the API or the database.** |

:::note[What "admin form only" means]
A few options below carry that label. They shape the form the panel draws and
nothing else: the API accepts a write that ignores them, and the column has no
constraint behind them. A rule that has to hold for every caller is a
[validation rule](/docs/collections/validation-and-conditions/) the server
checks, or a [security rule](/docs/collections/security-rules/) the database
enforces.
:::

### UI Configuration (`admin`)

UI-related options are nested under the `admin` sub-object:

```typescript
price: {
    type: "number",
    name: "Price",
    admin: {
        readOnly: true,
        columnWidth: 120,
        hideFromCollection: false
    }
}
```

| Property | Type | Description |
|----------|------|-------------|
| `admin.readOnly` | `boolean` | Prevent editing |
| `admin.disabled` | `boolean \| PropertyDisabledConfig` | Disable with optional tooltip |
| `admin.hideFromCollection` | `boolean` | Hide from table view |
| `admin.columnWidth` | `number` | Column width in pixels (table view) |
| `admin.span` | `1 \| 2 \| 3 \| 4` | Field width over the four-column form grid |
| `admin.Field` | `React.ComponentType` | Custom field component |
| `admin.Preview` | `React.ComponentType` | Custom table cell component |
| `admin.Filter` | `React.ComponentType` | Custom filter field for this property. Wins over the collection-level `Collection.FilterField` override and the built-in per-type field |
| `admin.filterOperators` | `WhereFilterOp[]` | Narrow the operators offered when filtering on this property. The offered set is the **intersection** of the engine's capabilities, the type's defaults and this list — you can only restrict, never add an operator the engine cannot run. `[]` disables filtering on the property |
| `admin.customProps` | `unknown` | Anything your own `Field` or `Preview` needs. Rebase passes it through untouched |

#### `PropertyDisabledConfig`

The object form of `admin.disabled`. The control stays visible and greyed out,
which is the difference from `admin.readOnly` — a reader can see the shape of
what they are not allowed to fill in.

| Property | Type | Description |
|----------|------|-------------|
| `disabledMessage` | `string` | Why this property is disabled, shown to the reader. Without it a greyed-out control explains nothing |
| `clearOnDisabled` | `boolean` | Set the value to `null` when the property becomes disabled, so a stale answer is not saved with the entity |
| `hidden` | `boolean` | Hide the field entirely while it is disabled, rather than greying it out |

## String Properties

The `string` type is the most versatile — depending on the options you set, it renders as different widgets.

### Text field

A basic single-line text input.

```typescript
name: {
    type: "string",
    name: "Name",
    validation: { required: true, min: 2, max: 200 }
}
```

### Multi-select

Several values out of a fixed set is an **array of an enum string**, not a flag on
one: the column holds many values, so the property that describes it is the array.
`columnType: "text[]"` is what makes it one Postgres column rather than a join.

```typescript no-verify
locales: {
    type: "array",
    name: "Available locales",
    columnType: "text[]",
    of: {
        type: "string",
        name: "Locale",
        enum: [
            { id: "es", label: "Spanish", color: "pink" },
            { id: "en", label: "English", color: "blueLight" },
            { id: "fr", label: "French", color: "purpleLight" },
        ]
    }
}
```

<FieldWidgetPreview client:only="react" variant="multi_select" />

### String Options

| Property | Type | Description |
|----------|------|-------------|
| `admin.multiline` | `boolean` | Render as textarea |
| `admin.markdown` | `boolean` | Render as markdown editor |
| `email` | `boolean` | Email format validation |
| `url` | `boolean` | URL format validation |
| `storage` | `StorageConfig` | Enable file upload — see [Storage options](#storage-options) |
| `enum` | `EnumValues` | Render as select dropdown |
| `columnType` | `"varchar" \| "text" \| "char" \| "uuid"` | The database column. Defaults to `varchar`, or `uuid` when `isId` says so. `text` for unbounded strings, `char` for fixed width |
| `isId` | `boolean \| string` | Marks the property as the primary key, and says who fills it: `"manual"` (you do), `"uuid"` (`gen_random_uuid()`), `"cuid"`, or any other string, which is used verbatim as the column's SQL default expression — `"nanoid()"`. `"increment"` is a **number** strategy and does nothing here |
| `userSelect` | `boolean` | Render as a user picker. The value is a plain string column holding the user id — nothing resolves or checks it on the way in. **Admin form only — not enforced by the API or the database.** |
| `admin.previewAsTag` | `boolean` | Render this string as a tag in previews |
| `admin.clearable` | `boolean` | Add an icon to clear the value (set to null) |
| `admin.urlPreview` | `PreviewType` | How to render a string that holds a URL: a link, or an inline image, audio or video preview. Presentation only — whether the value *is* a URL is the `url` flag on the property, which is what the OpenAPI contract is generated from |

### Storage options

Everything inside `storage`. The column itself stays a string: what is written
to it is the object's key in the bucket, or its URL if you ask for that.

| Property | Type | Description |
|----------|------|-------------|
| `storagePath` | `string \| function` | **Required.** Where in the bucket the file goes. A string with placeholders — `{file}`, `{file.name}`, `{file.ext}`, `{rand}`, `{entityId}`, `{propertyKey}`, `{path}` — or a function of the upload's context. **Admin form only — not enforced by the API or the database:** it is the panel's uploader that resolves it, and `client.storage.upload()` names its own key |
| `fileName` | `string \| function` | The uploaded object's file name, with the same placeholders. **Admin form only — not enforced by the API or the database.** |
| `storageSource` | `string` | Which registered bucket, when a project has more than one. The `bucket("media")` handle works here too. See [Storage](/docs/backend/storage) |
| `public` | `boolean` | Store under the public prefix and serve through a stable, token-less, cacheable URL. `false` by default, which means private objects and short-lived signed URLs |
| `acceptedFiles` | `FileType[]` | MIME types this property takes. The asterisk form works — `image/*` |
| `maxSize` | `number` | Largest accepted file, in bytes |
| `metadata` | `Record<string, unknown>` | Object metadata to store alongside the file |
| `includeBucketUrl` | `boolean` | Write `s3://my-bucket/path/to/file.png` into the column instead of `path/to/file.png`. `false` by default |
| `storeUrl` | `boolean` | Write the download URL into the column instead of the key. `false` by default, and worth leaving that way: a URL that carries a token stops working when the token does, and the original reference is then gone |
| `imageResize` | `ImageResize` | Resize and crop before uploading, for `image/jpeg`, `image/png` and `image/webp`. **Admin form only — not enforced by the API or the database.** |
| `processFile` | `(file: File) => Promise<File>` | Transform the file before it is uploaded. Runs in the browser. **Admin form only — not enforced by the API or the database.** |
| `postProcess` | `(pathOrUrl: string) => Promise<string>` | Transform the resolved path or URL before it is saved. Runs in the browser. **Admin form only — not enforced by the API or the database.** |
| `previewUrl` | `(fileName: string) => string` | Build the preview URL, for when the file's real address is not the field's value. **Admin form only — not enforced by the API or the database.** |

`imageResize` takes `maxWidth` and `maxHeight` in pixels, a `mode` of
`"contain"` (scale down to fit, the default) or `"cover"` (fill the bounds and
crop), a `format` of `"original"`, `"jpeg"`, `"png"` or `"webp"`, and a
`quality` between 0 and 100 for the lossy formats — 80 by default.

For buckets, signed URLs and what the server does with an upload, see
[Storage](/docs/backend/storage).

## Number Properties

```typescript
price: {
    type: "number",
    name: "Price",
    validation: { required: true, min: 0 }
}

quantity: {
    type: "number",
    name: "Quantity",
    columnType: "integer"  // Store as integer
}
```

<FieldWidgetPreview client:only="react" variant="number" />

Number fields render as a standard text input with numeric validation.

### Number Options

| Property | Type | Description |
|----------|------|-------------|
| `enum` | `EnumValues` | Render as select with numeric values |
| `columnType` | `string` | `"integer"`, `"real"`, `"double precision"`, `"numeric"`, `"bigint"`, `"serial"`, `"bigserial"`. Defaults to `integer` where `validation.integer` or `isId` says the value is whole, `numeric` otherwise |
| `isId` | `boolean \| string` | Marks the property as the primary key: `"manual"`, `"increment"` (`GENERATED BY DEFAULT AS IDENTITY`), or any other string used verbatim as the column's SQL default expression |
| `admin.clearable` | `boolean` | Add an icon to clear the value (set to null) |
| `admin.format` | `NumberFormatOptions` | Write the number out as currency, a percentage, or with fixed decimals. Omitted, the raw value renders — a number in the database is shown as the number in the database |

#### `NumberFormatOptions`

Presentation only. The stored value never changes — a rounded display is still
the full number in the column, and in the API.

| Property | Type | Description |
|----------|------|-------------|
| `style` | `"decimal" \| "currency" \| "percent"` | Defaults to `"decimal"`. `"currency"` requires `currency` |
| `currency` | `string` | ISO 4217 code — `"EUR"`, `"USD"`. Setting it implies `style: "currency"`, so the common case is one key |
| `locale` | `string` | BCP 47 tag. Defaults to the panel's locale, which is what makes the same amount read `1,234.50` for one reader and `1.234,50` for another |
| `minimumFractionDigits` | `number` | Pad to at least this many decimals — `2` writes `5` as `5.00` |
| `maximumFractionDigits` | `number` | Round to at most this many decimals. Does not change the stored value |
| `notation` | `"standard" \| "compact"` | `"compact"` renders `12000` as `12K`. Useful in a narrow table column |

    mode: "date"

### Date and time

The default mode `"date_time"` includes both date and time.

```typescript
arrival_time: {
    type: "date",
    name: "Arrival time",
    mode: "date_time"
}
```

<FieldWidgetPreview client:only="react" variant="date_time" />

### Auto timestamps

Use `autoValue` to automatically set timestamps on create or update.

```typescript
createdAt: {
    type: "date",
    name: "Created At",
    autoValue: "on_create",
    admin: { readOnly: true }
}

updatedAt: {
    type: "date",
    name: "Updated At",
    autoValue: "on_update"
}
```

### Date Options

| Property | Type | Description |
|----------|------|-------------|
| `mode` | `"date" \| "date_time"` | Date only or date + time (default: `"date_time"`). Picks the widget; the column is the same either way. **Admin form only — not enforced by the API or the database.** |
| `autoValue` | `"on_create" \| "on_update"` | Auto-set timestamps |
| `columnType` | `"timestamp" \| "date" \| "time"` | The database column. Defaults to `timestamp` **with time zone** |
| `timezone` | `string` | Which timezone the picker reads and writes the value in. **Admin form only — not enforced by the API or the database.** |
| `admin.clearable` | `boolean` | Add an icon to clear the value (set to null) |

### Block editor

Use `oneOf` to create a block editor with multiple content types. Each key creates a card type that users can pick from.

```typescript
content: {
    type: "array",
    name: "Content",
    oneOf: {
        properties: {
            text: {
                type: "map",
                properties: {
                    body: { type: "string", name: "Text", admin: { markdown: true } }
                }
            },
            image: {
                type: "map",
                properties: {
                    src: { type: "string", name: "Image", storage: { storagePath: "content" } },
                    caption: { type: "string", name: "Caption" }
                }
            }
        }
    }
}
```

### Array Options

| Property | Type | Description |
|----------|------|-------------|
| `of` | `Property \| Property[]` | Property schema for array items |
| `oneOf` | `object` | Array of typed objects with multiple discriminator types. Takes `properties`, and optionally `propertiesOrder`, `typeField` (default `"type"`) and `valueField` (default `"value"`) |
| `columnType` | `"json" \| "jsonb" \| "text[]" \| "integer[]" \| "boolean[]" \| "numeric[]"` | The database column. A primitive `of` defaults to the matching native Postgres array; anything else to `jsonb` |
| `admin.expanded` | `boolean` | Should the field be initially expanded (default: true) |

## Geopoint Properties

A latitude/longitude pair, stored as `jsonb` — `{ latitude, longitude }`, which
is what the generated TypeScript type, the OpenAPI schema and the form field all
describe.

```typescript
location: {
    type: "geopoint",
    name: "Location"
}
```

Writes take the same shape, or a `GeoPoint` from `@rebasepro/types`:

```typescript
import { GeoPoint } from "@rebasepro/types";

await client.data.venues.create({
    name: "Sagrada Família",
    location: new GeoPoint(41.4036, 2.1744)
});
```

There are no options beyond the ones every property has. Geopoint columns are
not spatially indexed and there is no distance operator to filter on — a
geopoint is a value you store and show, not one you search by. For that, model
the two numbers as columns of their own.

## Reference Properties

References link to entities in another collection. They render as a preview card showing the referenced entity's details.

```typescript
client: {
    type: "reference",
    name: "Related client",
    path: "clients",
    admin: {
        previewProperties: ["first_name", "last_name", "email"]
    }
}
```

<FieldWidgetPreview client:only="react" variant="reference" />

On Postgres a `reference` is a foreign key like any other, so it follows the same `ON DELETE` rule as a `belongsTo` relation: optional is `SET NULL`, required is `RESTRICT`. See [Relations](/docs/collections/relations).


### Reference & Relation Options

These apply to both `reference` and `relation` properties.

| Property | Type | Description |
|----------|------|-------------|
| `admin.fixedFilter` | `FilterValues` | Filter the entities offered in the selection widget |
| `admin.widget` | `"select" \| "dialog"` | Which widget selects the related entity (relations only) |
| `admin.includeId` | `boolean` | Show the related entity's id in previews (default: true) |
| `admin.includeEntityLink` | `boolean` | Show a link that opens the related entity (default: true) |
| `admin.previewProperties` | `string[]` | Which of the target's properties appear in the preview (max 3) |
| `admin.renderInForm` | `boolean` | Render a **many**-relation as a picker inside the form as well as the tab it already gets. `false` by default: the entity view already lists the related rows as a tab, so the two surfaces are redundant by construction. No effect on a to-one relation, which gets no tab |

## Vector Properties

An embedding column, for nearest-neighbour search. Postgres only.

```typescript
embedding: {
    type: "vector",
    name: "Embedding",
    dimensions: 1536
}
```

| Property | Type | Description |
|----------|------|-------------|
| `dimensions` | `number` | **Required.** Length of the vector. Compiles to `VECTOR(n)`. |
| `index` | `VectorIndexConfig \| false` | How the ANN index is built. Omitted, one HNSW index for cosine distance. `false` creates none. |

An ANN index is created with the column, so `vectorSearch` is approximate and
fast rather than an exact scan. It is built for **cosine** distance, which is
what `vectorSearch` measures with unless you pass `distance` — an index serves
exactly one operator, so an `l2` query against a cosine index quietly goes back
to scanning. `method` (`hnsw` or `ivfflat`), `distance` (one or several), `m`,
`efConstruction` and `lists` are all on `index`. Above 2000 dimensions pgvector
can build neither index type, so the column is left unindexed and the boot says
so.

Query it with [`.vectorSearch()`](/docs/sdk/aggregates-and-search#vector-search), which also
covers what pgvector needs to be installed and how to tune the index. For
ordinary btree, GIN and BRIN indexes on any collection, see
[Indexes](/docs/backend/indexes).

## Binary Properties

Raw bytes, stored as `bytea`. Values cross the API as **base64 strings** —
including `defaultValue`.

```typescript
signature: {
    type: "binary",
    name: "Signature"
}
```

Large files belong in [storage](/docs/backend/storage), not in a column: a
`bytea` is read and written whole, with the row.

Enum values, validation rules and conditional fields have a page of their own:
[Validation and conditions](/docs/collections/validation-and-conditions/).
