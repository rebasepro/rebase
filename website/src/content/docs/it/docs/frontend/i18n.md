## Panoramica

Ogni stringa visualizzata dal pannello di amministrazione proviene da una chiave. Viene fornito con
sette lingue predefinite — inglese, spagnolo, tedesco, francese, italiano, portoghese e hindi — e un
progetto può sovrascrivere qualsiasi chiave, aggiungere una propria lingua o tradurre i propri
componenti utilizzando la stessa tabella.

Il funzionamento si basa su tre elementi:

| | |
|---|---|
| `<Rebase locale>` | la lingua iniziale |
| `<Rebase translations>` | il testo associato a ciascuna chiave, per lingua |
| `useTranslation()` | la lettura di una chiave dal proprio componente |

## Scegliere la lingua

```tsx
<Rebase client={client} authController={authController} locale="es">
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

`locale` è la lingua *iniziale*. Se un utente ne seleziona una dal menu delle lingue,
tale scelta viene memorizzata nel suo browser e ha la priorità sulla prop alla
visita successiva — la modifica di `locale` nel codice non sovrascrive l'impostazione
dell'utente. Qualsiasi elemento per cui Rebase non dispone di una stringa utilizzerà come fallback
l'inglese invece di mostrare una chiave non tradotta.

## Modificare il testo di una stringa

`translations` è organizzato per lingua e poi per chiave. È parziale: basta indicare la manciata di chiavi che
si desidera modificare e tutto il resto rimarrà invariato.

```tsx
<Rebase
    client={client}
    authController={authController}
    translations={{
        en: { save: "Publish", delete_confirmation_title: "Unpublish?" },
        es: { save: "Publicar", delete_confirmation_title: "¿Despublicar?" }
    }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

La stessa struttura permette di aggiungere una lingua non inclusa nativamente in Rebase. È sufficiente fornire un set completo di chiavi
e impostare `locale` su di essa:

```tsx
<Rebase
    client={client}
    authController={authController}
    locale="nl"
    translations={{ nl: { save: "Opslaan", cancel: "Annuleren" } }}
>
    <RebaseCMS tableCustomizations={tableCustomizations}/>
    <RebaseShell title="My App"/>
</Rebase>
```

Le chiavi omesse adotteranno l'inglese come fallback, quindi un set parziale rappresenta una traduzione
funzionante, non danneggiata.

### Dove trovare le chiavi

L'intera tabella corrisponde a `RebaseTranslations` — un'interfaccia contenente tutte le chiavi, in modo che
l'editor possa completarle automaticamente e un eventuale refuso risulti in un errore di tipo. I valori in lingua inglese risiedono
in `packages/app/src/locales/en.ts`, che costituisce il riferimento ufficiale per il testo effettivo di ciascuna chiave.

I nomi seguono l'ambito a cui appartengono: `save`, `cancel`, `delete_confirmation_title`
per il pannello, `studio_*` per gli strumenti per sviluppatori (`studio_tool_sql`,
`studio_group_database`, `studio_backups_denied_title`).

## Tradurre i propri componenti

`useTranslation()` fornisce l'accesso alla stessa tabella che viste, campi e
azioni personalizzati possono leggere:

```tsx
import { useTranslation } from "@rebasepro/app";

function PublishButton() {
    const { t } = useTranslation();
    return <Button>{t("save")}</Button>;
}
```

L'interpolazione utilizza la stessa sintassi `{{name}}` delle stringhe predefinite:

```tsx
t("add_to_field", { fieldName: "Tags" });
```

Le chiavi personalizzate vengono passate tramite `translations` come qualsiasi altra — una chiave non dichiarata
da Rebase viene comunque risolta, consentendo di inserire le stringhe dei propri componenti nella stessa
tabella anziché gestire un secondo stack i18n parallelo.

Inoltre, `t` restituisce la chiave stessa quando non viene trovata alcuna corrispondenza, offrendo un riscontro
trasparente e rendendo visibile la chiave mancante nell'interfaccia utente anziché lasciare uno spazio vuoto.

## I testi del kit UI

Alcune stringhe appartengono a `@rebasepro/ui` stesso piuttosto che al pannello di amministrazione: "No entries found", "All 12 entries loaded" ed "Error
loading data" delle visualizzazioni a elenco e a schede, il titolo di errore della tabella, i nomi della barra di ricerca e le date
relative come "5m ago". All'interno di un'applicazione Rebase provengono dalle stesse
traduzioni (`no_entries_found`, `all_entries_loaded`,
`error_loading_data_message`, `search`, `clear_search`, `relative_*`) e seguono
la lingua impostata come qualsiasi altra stringa.

Utilizzando il kit in modo autonomo, questo sarà in inglese a meno che non venga avvolto da un
`UiLabelsProvider`. Qualsiasi etichetta omessa manterrà il valore predefinito in inglese:

```tsx
import { UiLabelsProvider } from "@rebasepro/ui";

<UiLabelsProvider labels={{
    noEntriesFound: "Nessuna voce trovata",
    allEntriesLoaded: (count) => `Tutte le ${count} voci caricate`,
    relativeTime: { minutesAgo: (count) => `${count} min fa` }
}}>
    <ListView data={rows} renderRow={renderRow}/>
</UiLabelsProvider>
```

`useUiLabels()` legge le etichette correntemente applicate e `formatRelativeTime` di
`@rebasepro/utils` accetta `labels: useUiLabels().relativeTime` per formattare una data
nello stesso modo.

## I nomi dei gruppi non sono etichette

La proprietà `group` di una `AppView` è un identificatore: il drawer la usa per raggruppare,
la home page di Studio la usa per ordinare e `navigationGroupMappings` la usa per associare le icone.
Tradurre questo valore nel punto in cui viene dichiarato compromette tutte e tre le funzionalità in ogni lingua diversa da
quella in cui è stato tradotto.

Dichiara il gruppo in inglese e lascia che sia l'intestazione a tradursi autonomamente — i gruppi
predefiniti di Rebase hanno chiavi `studio_group_*` e vengono cercati per nome; un gruppo personalizzato
viene visualizzato esattamente come scritto.

```tsx
// Corretto: il nome rimane stabile, l'intestazione è localizzata per i gruppi predefiniti.
{ slug: "queues", name: "Queues", group: "Compute", view: <QueuesView/> }
```
