# Aggiornare un'app esistente

Undici passaggi, dal più recente al meno recente. Inizia da quello subito sopra la versione in cui ti trovi e procedi verso il basso — oppure, se provieni dalla versione 0.12, inizia dal fondo e procedi verso l'alto.

| Sei alla versione | Leggi | Cosa comporta per te |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Non ancora rilasciata. Tutto ciò che l'admin passa al tuo codice è la riga del server con il rispettivo id accanto: `context.data` e `browserCallbacks` nel browser passano stringhe ISO e foreign key dove prima passavano oggetti `Date` e di relazione, cosa che nessun compilatore rileva; gli hook di dati `Entity` diventano interni; callback, pannelli, il pannello laterale e la selezione accettano `row` e `id` al posto di `entity` ed `entityId`; e `CollectionPanel` nomina la sua collection con `collection` e ordina con `orderBy`. La versione 0.28 non dichiara alcuna breaking change, quindi si tratta di un unico passaggio da 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Una pianificazione cron che vincola entrambi i campi del giorno viene eseguita su entrambi, quindi viene eseguita più spesso, mentre una pianificazione con un numero non valido viene rifiutata, causando l'interruzione del job. Una chiave la cui strategia `isId` non può essere soddisfatta dal suo tipo blocca l'avvio. Su Rebase Cloud, un deploy o una preview fallisce quando una funzione o un file cron non viene caricato. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Una scrittura che specifica una relazione `via` a più passaggi (multi-hop), un nome di ruolo non valido, un token di pagina nel local storage precedente all'aggiornamento e un upstream per le funzioni non funzionante vengono rifiutati. L'accesso tramite OAuth converte un account non verificato invece di rispondere `local-account-unverified`, il server MCP non invia più `REBASE_TOKEN` all'app e i tipi generati rimuovono la chiave di un belongsTo con `excludeFromApi`. Su Rebase Cloud, `rebase cloud webhooks` e `--scale-to-zero true` sono stati ritirati e i token più vecchi potrebbero dover essere ricreati. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` su un elenco REST diventa il parametro per il conteggio dietro a `meta.total`, quindi un filtro su una colonna denominata `count` va inserito all'interno di `?where=`; `list_collections` dell'MCP remoto invia il proprio elenco solo nel blocco di testo, senza `structuredContent`; e `@rebasepro/app` non esporta più la tabella di traduzione spagnola `es`. Vengono rifiutate una richiesta `OPTIONS` semplice a una route priva di handler, i conflitti di nomi di tabelle all'avvio, un upsert sulla collection degli utenti, `page` con `offset`, una stringa vuota su un campo obbligatorio e una password di amministratore che non rispetta i criteri di sicurezza. Le sessioni durano 30 giorni di inattività per impostazione predefinita, `client.cron` chiama `/api/admin/cron`, le letture offline che non possono ricevere risposta completa falliscono con `OFFLINE`, e sono state rimosse alcune esportazioni interne e prop inutilizzate. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | L'output SQL generato da `db push` e `db generate` viene spostato da `drizzle/` alla cartella non tracciata `.rebase/sql/`, il flag `--generate` di `rebase dev` è stato rimosso perché `dev` rigenera sempre i tipi dell'SDK, e una modifica dello schema in tempo reale non esegue il commit di codice SQL. I permessi diventano scope: le interfacce admin richiedono uno scope anziché il ruolo di admin, le chiavi API contengono scope invece di un elenco di permessi e di un flag `admin`, e `schema-admin` non è più un amministratore. Un percorso relativo in `--collections` viene letto a partire da dove viene eseguito il comando, un upsert su una riga cestinata e un aggiornamento che modifica una chiave vengono rifiutati, l'endpoint MCP remoto accetta gli argomenti dell'SDK, e i socket realtime aperti, i link di verifica email, `signUp` e i codici di recupero MFA modificano la gestione della sessione. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Una chiave API su un percorso annidato richiede il permesso di `read` sui suoi genitori, variabili numeriche non leggibili e durate di sessione non valide impediscono l'avvio, un repository di autenticazione personalizzato richiede `unlinkUserIdentity` e gli upgrade degli account guest richiedono il captcha di `register`. La versione 0.22 non dichiara alcuna breaking change, quindi si tratta di un unico passaggio da 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` non compila più all'interno di una callback di collection — esegui le query tramite `context.data` — e `selectedEntities` lascia il posto a una selezione che può rappresentare righe che nessuno ha ancora caricato. Le versioni 0.19 e 0.20 non dichiarano alcuna breaking change, quindi si tratta di un unico passaggio da 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Undici breaking change, per la maggior parte errori di compilazione anziché modifiche silenziose del comportamento. `rebase.data` scompare a runtime, i range delle peer dependencies si restringono ai caret, e la versione minima supportata di Node passa a 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | I pacchetti admin vengono rinominati, le risorse vengono dichiarate anziché configurate e un bundle compilato in precedenza non si avvierà su un runtime attuale. Le versioni 0.15 e 0.16 non introducono modifiche incompatibili, quindi si tratta di un unico passaggio da 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Tutte le chiavi di trasmissione sono in camelCase e l'accesso anonimo è ora opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Il passaggio più consistente e l'unico che modifica **chi può leggere i tuoi dati**. Rimuove lo schema `auth`, rinomina i pacchetti, modifica il significato di `id`, abbandona CJS, migra il pannello admin a react-router 8 e corregge tre modalità in cui potevano essere concessi accessi non richiesti. |

Le sezioni di ciascuna pagina sono ordinate in base alla sequenza in cui è necessario applicarle, e ciascuna indica il sintomo che altrimenti ti troveresti a dover diagnosticare dal punto di vista sbagliato.

Inoltre, qualunque sia il passaggio effettuato:

- [La checklist di aggiornamento](#upgrade-checklist) in basso — i comandi grep e le istruzioni utili da eseguire successivamente, raccolti in un unico blocco.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` è il comando da integrare nella CI: restituisce un codice di uscita diverso da zero in presenza di una policy che contiene ancora la tautologia permissiva o di una policy sostituita da un push precedente. Le letture di `pg_policies` prima e dopo valgono comunque il minuto speso: mostrano le espressioni effettive, l'unico modo per individuare una policy fail-open formulata con una sintassi non riconosciuta dal detector. Né i pacchetti né il sistema dei tipi lo segnaleranno: la modifica risiede nel database e `db push` è l'unico comando che la applica.
