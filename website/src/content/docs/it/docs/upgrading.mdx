# Aggiornare un'applicazione esistente

Undici passaggi, dai più recenti ai più vecchi. Inizia da quello subito sopra la versione in uso e procedi verso il basso — oppure, se provieni dalla versione 0.12, parti dal basso e procedi verso l'alto.

| Versione attuale | Leggi | Cosa comporta |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Non ancora rilasciato. Tutto ciò che l'admin passa al codice è la riga del server con il relativo ID a fianco: nel browser `context.data` e `browserCallbacks` passano stringhe ISO e foreign key dove prima passavano `Date` e oggetti di relazione, cosa che nessun compilatore rileva; gli hook di dati di `Entity` diventano interni; e callback, pannelli, il pannello laterale e la selezione accettano `row` e `id` al posto di `entity` ed `entityId`. La versione 0.28 non dichiara alcuna breaking change, quindi si tratta di un unico passaggio da 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Una pianificazione cron che vincola entrambi i campi del giorno viene eseguita su entrambi, quindi viene eseguita più spesso, mentre una pianificazione con un numero malformato viene rifiutata, arrestando l'esecuzione di quel job. Una chiave la cui strategia `isId` non può essere rispettata dal tipo blocca l'avvio. Su Rebase Cloud, un deploy o una preview fallisce quando un file di funzione o cron non viene caricato. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Vengono rifiutate le scritture che indicano una relazione `via` multi-hop, un nome di ruolo che non corrisponde a un singolo ruolo, un token di pagina nel local storage precedente all'aggiornamento e un upstream per le funzioni non valido. L'accesso OAuth finalizza un account non verificato invece di rispondere con `local-account-unverified`, il server MCP non invia più `REBASE_TOKEN` all'applicazione e i tipi generati rimuovono la chiave di un belongsTo contrassegnato con `excludeFromApi`. Su Rebase Cloud, `rebase cloud webhooks` e `--scale-to-zero true` sono dismessi, e i token meno recenti potrebbero dover essere ricreati. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` su un elenco REST diventa il selettore per il conteggio dietro a `meta.total`, quindi un filtro su una colonna denominata `count` va inserito all'interno di `?where=`; `list_collections` dell'MCP remoto invia il suo elenco solo nel blocco di testo, senza `structuredContent`; e `@rebasepro/app` non esporta più la tabella di traduzione spagnola `es`. Vengono rifiutate le richieste `OPTIONS` semplici verso una route senza gestore, i nomi di tabella in conflitto all'avvio, un upsert sulla collection users, `page` con `offset`, una stringa vuota su un campo obbligatorio e una password amministratore che non rispetta i criteri di sicurezza. Le sessioni durano per impostazione predefinita 30 giorni di inattività, `client.cron` chiama `/api/admin/cron`, le letture offline a cui non è possibile rispondere completamente falliscono con `OFFLINE`, e sono stati rimossi alcuni export interni e proprietà non utilizzate. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | L'output SQL generato da `db push` e `db generate` si sposta da `drizzle/` a `.rebase/sql/` (non tracciato da git), il flag `--generate` di `rebase dev` è stato rimosso poiché `dev` rigenera sempre i tipi dell'SDK, e una modifica dello schema in tempo reale non esegue il commit di codice SQL. I permessi diventano scope: le interfacce admin richiedono uno scope anziché il ruolo di admin, le chiavi API contengono scope invece di un elenco di permessi e di un flag `admin`, e `schema-admin` non è più un amministratore. Un percorso relativo per `--collections` viene letto a partire da dove viene eseguito il comando, un upsert in una riga cestinata e un aggiornamento che modifica una chiave vengono rifiutati, l'endpoint MCP remoto accetta gli argomenti dell'SDK, e i socket realtime aperti, i link di verifica email, `signUp` e i codici di recupero MFA modificano il modo in cui gestiscono una sessione. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Una chiave API su un percorso annidato richiede `read` sui nodi padre, variabili numeriche non leggibili e durate di sessione non valide impediscono l'avvio, un repository di autenticazione personalizzato richiede `unlinkUserIdentity` e gli upgrade degli account guest richiedono il captcha di `register`. La versione 0.22 non dichiara alcuna breaking change, quindi si tratta di un unico passaggio da 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` non compila più all'interno di una callback di collection — esegui le query tramite `context.data` — e `selectedEntities` lascia il posto a una selezione in grado di rappresentare righe che nessuno ha caricato. Le versioni 0.19 e 0.20 non dichiarano alcuna breaking change, quindi si tratta di un unico passaggio da 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Undici breaking change, per la maggior parte errori di compilazione anziché modifiche silenziose del comportamento. `rebase.data` scompare a runtime, i range delle peer dependency si restringono ai caret (^) e la versione minima di Node passa a 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | I pacchetti admin vengono rinominati, le risorse vengono dichiarate anziché configurate e un bundle compilato in precedenza non si avvierà su un runtime attuale. Le versioni 0.15 e 0.16 non introducono modifiche distruttive, quindi si tratta di un unico passaggio da 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Tutte le chiavi di trasmissione (wire keys) sono in camelCase e l'accesso anonimo diventa opt-in. |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Il passaggio più consistente, e l'unico che modifica **chi può leggere i tuoi dati**. Rimuove lo schema `auth`, rinomina i pacchetti, ridefinisce il significato di `id`, elimina CJS, sposta il pannello di amministrazione su react-router 8 e corregge tre scenari in cui l'accesso poteva essere concesso senza esplicita richiesta. |

Le sezioni di ciascuna pagina sono ordinate in base alla sequenza con cui applicare le modifiche, e ognuna indica il sintomo che altrimenti ti ritroveresti a diagnosticare dalla prospettiva sbagliata.

In seguito, indipendentemente dal passaggio effettuato:

- [La checklist di aggiornamento](#checklist-di-aggiornamento) qui sotto — i controlli tramite grep e i comandi da eseguire successivamente, raccolti in un unico blocco.

## Checklist di aggiornamento

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` è il comando da integrare nella CI: restituisce un codice di uscita diverso da zero in presenza di una policy che contiene ancora la tautologia permissiva o di una policy sostituita da un push precedente. Vale comunque la pena dedicare un minuto alle letture di `pg_policies` prima e dopo l'operazione: mostrano le espressioni effettive, che rappresentano l'unico modo per individuare una policy permissiva (fail-open) scritta con una sintassi non riconosciuta dal detector. Né i pacchetti né il type system lo segnaleranno: la modifica risiede nel database e `db push` è l'unica operazione che la applica.
