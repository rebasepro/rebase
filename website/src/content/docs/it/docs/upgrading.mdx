# Aggiornare un'app esistente

Undici passaggi, dai più recenti ai più datati. Parti da quello immediatamente successivo alla versione che stai utilizzando e procedi verso il basso — oppure, se provieni dalla versione 0.12, parti dal basso e risali.

| Versione attuale | Leggi | Cosa comporta |
|---|---|---|
| **0.27 – 0.28** | [0.27 → next](/docs/upgrading/0-27-to-next/) | Non ancora rilasciato. Tutto ciò che l'admin passa al tuo codice è la riga del server con il relativo ID a fianco: `context.data` e `browserCallbacks` del browser passano stringhe ISO e chiavi esterne dove prima passavano oggetti `Date` e di relazione, cosa che nessun compilatore rileva; gli hook dei dati `Entity` diventano interni; e callback, pannelli, il pannello laterale e la selezione accettano `row` e `id` al posto di `entity` ed `entityId`. La versione 0.28 non dichiara breaking change, quindi questo è un unico passaggio da 0.27. |
| **0.26** | [0.26 → 0.27](/docs/upgrading/0-26-to-0-27/) | Una pianificazione cron che vincola entrambi i campi del giorno viene eseguita su uno qualsiasi dei due, quindi più spesso, e una pianificazione con un numero non valido viene rifiutata, interrompendo l'esecuzione di quel job. Una chiave la cui strategia `isId` non può essere rispettata dal suo tipo blocca l'avvio. Su Rebase Cloud, un deploy o una preview fallisce quando una funzione o un file cron non si carica. |
| **0.25** | [0.25 → 0.26](/docs/upgrading/0-25-to-0-26/) | Una scrittura che fa riferimento a una relazione `via` multi-hop, un nome di ruolo che non corrisponde a un singolo ruolo, un token di pagina nel local storage precedente all'aggiornamento e un upstream per le funzioni non valido vengono rifiutati. L'accesso OAuth finalizza un account non verificato invece di rispondere con `local-account-unverified`, il server MCP non invia più `REBASE_TOKEN` all'app e i tipi generati rimuovono la chiave di un belongsTo con `excludeFromApi`. Su Rebase Cloud, `rebase cloud webhooks` e `--scale-to-zero true` sono deprecati e dismessi, e potrebbe essere necessario ricreare i token più vecchi. |
| **0.24** | [0.24 → 0.25](/docs/upgrading/0-24-to-0-25/) | `?count=` in un elenco REST diventa lo switch per il conteggio dietro `meta.total`, quindi un filtro su una colonna denominata `count` va inserito dentro `?where=`; `list_collections` dell'MCP remoto invia il suo elenco solo nel blocco di testo, senza `structuredContent`; e `@rebasepro/app` non esporta più la tabella di traduzione spagnola `es`. Una semplice richiesta `OPTIONS` verso una route senza handler, nomi di tabelle in conflitto all'avvio, un upsert sulla collection degli utenti, `page` con `offset`, una stringa vuota su un campo obbligatorio e una password di amministratore non conforme alla password policy vengono rifiutati. Le sessioni durano 30 giorni di inattività per impostazione predefinita, `client.cron` chiama `/api/admin/cron`, le letture offline a cui non è possibile rispondere completamente falliscono con `OFFLINE`, e alcune esportazioni interne e prop non utilizzate sono state rimosse. |
| **0.23** | [0.23 → 0.24](/docs/upgrading/0-23-to-0-24/) | L'output SQL generato da `db push` e `db generate` si sposta da `drizzle/` alla cartella non tracciata `.rebase/sql/`, il flag `--generate` di `rebase dev` è stato rimosso perché `dev` rigenera sempre i tipi dell'SDK, e una modifica dello schema live non esegue commit di SQL. I permessi diventano scope: le superfici di amministrazione richiedono uno scope anziché il ruolo di admin, le chiavi API contengono scope invece di un elenco di permessi e di un flag `admin`, e `schema-admin` non è più un amministratore. Un valore relativo di `--collections` viene letto dalla posizione in cui viene eseguito il comando, un upsert in una riga cestinata e un aggiornamento che modifica una chiave vengono rifiutati, l'endpoint MCP remoto accetta gli argomenti dell'SDK, e i socket realtime aperti, i link di verifica email, `signUp` e i codici di recupero MFA modificano la gestione delle sessioni. |
| **0.21 – 0.22** | [0.21 → 0.23](/docs/upgrading/0-21-to-0-23/) | Una chiave API su un percorso nidificato richiede il permesso `read` sui nodi superiori, variabili numeriche illeggibili e durate di sessione non valide impediscono l'avvio, un repository di autenticazione personalizzato richiede `unlinkUserIdentity`, e l'upgrade degli utenti guest richiede il captcha `register`. La versione 0.22 non dichiara breaking change, quindi questo è un unico passaggio da 0.21. |
| **0.18 – 0.20** | [0.18 → 0.21](/docs/upgrading/0-18-to-0-21/) | `context.client.data` non compila più all'interno di una callback di collection — esegui le query tramite `context.data` — e `selectedEntities` cede il posto a una selezione che può rappresentare righe che nessuno ha caricato. Le versioni 0.19 e 0.20 non dichiarano breaking change, quindi questo è un unico passaggio da 0.18. |
| **0.17** | [0.17 → 0.18](/docs/upgrading/0-17-to-0-18/) | Undici breaking change, per la maggior parte errori di compilazione anziché modifiche silenziose del comportamento. `rebase.data` scompare a runtime, i range delle peer dependency si restringono all'uso del caret (`^`) e il requisito minimo di Node sale a 22.22.0. |
| **0.14 – 0.16** | [0.14 → 0.17](/docs/upgrading/0-14-to-0-17/) | I pacchetti admin vengono rinominati, le risorse vengono dichiarate anziché configurate, e un bundle creato in precedenza non si avvierà su un runtime attuale. Le versioni 0.15 e 0.16 non introducono breaking change, quindi questo è un unico passaggio da 0.14. |
| **0.13** | [0.13 → 0.14](/docs/upgrading/0-13-to-0-14/) | Tutte le chiavi di rete sono in camelCase e l'accesso anonimo diventa facoltativo (opt-in). |
| **0.12** | [0.12 → 0.13](/docs/upgrading/0-12-to-0-13/) | Il passaggio più consistente, nonché l'unico che modifica **chi può leggere i tuoi dati**. Rimuove lo schema `auth`, rinomina i pacchetti, ridefinisce il significato di `id`, elimina il supporto a CJS, migra il pannello di amministrazione a react-router 8 e corregge tre scenari in cui l'accesso poteva essere concesso senza averlo richiesto. |

Le sezioni di ciascuna pagina sono disposte nell'ordine in cui devono essere eseguite le modifiche, e ognuna indica il sintomo che altrimenti ti ritroveresti a debuggare partendo dalla prospettiva sbagliata.

Successivamente, a prescindere dal passaggio effettuato:

- [La checklist di aggiornamento](#upgrade-checklist) sottostante — i comandi grep e le operazioni utili da eseguire subito dopo, riassunti in un unico blocco.

## Upgrade checklist

```
[ ] grep for authenticated() and (auth|rebase).uid() IS NOT NULL in config/collections/
[ ] decide the intent of each rule; rewrite the ones that meant "public"
[ ] replace not(authenticated()) with serverContext()
[ ] if realtime.requireAuth was true with an AuthAdapter, treat the socket as
    having been open — verify RLS on every subscribable collection (section 2)
[ ] SELECT ... FROM pg_policies — record the qual of every policy BEFORE
[ ] update package names and imports
[ ] grep for rebase.data — it is now rebase.dataAsAdmin (section 8)
[ ] grep for the other ten removed deprecated exports (section 8)
[ ] drop react-router-dom; import RouterProvider from "react-router/dom"
[ ] check node >= 22.22.0 and react >= 19.2.7 (react-router 8 requires both)
[ ] move defaultSecurityRules into config/collections/index.ts
[ ] grep for .userId
[ ] grep for row.id on tables not keyed on id
[ ] run db push
[ ] run rebase doctor --policies — expect no Insecure or Orphaned entries
[ ] SELECT ... FROM pg_policies again — confirm every intended change landed
[ ] exercise the app signed OUT, in a private window — watch the websocket too

--- 0.13 → 0.14 (part 2) ---
[ ] re-run rebase generate-sdk, then build — the compiler finds row.author_id
[ ] grep for snake_case where/orderBy keys; a stale one is a 400, not a warning
[ ] grep for raw fetch consumers reading row.<something>_id — these read
    undefined and raise nothing
[ ] if the project was introspected, re-run rebase schema introspect
[ ] decide anonymous sign-in: set auth.allowAnonymous: true, or confirm you
    never used it (grep for signInAnonymously)
[ ] drop @rebasepro/client-postgres from package.json

--- 0.14 → 0.17 (part 3) ---
[ ] rename @rebasepro/admin → @rebasepro/cms and admin-types → cms-types,
    and RebaseAdmin → RebaseCMS
[ ] move dataSources / storageSources out of the backend config into
    rebase.json and config/, then `rebase build` — an old bundle will not boot
[ ] grep collections for admin.titleProperty; it is refused at boot now
[ ] grep crons for ctx.client and for `userId` as an identity key
[ ] rename --legacy to --workspace wherever build/start is scripted
[ ] if you implement EmailService yourself, `send` must return a result
```

`rebase doctor --policies` è il comando da integrare nella CI: restituisce un exit code diverso da zero in presenza di una policy che include ancora la tautologia permissiva o di una policy sostituita da un push precedente. Le verifiche su `pg_policies` prima e dopo valgono comunque il minuto speso: mostrano le espressioni effettive, l'unico modo per individuare una policy fail-open formulata con una sintassi non riconosciuta dal detector. Né i pacchetti né il type system lo segnaleranno: la modifica risiede nel database e `db push` è l'unica operazione che la applica.
