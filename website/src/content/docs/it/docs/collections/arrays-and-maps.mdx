Una colonna array è un elenco che il modulo ripete. Una colonna `jsonb` è un documento: il
CMS genera un modulo per essa quando la colonna ne descrive la struttura con
[`json.*`](/docs/schema/json/), e offre la modifica libera di tipo chiave/valore quando
non lo fa.

```ts
// backend/schema/pages.ts
import { defineTable, col, json } from "@rebasepro/server/schema";

export const pages = defineTable("pages", {
    columns: {
        id:       col.uuid().primaryKey().defaultRandom(),
        tags:     col.text().array(),
        settings: col.jsonb().$type<{ theme?: "light" | "dark"; pinned?: boolean }>(),
        address:  col.jsonb(json.object({
            street: json.string().required(),
            city:   json.string(),
            zip:    json.string(),
        })),
        body:     col.jsonb(json.array(json.oneOf({
            paragraph: json.string(),
            image:     json.storage({ path: "pages/images/", accept: ["image/*"] }),
            quote:     json.object({ text: json.string().required(), author: json.string() }),
        }))),
    },
    rls: "admin-only",
});
```

## Array

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Una colonna array (`col.text().array()`) è un elenco ripetibile del campo dell'elemento: `tags`
nell'esempio sopra è un elenco di campi di input di testo. `.validate({ minItems, maxItems, uniqueItems })`
sull'array imposta quanti elementi accetta il modulo.

<FieldWidgetPreview client:only="react" variant="repeat" />

Un array di un insieme chiuso, `col.text({ enum: [...] }).array()`, è invece una
selezione multipla; vedi [insiemi chiusi](/docs/collections/properties/#closed-sets-of-values).
Una colonna `col.storage().multiple()` è un caricamento di più file; vedi
[Caricamenti di file](/docs/collections/file-uploads/#several-files).

## Documenti con una struttura

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

`col.jsonb(json.object({ … }))` è un gruppo di campi, uno per chiave, ciascuno corrispondente
al campo richiesto dal rispettivo builder `json.*`: `json.string()` un input di testo, `json.number()` un
numero, `json.date()` un selettore di data, `json.storage()` un campo di caricamento. Una chiave
`.required()` è obbligatoria nel modulo e un `.default()` popola il modulo per un nuovo
record.

<FieldWidgetPreview client:only="react" variant="group" />

`json.array(of)` ripete il proprio elemento. Un array di `json.oneOf({ … })` è un editor
a blocchi: ogni variante è un tipo di blocco che l'utente può aggiungere, riordinare e rimuovere.
`body` nell'esempio sopra contiene paragrafi, immagini e citazioni.

<FieldWidgetPreview client:only="react" variant="block" />

Un `json.oneOf` da solo, al di fuori di un array, e `json.unknown()` non hanno un
campo strutturato: vengono modificati come JSON libero.

## Documenti senza una struttura

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

`col.jsonb().$type<T>()` tipizza il documento per TypeScript, ma `T` viene rimosso quando il
codice viene eseguito, quindi il server e il CMS non ne sanno nulla. `settings` sopra viene
modificato come coppie chiave/valore libere. Definisci una struttura `json.*` per la colonna
quando il CMS deve visualizzare un modulo per essa.

## Personalizzazione di elementi e chiavi annidate

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

```tsx
// frontend/src/cms/pages.tsx
import { customizeTable } from "@rebasepro/cms";
import type { pages } from "../../../backend/schema/pages";

export const pagesCms = customizeTable<typeof pages>("pages", {
    fields: {
        tags: { sortable: false, of: { previewAsTag: true } },
        address: {
            spreadChildren: true,
            fieldOrder: ["zip", "city", "street"],
            fields: {
                street: { name: "Street and number" },
                zip:    { name: "Postal code", span: 1 },
            },
        },
        body: {
            expanded: true,
            oneOf: {
                paragraph: { markdown: true },
                quote:     { fields: { author: { name: "Who said it" } } },
            },
        },
    },
});
```

Su un array:

| Opzione | Effetto |
|---|---|
| `of` | Le opzioni di ciascun elemento: qualsiasi opzione di campo, con qualsiasi livello di annidamento dell'elemento. |
| `sortable` | Gli elementi possono essere riordinati tramite trascinamento. |
| `canAddElements` | Gli elementi possono essere aggiunti. |
| `expanded` | Ogni elemento è aperto al caricamento. |
| `minimalistView` | Elementi senza cornice e intestazione. |
| `oneOf` | Per un elenco di blocchi tipizzati: le opzioni di ciascuna variante, in base al nome della variante. |
| `enumLabels`, `enumOrder`, `storage` | Definiti sull'array, applicati a ciascun elemento. |

Su un documento:

| Opzione | Effetto |
|---|---|
| `fields` | Le opzioni di ciascuna chiave, per chiave; ciascuna accetta qualsiasi opzione di campo, inclusi i propri `fields`. |
| `fieldOrder` | L'ordine in cui vengono mostrate le chiavi. |
| `previewFields` | Le chiavi mostrate quando il documento viene visualizzato come anteprima. |
| `spreadChildren` | Le chiavi disposte come se fossero i campi del record stesso. |
| `expanded` | Le chiavi aperte al caricamento. |
| `minimalistView` | Le chiavi senza la cornice del documento. |
| `keyValue` | Modifica come coppie chiave/valore libere, anche quando la colonna ha una struttura. |

`fields`, `fieldOrder` e `previewFields` sono tipizzati in base alle chiavi del documento,
sia che la colonna sia `col.jsonb().$type<T>()` sia che abbia una struttura `json.*`. Tuttavia, su
una colonna `col.jsonb().$type<T>()`, il CMS non ha una struttura a cui applicarli: vengono
ignorati, con un avviso in fase di sviluppo. Le opzioni annidate per una chiave, una variante o
un elemento non presenti nel documento vengono ignorate allo stesso modo.
