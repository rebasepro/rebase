<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Ogni colonna di una tabella corrisponde a un campo nel CMS. La natura del campo
deriva dalla colonna: il suo tipo, la sua validazione e le sue regole di archiviazione,
tutte dichiarate in [`backend/schema`](/docs/schema/columns/). L'aspetto del campo
può essere personalizzato, campo per campo, in [`customizeTable`](/docs/frontend/customize-table/).

Questa tabella viene utilizzata negli esempi seguenti:

```ts
// backend/schema/products.ts
import { defineTable, col } from "@rebasepro/server/schema";

export const products = defineTable("products", {
    columns: {
        id:          col.uuid().primaryKey().defaultRandom(),
        name:        col.text().notNull().validate({ min: 2, max: 200 }),
        description: col.text(),
        body:        col.text(),
        supportEmail: col.text().validate({ email: true }),
        website:     col.text().validate({ url: true }),
        category:    col.enum(["electronics", "clothing", "home"]).notNull(),
        locales:     col.text({ enum: ["es", "en", "fr"] }).array(),
        price:       col.numeric({ precision: 10, scale: 2 }).notNull(),
        stock:       col.integer().default(0),
        onSale:      col.boolean().default(false),
        launchDay:   col.date(),
        availableAt: col.timestamp({ withTimezone: true }),
        ownerId:     col.uuid().userId(),
        createdAt:   col.timestamp({ withTimezone: true }).notNull().onCreateNow(),
        createdBy:   col.uuid().onCreateUser(),
    },
    rls: "admin-only",
});
```

Anche senza alcun file di frontend, ogni colonna ha già un campo associato.
Questa personalizzazione ne modifica alcuni:

```tsx
// frontend/src/cms/products.tsx
import { customizeTable } from "@rebasepro/cms";
import type { products } from "../../../backend/schema/products";

export const productsCms = customizeTable<typeof products>("products", {
    fields: {
        description: { multiline: true },
        body:        { name: "Product page", markdown: true },
        website:     { urlPreview: true },
        category: {
            enumLabels: {
                electronics: { label: "Electronics", color: "blueDark" },
                clothing:    { label: "Clothing", color: "pink" },
            },
            enumOrder: ["home", "electronics", "clothing"],
        },
        locales: {
            enumLabels: { es: "Spanish", en: "English", fr: "French" },
        },
        price:       { format: { style: "currency", currency: "EUR" } },
        stock:       { format: { notation: "compact" }, columnWidth: 90 },
        availableAt: { timezone: "Europe/Madrid" },
    },
});
```

## Testo

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Una colonna `col.text()`, `col.varchar({ length })`, `col.char({ length })` o `col.uuid()` è
un campo di input di testo. `varchar(n)` e `char(n)` ne limitano la lunghezza a `n`, mentre
`.validate({ min, max, length, matches })` aggiunge le regole che il form verifica prima del salvataggio.

<FieldWidgetPreview client:only="react" variant="text" />

`multiline: true` la trasforma in un'area di testo che si espande con il suo contenuto.

<FieldWidgetPreview client:only="react" variant="multiline" />

`markdown: true` la trasforma in un editor markdown con barra degli strumenti e anteprima.

<FieldWidgetPreview client:only="react" variant="markdown" />

`.validate({ email: true })` sulla colonna genera un campo di input email, validato come
tale. Trattandosi di una caratteristica del dato, viene dichiarato sulla colonna, dove
viene verificato anche dal server.

<FieldWidgetPreview client:only="react" variant="email" />

`.validate({ url: true })` genera un campo di input URL, validato come URL, con anteprima
del link. `urlPreview` modifica unicamente l'anteprima: `true` per un link, oppure `"image"`,
`"video"`, `"audio"` o `"file"` per visualizzare il contenuto multimediale inline.

<FieldWidgetPreview client:only="react" variant="url" />

Una colonna di tipo text o uuid contrassegnata con `.userId()` contiene l'id di un utente
ed è un selettore degli utenti del progetto: i loro nomi, email e avatar, mostrati a
chiunque abbia i permessi di scrittura sulla tabella. `ownerId` mostrato sopra ne è un esempio.
Lo stesso vale per ogni elemento di `col.text().userId().array()`.

`previewAsTag: true` visualizza il valore come chip al di fuori del form. `clearable:
true` aggiunge un controllo per impostarlo su `null`. `referenceTo: "<slug>"` tratta il
valore come la chiave di un record in un'altra collection, su qualsiasi origine dati, e
disegna un selettore di riferimento; vedi [Firestore](/docs/frontend/firebase/#from-a-table-to-firestore).

## Insiemi chiusi di valori

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Un `col.enum([...])` è un campo select, visualizzato altrove come chip colorato. Lo stesso
vale per una colonna di testo o numerica con `.oneOf([...])`. A ogni valore viene assegnata
un'etichetta ricavata dal suo identificatore (`needs_review` diventa "Needs Review") e un
colore generato a partire dal valore stesso, identico a ogni caricamento.

<FieldWidgetPreview client:only="react" variant="select" />

`enumLabels` definisce etichette e colori per alcuni valori; i valori non specificati
mantengono l'etichetta e il colore derivati. Ogni voce può essere una stringa o
`{ label, color?, disabled? }`: `color` è la chiave del colore del chip, come `"green"`
o `"orangeDark"`, mentre `disabled` mantiene il valore visibile ma ne impedisce la selezione.
`enumOrder` imposta l'ordine con cui i valori vengono proposti e l'ordine delle colonne kanban.
Entrambi vengono verificati rispetto alla colonna: un valore non ammesso dalla colonna
genererà un errore di tipo.

Un array di un insieme chiuso, `col.text({ enum: [...] }).array()`, è una selezione multipla
su una singola colonna `text[]`. Le `enumLabels` definite sull'array si applicano ai suoi elementi.

<FieldWidgetPreview client:only="react" variant="multi_select" />

## Numeri

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Ogni colonna di tipo integer, serial, `real`, `doublePrecision` e `numeric` è un campo di
input numerico. Le colonne integer e serial accettano solo numeri interi, e
`.validate({ min, max, moreThan, lessThan, positive, negative })` aggiunge i limiti di intervallo.

<FieldWidgetPreview client:only="react" variant="number" />

`format` formatta la visualizzazione del numero senza modificare ciò che viene memorizzato: `style`
(`"decimal"`, `"currency"`, `"percent"`), `currency` (con `"currency"`),
`locale`, `minimumFractionDigits`, `maximumFractionDigits`, e `notation:
"compact"`, che scrive `12000` come `12K` in una colonna stretta. `clearable` aggiunge un
controllo per impostare il valore su `null`.

## Date e orari

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Un `col.timestamp({ withTimezone: true })` è un selettore di data e ora, un `col.date()` un
selettore di data e un `col.time()` un'ora del giorno. `mode` consente di passare da `"date"` a
`"date_time"`, mentre `timezone` mostra e seleziona il valore in un fuso orario IANA fisso
(`"Europe/Madrid"`) anziché in quello dell'utente.

<FieldWidgetPreview client:only="react" variant="date" />

<FieldWidgetPreview client:only="react" variant="date_time" />

Una colonna con timestamp assegnato dal server, `.onCreateNow()` o `.onUpdateNow()`, è di
sola lettura, viene mostrata nel blocco dei metadati del record ed è esclusa dalle colonne
predefinite della tabella. Le colonne `.onCreateUser()` e `.onUpdateUser()` sono di sola lettura:
il server scrive l'id dell'utente che esegue l'azione, indipendentemente da quanto indicato nella richiesta.

## File

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Una colonna `col.storage({ … })` è un campo di caricamento con anteprima, e
`.multiple()` la rende un campo per file multipli. Il bucket, il percorso, i tipi
accettati e il limite di dimensione vengono dichiarati sulla colonna; le funzioni eseguite
nel browser vengono aggiunte con `storage` in `customizeTable`. Vedi
[Caricamento file](/docs/collections/file-uploads/).

<FieldWidgetPreview client:only="react" variant="file_upload" />

## Array e JSON

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Una colonna di tipo array (`<item>.array()`) è una lista ripetibile del campo dell'elemento. Una colonna `jsonb`
con una [struttura `json.*`](/docs/schema/json/) è un gruppo di campi tipizzati, liste e
blocchi; una priva di struttura è un editor chiave/valore. Vedi
[Array e JSON](/docs/collections/arrays-and-maps/).

## Relazioni e riferimenti

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Una relazione `belongsTo` è un selettore della riga correlata, mostrato al posto della
relativa colonna di chiave esterna; una relazione to-many è una scheda del record. Anche una colonna
di testo con `referenceTo` funge da selettore.

<FieldWidgetPreview client:only="react" variant="reference" />

Vedi [Relazioni nel pannello](/docs/collections/relations-in-the-admin-panel/).

## Geopoint, vettori e binari

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Un `col.geopoint()` è un campo per latitudine e longitudine. Un `col.vector({ dimensions })` è un
input vettoriale; `clearable` è la sua unica opzione. Un `col.bytea()` è un campo binario,
letto e scritto in base64. Nessuno di essi dispone di opzioni specifiche del tipo oltre a
quelle comuni a ogni campo.

## Opzioni disponibili per ogni campo

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

Indipendentemente dal tipo di colonna:

- `name` e `description` sostituiscono l'etichetta derivata e aggiungono un testo di aiuto.
- `hidden` esclude il campo dalle viste a tabella e a schede, mentre `hiddenInForm`
  lo esclude dal form. Nessuno dei due modifica ciò che l'API legge o scrive; per nascondere
  un valore a un chiamante, usa [field access](/docs/collections/field-access/).
- `readOnly` visualizza il valore come testo; `disabled` disabilita visivamente il controllo, e nella
  forma `{ disabledMessage, clearOnDisabled }` ne spiega il motivo e azzera il valore.
- `columnWidth` imposta la larghezza della colonna nella tabella; `span` definisce quante delle
  quattro colonne della griglia del form occupa il campo (vedi [Layout del form](/docs/frontend/form-layout/)).
- `filterOperators` restringe gli operatori di filtro disponibili per il campo, e
  `[]` disattiva il filtraggio su di esso. Gli operatori offerti sono il risultato dell'intersezione
  tra quelli supportati dall'origine dati, i valori predefiniti del tipo e questo elenco: è possibile
  soltanto applicare restrizioni.
- `filledByServer` consente a un'operazione di creazione di lasciare il campo vuoto, affinché venga
  popolato da un hook del server.
- `Field`, `Preview` e `Filter` sostituiscono il controllo del form, la visualizzazione esterna al
  form e il controllo del filtro con i tuoi componenti personalizzati; `customProps` viene
  passato loro intatto. Vedi [Campi personalizzati](/docs/frontend/custom-fields/).
- `propertyConfig` specifica il nome di un tipo di campo registrato su `<Rebase propertyConfigs>`.
- `conditions` e `dynamicProps` modificano il campo in base ai valori del record stesso; vedi
  [campi condizionali](/docs/collections/validation-and-conditions/#conditional-fields).
- `metadata` è a tua completa disposizione.

Tutte le opzioni, con il rispettivo tipo, sono descritte nel
[riferimento di customizeTable](/docs/frontend/customize-table/#field-options).

:::note[Solo presentazione]
Le opzioni di campo definiscono ciò che il CMS visualizza. L'API accetta operazioni di scrittura che le
ignorano e dietro di esse non c'è alcun vincolo. Ciò che deve valere per qualsiasi chiamante
appartiene alla colonna (`.notNull()`, `.validate()`, `.access()`) o alla
[row-level security](/docs/collections/security-rules/) della tabella.
:::
