## Cos'è Rebase?

Rebase è il **backend open source per PostgreSQL**, con un **pannello di amministrazione** per il tuo team, creato con React e TypeScript. Ti offre tutto il necessario per creare un'applicazione pronta per la produzione su **PostgreSQL**:

- **Schema as Code** — Dichiara le tue tabelle Postgres in TypeScript, ciascuna con una configurazione obbligatoria di row-level security. Rebase genera le tabelle e le relative policy, gli endpoint delle API REST, un SDK tipizzato e un'interfaccia utente CRUD completa a partire da quell'unica fonte di verità.
- **Pannello di amministrazione istantaneo** — Un pannello elegante e veloce basato su React con viste a foglio di calcolo, elenchi, moduli, bacheche Kanban, modifica inline e sincronizzazione in tempo reale.
- **Backend integrato** — Autenticazione (password, magic link, codici monouso, MFA, chiavi API e dodici provider OAuth/OIDC), archiviazione file (locale, S3 o GCS), Row Level Security, cronologia delle entità e real-time tramite WebSocket — tutto integrato.
- **Radicalmente estendibile** — Se puoi crearlo in React, puoi aggiungerlo a Rebase. Campi personalizzati, viste personalizzate, plugin e pieno accesso agli hook interni.

:::tip
Rebase funziona in entrambi i modi e il tuo codice non cambia tra di essi. **Esegui il self-hosting** — possiedi i dati, il codice e la macchina su cui viene eseguito. Oppure distribuisci lo stesso progetto su **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), che è lo stesso Rebase gestito per te; è già attivo con tenant reali e sta aprendo gli accessi a scaglioni durante la fase di private beta. Pensalo come un'alternativa open source a Supabase o Retool in cui sei *tu* a decidere chi lo gestisce.
:::

## Scegli il tuo percorso

Rebase è un backend e un pannello di amministrazione che condividono un server. Inizia da ciò per cui sei arrivato:

| Voglio… | Inizia da qui | Cosa ottieni |
|---|---|---|
| **Un backend e un pannello di amministrazione** | [Quickstart](/docs/getting-started/quickstart/) | Tabelle in TypeScript, un'interfaccia utente CRUD generata, un'API REST, autenticazione, storage e real-time |
| **Solo l'API, sul mio database** | [Solo backend](/docs/getting-started/headless/) | Un'API REST headless e un SDK sul tuo PostgreSQL esistente — nessun pannello di amministrazione, nessun file di tabella |

Nessuna delle due opzioni è a senso unico: un progetto headless può integrare un pannello di amministrazione aggiungendo un frontend, che esegue il rendering di ogni tabella gestita dal backend, ed entrambi possono definire le proprie tabelle in `backend/schema/` quando si desidera averle nel codice.

## Avvio rapido

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` genera per te un file `.env` pronto all'uso — non è richiesta alcuna modifica. Quindi:

```bash
pnpm install
pnpm run dev
```

Questo è tutto per la prima esecuzione. Non c'è alcun database da installare e nessun passaggio di configurazione dello schema: senza alcuna `DATABASE_URL` impostata, `rebase dev` avvia un'istanza PostgreSQL gestita (PGlite) nella directory del progetto, genera lo schema dalle tue tabelle e le crea all'avvio.

**Leggi gli URL dall'output.** `rebase dev` sceglie una porta libera per ciascun progetto anziché porte fisse, quindi variano tra progetti e tra macchine. Il primo account registrato diventa l'amministratore — sulla tua macchina. Una distribuzione in produzione definisce invece il proprio amministratore tramite `REBASE_ADMIN_EMAIL` e `REBASE_ADMIN_PASSWORD` (consulta la sezione [Configurazione](/docs/getting-started/configuration/)).

Per usare invece il tuo Postgres, decommenta `DATABASE_URL` in `.env` ed esegui nuovamente `pnpm run dev`.

→ Segui la [Guida introduttiva rapida](/docs/getting-started/quickstart) completa per una panoramica dettagliata, compreso come connettere il tuo database.

## Funzionalità principali

| Funzionalità | Descrizione |
|---------|-------------|
| **Viste a foglio di calcolo** | Tabella virtualizzata e veloce con modifica inline, filtri, ordinamento e ricerca testuale |
| **Vista a elenco** | Vista a elenco verticale chiara e reattiva per qualsiasi tabella |
| **Bacheca Kanban** | Vista a bacheca drag-and-drop raggruppata per qualsiasi colonna enum |
| **Relazioni** | Uno a uno, uno a molti, molti a molti con tabelle di giunzione e join multi-hop |
| **Row Level Security** | Policy RLS di Postgres compilate dalla direttiva `rls` che ogni tabella deve dichiarare |
| **Autenticazione** | JWT + token di refresh, dodici provider OAuth/OIDC, magic link, codici monouso, MFA con TOTP, chiavi API con ambiti limitati (scoped), controllo degli accessi basato sui ruoli |
| **Archiviazione file** | File system locale, compatibile con S3 o Google Cloud Storage, con campi di upload e visualizzatore di file |
| **Sincronizzazione in tempo reale** | Aggiornamenti live basati su WebSocket per tutti i client connessi |
| **Cronologia delle entità** | Tracciamento completo (audit trail) per ogni creazione, modifica ed eliminazione |
| **API REST** | Endpoint CRUD generati automaticamente per ogni tabella |
| **Importazione/Esportazione dati** | Importazione di CSV, JSON ed Excel con mappatura dei campi; esportazione in CSV/JSON |
| **SDK tipizzato** | SDK JavaScript type-safe per le tue applicazioni frontend |
| **Sistema di plugin** | Estendi ogni parte dell'interfaccia utente — barra degli strumenti, moduli, campi, home page |
| **Ottimizzazione dati con IA** | Completamento automatico basato su LLM per i campi di testo |
| **Cron job** | Attività in background pianificate con monitoraggio, registrazione log e dashboard in Studio |
| **Funzioni personalizzate** | Route Hono basate su file con accesso al DB, pubbliche per impostazione predefinita: il token del chiamante viene letto quando inviato e `requireAuth` protegge la route |
| **Servizio email** | SMTP integrato per reimpostazione della password, verifica ed email transazionali |
| **Branching del database** | Copie isolate istantanee del tuo database per sviluppo, staging o test |
| **Webhook** | Notifiche in uscita con firma HMAC su INSERT, UPDATE, DELETE |
| **Canali broadcast** | Canali WebSocket per la messaggistica in tempo reale tra i client connessi |
| **Tracciamento della presenza** | Rileva gli utenti online e sincronizza lo stato condiviso tra i partecipanti |
