## Cos'è Rebase?

Rebase è il **backend open-source per PostgreSQL**, con un **pannello di amministrazione** per il tuo team, creato con React e TypeScript. Ti offre tutto il necessario per creare un'applicazione pronta per la produzione su **PostgreSQL**:

- **Schema as Code** — Dichiara le tue tabelle Postgres in TypeScript, ciascuna con una configurazione obbligatoria per la Row Level Security. Rebase genera le tabelle e le relative policy, gli endpoint delle API REST, un SDK tipizzato e un'interfaccia utente CRUD completa a partire da quell'unica fonte di verità.
- **Pannello di amministrazione istantaneo** — Un pannello basato su React bello e veloce, con tabelle in stile foglio di calcolo, elenchi, moduli, bacheche Kanban, modifica inline e sincronizzazione in tempo reale.
- **Backend integrato** — Autenticazione (password, magic link, codici monouso, MFA, chiavi API e dodici provider OAuth/OIDC), archiviazione file (locale, S3 o GCS), Row Level Security, cronologia delle entità e WebSocket in tempo reale — tutto integrato.
- **Radicalmente estendibile** — Se puoi crearlo in React, puoi aggiungerlo a Rebase. Campi personalizzati, viste personalizzate, plugin e accesso completo agli hook interni.

:::tip
Rebase funziona in entrambi i modi e il tuo codice non cambia tra di essi. **Ospitalo in autonomia (self-host)** — hai il pieno controllo dei dati, del codice e della macchina su cui viene eseguito. Oppure distribuisci lo stesso progetto su **Rebase Cloud** ([app.rebase.pro](https://app.rebase.pro)), che è lo stesso Rebase gestito per te; è attualmente attivo con tenant reali e le registrazioni vengono aperte a scaglioni durante la beta privata. Pensalo come un'alternativa open-source a Supabase o Retool in cui sei *tu* a decidere chi lo gestisce.
:::

## Scegli il tuo percorso

Rebase è un backend e un pannello di amministrazione che condividono un server. Inizia da ciò che stai cercando:

| Desidero… | Inizia da qui | Cosa ottieni |
|---|---|---|
| **Un backend e un pannello di amministrazione** | [Quickstart](/docs/getting-started/quickstart/) | Tabelle in TypeScript, una UI CRUD generata, un'API REST, autenticazione, archiviazione e funzionalità real-time |
| **Solo l'API, sul mio database** | [Solo backend](/docs/getting-started/headless/) | Un'API REST headless e un SDK sul tuo PostgreSQL esistente — nessun pannello di amministrazione, nessun file di tabella |

Nessuna delle due scelte è irreversibile: un progetto headless può integrare un pannello di amministrazione aggiungendo un frontend, che esegue il rendering di ogni tabella gestita dal backend, ed entrambi possono definire le tabelle in `backend/schema/` quando si desidera averle nel codice.

## Avvio rapido

```bash
pnpm dlx @rebasepro/cli init my-app
cd my-app
```

`init` genera per te un file `.env` pronto all'uso — non è richiesta alcuna modifica. Poi:

```bash
pnpm install
pnpm run dev
```

Questo è tutto ciò che serve per la prima esecuzione. Non c'è alcun database da installare né passaggi per lo schema: senza `DATABASE_URL` impostato, `rebase dev` avvia un PostgreSQL gestito (PGlite) nella directory del progetto, genera lo schema dalle tue tabelle e le crea all'avvio.

**Leggi gli URL dall'output.** `rebase dev` seleziona una porta libera per ciascun progetto anziché porte fisse, quindi variano tra progetti e macchine diverse. Il primo account registrato diventa l'amministratore — sulla tua macchina. Una distribuzione in produzione definisce invece il proprio amministratore tramite `REBASE_ADMIN_EMAIL` e `REBASE_ADMIN_PASSWORD` (vedi [Configurazione](/docs/getting-started/configuration/)).

Per utilizzare invece il tuo Postgres, decommenta `DATABASE_URL` in `.env` ed esegui nuovamente `pnpm run dev`.

→ Segui la [guida rapida](/docs/getting-started/quickstart) completa per una panoramica dettagliata, compreso come connettere il tuo database.

## Funzionalità principali

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

| Funzionalità | Descrizione |
|---------|-------------|
| **Viste a foglio di calcolo** | Tabella rapida e virtualizzata con modifica inline, filtri, ordinamento e ricerca testuale |
| **Vista a elenco** | Vista a elenco verticale, pulita e reattiva per qualsiasi tabella |
| **Bacheca Kanban** | Vista a bacheca drag-and-drop raggruppata in base a qualsiasi colonna enum |
| **Relazioni** | Uno a uno, uno a molti, molti a molti con tabelle di giunzione e join multi-hop |
| **Row Level Security** | Policy RLS di Postgres compilate a partire dalla proprietà `rls` che ogni tabella deve dichiarare |
| **Autenticazione** | JWT + refresh token, dodici provider OAuth/OIDC, magic link, codici monouso, MFA TOTP, chiavi API con scope, controllo degli accessi basato sui ruoli (RBAC) |
| **Archiviazione file** | Filesystem locale, compatibile con S3 o Google Cloud Storage, con campi di caricamento e file browser |
| **Sincronizzazione in tempo reale** | Aggiornamenti live basati su WebSocket per tutti i client connessi |
| **Cronologia delle entità** | Registro di controllo (audit trail) completo per ogni operazione di creazione, modifica ed eliminazione |
| **API REST** | Endpoint CRUD generati automaticamente per ogni tabella |
| **Importazione/Esportazione dati** | Importazione di CSV, JSON ed Excel con mappatura dei campi; esportazione in CSV/JSON |
| **Collection Editor** | Editor visivo dello schema che scrive il codice TypeScript in `backend/schema` tramite manipolazione dell'AST |
| **SDK tipizzato** | SDK JavaScript type-safe per le tue applicazioni frontend |
| **Sistema di plugin** | Estendi ogni parte dell'interfaccia utente — barra degli strumenti, moduli, campi, home page |
| **Ottimizzazione dati con IA** | Completamento automatico basato su LLM per i campi di testo |
| **Cron Job** | Attività pianificate in background con monitoraggio, registrazione log e dashboard in Studio |
| **Funzioni personalizzate** | Route Hono basate su file montate automaticamente con middleware di autenticazione e accesso al DB |
| **Servizio email** | SMTP integrato per il ripristino della password, la verifica e le email transazionali |
| **Branching del database** | Copie isolate istantanee del database per sviluppo, staging o test |
| **Webhook** | Notifiche in uscita firmate con HMAC su INSERT, UPDATE, DELETE |
| **Canali di broadcast** | Canali WebSocket per la messaggistica in tempo reale tra i client connessi |
| **Rilevamento presenza** | Monitora gli utenti online e sincronizza lo stato condiviso tra i partecipanti |
