# Import spostati nella 0.31

<span class="since-badge" data-since="0.31">Dalla versione 0.31</span>

I pacchetti del kernel descrivono solo le tabelle, pertanto ciò che descrive una collection così come viene visualizzata dal pannello di amministrazione è stato spostato in `@rebasepro/cms-types`, e la migrazione del lift in `@rebasepro/common/migrate` ([sezione 135 della guida all'aggiornamento](/docs/upgrading/0-30-to-0-31/#135-rebaseprotypes-and-rebaseprocommon-drop-the-collection-model-from-their-roots)).

`rebase migrate sdk-calls` (parte di `rebase migrate collections-to-tables`) sposta ciascun import sottostante nel suo nuovo pacchetto — unendolo a un import di quel pacchetto già presente nel file, mantenendo `import type`, i `type` inline e gli alias `as` — e aggiunge il pacchetto alle dipendenze del pacchetto del workspace che esegue l'importazione; successivamente eseguire `pnpm install`. L'importazione di un nome rimosso, un import di namespace, un `export *`, un `import()` dinamico o un `require()` che utilizza un nome spostato rappresenta un passaggio manuale numerato.

Questo elenco è generato a partire da `tooling/scripts/headless-guard/moved-symbols.json`, la tabella letta dal codemod. Consultare [`rebase migrate`](/docs/cli/schema/#rebase-migrate) per il comando e [Personalizzazione di una tabella](/docs/frontend/customize-table/) per scoprire dove vengono utilizzati i tipi del pannello.
