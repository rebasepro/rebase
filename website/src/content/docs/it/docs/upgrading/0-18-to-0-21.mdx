# Aggiornamento 0.18 → 0.21

**0.21.0 è stato rilasciato.** Queste sono le voci `### Breaking` della relativa
[sezione del changelog](/docs/changelog/), una alla volta, con le modifiche richieste
per ciascuna di esse. 0.19 e 0.20 non dichiarano alcuna breaking change, quindi questo è
un unico passaggio da 0.18 — leggilo prima di passare a 0.21, non dopo.

Entrambe sono errori di compilazione anziché modifiche silenziose del comportamento:
la build segnala ogni riga da modificare e il comando grep sotto ogni sezione consente
di trovarle prima ancora che lo faccia la build.

---

## 31. `context.client.data` non compila più in una callback di collection

`RebaseCallContext["client"]` è ora `RebaseCallbackClient`: `RebaseClient`
senza `data`. Lato server questo client è il singleton `rebase`, che non ha più
`data` a partire dalla 0.18; di conseguenza, `context.client.data.collection(…)` compilava
per poi lanciare l'errore `Cannot read properties of undefined (reading 'collection')`
a ogni chiamata. Ora è invece un errore di compilazione.

**Cosa modificare:** esegui le query tramite `context.data`, l'accessor che le query di
una callback avrebbero sempre dovuto utilizzare. Viene eseguito con i privilegi di
qualunque elemento abbia attivato la callback, all'interno della transazione della
scrittura stessa. La [guida alle callback](/docs/collections/callbacks/) illustra cosa
può raggiungere ciascun accessor presente nel context.

```diff lang="ts"
 afterSave: async ({ context }) => {
-    await context.client.data.audit_logs.create({ action: "approved" });
+    await context.data.audit_logs.create({ action: "approved" });
 }
```

```bash
grep -rn "client\.data\b" config
```

`context.client.dataAsAdmin` è ancora disponibile per una callback che deve vedere ciò
che un amministratore può vedere. Anche `admin.browserCallbacks` cambia: la vecchia
dicitura funzionava lì perché il client del pannello include `data`, e smette di
compilare allo stesso modo. `useRebaseContext().client` in un componente React mantiene
il proprio `data`.

## 32. `selectedEntities` non esiste più: una selezione è ora composta da righe o da una query

Una vista di collection ora può selezionare ogni riga che corrisponde al suo filtro,
non solo le righe che ha caricato; pertanto, `SelectionController` non restituisce più
un `Entity[]`. `selectionController.selection` è un'unione `EntitySelection`:
`{ type: "entities", entities }` per le righe spuntate manualmente, oppure
`{ type: "query", query, excluded, count? }` per ogni riga che soddisfa una query,
la maggior parte delle quali non è mai stata letta da nessuno.

**Cosa modificare:** un'azione personalizzata che legge la selezione la converte in
righe tramite `resolveSelection` da `@rebasepro/cms`. Questa restituisce le righe
spuntate tutte insieme e legge una selezione basata su query una pagina alla volta —
con una callback di avanzamento opzionale — lanciando un errore invece di restituire
un prefisso quando la query trova più di 20.000 righe.

```diff lang="tsx" no-verify
 const handlePublish = async () => {
-    for (const entity of selectionController.selectedEntities) {
+    const selected = await resolveSelection({
+        selection: selectionController.selection,
+        accessor: data.collection(path)
+    });
+    for (const entity of selected) {
         await data.collection(entity.path).update(entity.id, { status: "published" });
     }
 };
```

```bash
grep -rn "selectedEntities" config frontend
```

Insieme a questo arrivano tre modifiche minori:

- `selectionController.selectedEntities.length` → `selectionController.selectedCount`.
  È `undefined`, mai 0, quando viene selezionata ogni riga corrispondente a una query
  e la collection non può essere conteggiata — gestisci questo caso nel rendering, non
  assegnargli un valore predefinito.
- `setSelectedEntities(prev => …)` → `setSelection(prev => …)`, che riceve e
  restituisce una `EntitySelection`. `setSelectedEntities(rows)` con un array continua
  a funzionare.
- Il controllo per verificare se "è selezionato qualcosa" è `selectionController.hasSelection`.

`isEntitySelected` e `toggleEntitySelection` rimangono invariati e sono ciò che una
casella di controllo per riga dovrebbe continuare a utilizzare. L'[esempio di azioni per collection](/docs/frontend/entity-actions/#collection-actions)
mostra l'intero pattern.
